# 角色卡制作规范盲审答案钥匙（作者保管）

> 本文件不得发给盲审者。两位评审者分别完成并签署夹具包后，才可用本文件核对；发现两人按规范得出不同结论时，优先记为规范歧义，不得反向改答案。

| 夹具 | 预期处理 | 必须出现的推理 | 典型错误 |
|---|---|---|---|
| A：换槽同决策 | `REVISE` | 引用至少两种情境和跨卡回答，指出决策、理由相同；证据账没有支持该共同行为，地名/词语替换不构成人物差异。 | 只统计句式相似；或因名词不同就认为人物不同。 |
| B：地点越权 | `REVISE` | 地点/家族关联不支持征税权、任命权或财政决策；“合理”不是来源。 | 把同地关系当作人物职权依据；将无来源主张标成普通推断。 |
| C：运行时关键主张丢失 | 技术门禁阻断，不得 `PASS` 或 `approved` | 说明 C1 在 definition→DSL 阶段丢失，prompt 缺失是最终证明；记录 fallback/trim 状态，要求修复或删除 runtime_required 声明并重测。 | 因 definition 有 C1 而通过；把缺失归咎文风。 |
| D：简单但有据的有限范围卡 | 范围内取得 `PASS` / `approved` 资格：`YES`；本夹具直接批准：`NO`；生产结论：`NOT_ESTABLISHED_BY_FIXTURE` | 允许范围只含身份/职位和该条有据行为；不可声称完整人格认证。需补齐真实链路、未知问题处理和独立盲评；不得要求第二项行为。 | 因只有一项行为就判整卡 `INSUFFICIENT_EVIDENCE` 或禁止批准；或忽略夹具未给出的实际门禁证据而直接判生产 PASS。 |
| E：句式负对照 | 不得仅因句式相似判 `REVISE`；同质化项可 `PASS` | 两种情境中选择、理由、约束不同且各有证据；记录句式线索但不提升成语义结论。 | 看到共同“先—再”就判同质，要求故意写成反差人格。 |
| F：窄范围许可不能掩盖超范围主张 | `REVISE` | D 的范围内许可不覆盖无据野心/忠诚主张或未注册/无依据 tag；删除、补证或缩窄范围后重审。 | 以“简单卡可通过”为由放行无据特征，或只保留作者声明范围而不检查实际运行字段。 |

## 验收核对

每位评审者需逐例写结论和至少一条规范条款依据。两人全部结论与理由均符合上表、且不依赖作者额外解释，才算通过本轮规范盲审。任何错误结论、无法定位条款、虚构要求或关键歧义都应回到规范修订；修订后重跑 A–F 并新增至少一条变体。
