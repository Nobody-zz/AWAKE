# AWAKE 世界书 · 全量知识体系目录（v2 草案 · 2026-09-12）

> **v1 的错（Max 指出）**：我把「有官方描述文」当成了能否编纂的**门槛**，于是把 67 座城堡、99 个藏身处判成「不做」。**这是拿"素材"当了"目标"。**
> **本修正**：世界观要成立，靠的是**体系完整**，不是文本覆盖率。**没文本 ≠ 没知识。**
> 而且这本就是项目既有规则 —— v3 手册 **B9 来源分级**里 **D = 开发者原创裁定**，用途明写「**解决冲突、填补空白、项目独有逻辑**」；索引 v2 §2.3 同。**v1 违背了这条既定规则，v2 依此重建。**
> 红线不变：① 不与官方数据冲突；② 不把官方说法撮合成自己的判断（内核只陈述"说法"）；③ **D 类必须登记来源**。

## 一、三条口径

1. **驱动是「这个世界需要什么知识」，不是「游戏写了什么」。** 官方文本只是素材之一，不是准入条件。
2. **素材四级**（手册 B9）：**A** 官方文本/游戏数据 · **B** 编年史 · **C** 模组资料提取 · **D** 开发者原创（填补空白）。
3. **D 不等于编造** —— 它是「官方没写、但这个世界必须成立」的部分（例：货币叫什么、神庙怎么运作）。须登记、可复核。

---

## 二、两条正交轴

| 轴 | 取值 | 说明 |
|---|---|---|
| **领域**（固定五类） | 政治 / 经济 / 文化 / 战争 / 地理 | 手册 B1 钉死，不许自创 |
| **知识形态** | **Ⅰ 锚定** / **Ⅱ 体系** / **Ⅲ 常识** | 见下 |

- **Ⅰ 锚定知识**：挂在一个游戏对象上（某王国、某家族、某英雄）。
- **Ⅱ 体系知识**：不属于任何单一对象（律法、商路、军制、习俗、史事）。
- **Ⅲ 常识层**：这个世界每个人天然就知道的（城堡是干什么的、集市怎么开）——**最容易被忽略，却最影响"像不像一个世界"**。

> v1 目录只覆盖了「Ⅰ 锚定」中最窄的一角（有简介文的那部分）。**Ⅱ 和 Ⅲ 整块漏掉了。**

### 二·补 锚点：可有可无（Max 09-12 定；读码确证，推翻我先前的"结构性矛盾"说法）

**Max 原话**：「锚点我写过的，可有可无。毕竟有些概念类的词语就是没有对应游戏代码。」

**我先前的错误说法**：我称「Ⅱ 体系知识没有 `hero|clan|settlement` 锚点 → 只能挂 `entity.lore.*` → 必然撞 C16 编译不过，这是最大结构性矛盾」。**这是错的**，我没核实就断言。

**读码确证**（`RuntimePackageCompiler.cs`）：
- **L142** `if (document["entity_ids"] is JsonArray entityIds && entityIds.Count > 0) { …CanonicalEntityRef… }` —— 整块**带守卫**：字段缺失或空数组 → 整段跳过 → **不调用** `CanonicalEntityRef` → 不抛 `WB-DOC-003`。
- **L347-351** `ReadEntityIds` → `(document["entity_ids"] as JsonArray)?… ?? []`，缺失即返空。
- **L353-355 注释原文**：「指针、登记表缺失或解析失败时返回空表，keywords 退化为「标题 + 别名 + 内部 id」，**不阻断编译**。」
- **schema**：`entity_ids` **不在 13 个必填字段内**，且无 `minItems`。

**结论**：**概念类知识（Ⅱ / Ⅲ）直接不写 `entity_ids` 即可，编译无障碍。** 锚点只在「这个概念确实对应某个游戏对象」时才用，是**加分项，不是准入项**。

> ⚠ **代价（不是阻塞，是要注意）**：没有锚点则 K1 关键词退化为「**标题 + aliases + 文档 id**」。**所以概念类条目比锚定条目更依赖 `aliases`**——而现有 12 档 `aliases` 是 **0/12**。写概念条目时，`aliases` 是命脉。
> ⚠ 上述为**读码确证**；**尚未跑过一次"省略 entity_ids"的真实编译**，实证待补。

## 三、逐领域：要建什么 · 料从哪来

### 地理

- **Ⅰ 锚定**：城镇 53 · 村庄 273 · **城堡 67** · **藏身处 99**
  - ⚠ **城堡/藏身处 v1 判错**：它们虽无简介文，但有 `owner`（归哪个家族）、`culture`、位置、被提及次数 —— **可写「归谁、为什么建在这、扼住哪条路」**。藏身处被提及 **154 次**，料相当足。
- **Ⅱ 体系**：大陆分区（帝国核心 / 北境 / 南方沙漠 / 东部草原…）、山脉河流道路的走向、气候与季节。
- **Ⅲ 常识**：什么叫"城"、什么叫"堡"、什么叫"村"，三者关系。
- **游戏侧可用素材**：`bannerlord_settlements`（494）+ 地形/坐标 XML（`xml_entities` 的 `Settlement/Town/Village/Hideout`）。

### 政治

- **Ⅰ 锚定**：王国 8 · 家族 95（贵族 73）· 关键英雄（27 位有传）
- **Ⅱ 体系**：**32 条王国政策**（游戏有全文 + 中文名，如「地方长官」「营房」「城堡地契」「市民权」）、王位继承、官职制度、外交与战争状态。
- **Ⅲ 常识**：贵族 / 市民 / 村民 / 奴隶的等级关系；效忠是怎么回事。
- **游戏侧可用素材**：`kingdoms`(8) / `clans`(95) / **`policies`(32，带全文)** / `heroes`(397) + 政策中文名。

### 文化

- **Ⅰ 锚定**：文化 23（主文化 6）
- **Ⅱ 体系**：语言、**各地域与民族的风俗习惯**、节庆、婚丧、荣誉观、族群偏见。
- **Ⅲ 常识**：见面怎么行礼、怎么待客、哪些话不能说。
- **游戏侧可用素材**：`cultures`(23) / `Trait`(68) / 人名库 / 本地化文本。
- **不单列宗教**（Max 09-12 定）：原版世界观**本来就没有宗教**，游戏也没做相关内容——**这是这个世界的事实，不硬造**。相关观感一律并入「风俗与文化」，按**地域 / 民族**分。
  > 边界原则：世界观补全的边界是「**这个世界本身**」，不是「中世纪类型惯例」。凡通用中世纪"应该有"而卡拉迪亚没有的（宗教、骑士团、教皇…），**不自动立项**。
  >
  > **补（09-12 二裁）**：Max 提供的资料 1 里有一整节私设「信仰」（卡拉德多神／北方多神／阿姆拉·奥拉姆），**已定整节不入**——**既不单列，也不并入政治/文化**（详见 `WORLDBOOK-REFERENCE-INTAKE-20260912.md` §三.1）。
  > 官方文本里**零散**出现的民间信仰词（诸神 6／神圣 9／祈祷 6／德鲁伊 4 含地名／萨满 2／神庙 1；而 教堂·祭司·先知 皆 0）**按其出现处如实带一句即可（A 级）**，**不建体系**。

### 经济

- **Ⅰ 锚定**：聚落物产、作坊、商队路线。
- **Ⅱ 体系**：商路、货币与物价、税收、行会。
- **Ⅲ 常识**：第纳尔怎么花、粮价什么时候涨。
- **游戏侧可用素材**：`items`(3052，含商品与装备) / 城镇繁荣度 / 村庄产出类型。
- **明确缺口（D）**：**货币名、度量衡、借贷**。

### 战争

- **Ⅰ 锚定**：兵种、战役。
- **Ⅱ 体系**：军制、征召、**潘德拉克战役**（无数英雄传记的共同背景）、匪患。
- **Ⅲ 常识**：打仗要粮要钱要人、冬天不出征。
- **游戏侧可用素材**：`troops`(1696，带升级链与兵种文化) / 政策中的军事条。

## 四、游戏其实给了多少（v1 完全没算这一层）

| 领域 | 有全文文本 | 有结构化数据 | 靠 D 补 |
|---|---|---|---|
| 地理 | 城镇/村庄简介 | 494 聚落 + 地形 + 坐标 | 地名由来、风物 |
| 政治 | 英雄传记 + **32 政策全文** | 王国/家族/英雄关系 | 制度细节、史事因果 |
| 文化 | 6 主文化简介 | 23 文化 + 特质 + 人名 | 风俗细节（按地域/民族，**不含宗教**） |
| 经济 | 几乎没有 | 3052 物品 + 繁荣度 | **货币、行会、商路** |
| 战争 | 散见传记 | 1696 兵种 + 升级链 | 战役经过、名将事迹 |

> 结论：**五个领域游戏侧都有料，只是大多不在「对象简介」里**（藏在政策全文、兵种表、物品表、关系数据里）。v1 只翻了"简介"一格抽屉。

## 五、建设顺序（依手册 B10 原话）

> 先按五领域归类，再拆条目边界；先登记官方来源，再生成作者档案；
> 先写 `fact/state/relation`，再写 `interpretation/rumor`；
> **先做地理聚落简介，再做政治沿革和家族关系。**

落地顺序：**地理 → 政治 → 文化 → 经济 → 战争**。
理由：地理是骨架（地点先能定位），政治挂上去，文化/经济/战争再往骨架里填。**Ⅰ→Ⅱ→Ⅲ 三级同铺**，不要只做 Ⅰ。

> **补（Max 09-12 16:50 裁）：骨架先行。**
> 上面 B10 的"先做地理聚落简介"是**Ⅰ 锚定层的建设顺序**；Max 追加的"**先做骨架**"是在它**之前**再加一步：**先把历史时间轴统一**。
> → **第一批产出 = 历史线骨架**（共同时间坐标）；之后一切条目按这条轴对齐年代，再按 B10 铺领域。
> 理由：历史线横跨政治/战争/文化三个领域，**若各自成文必互相矛盾**；先把轴钉死，后面才不用返工。
