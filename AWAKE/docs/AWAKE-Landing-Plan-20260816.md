## 二、B0：稳定基线 + 发布校验

目标：先把已知崩溃、焦点、持久化问题清掉，并让每次发布可验证。

范围：

- 修复 Messenger 历史缓存未随战役重置。
- 修复持久化回读在存储未就绪时永久跳过。
- WorldEvent / Messenger fire-and-forget 写任务安全包装。
- 周报触发日持久化，避免读档重复生成。
- MCM AI 自检补充路由/模型/Provider 状态。
- 新增 `tools/release_check.ps1`：SubModule 版本、程序集版本、哈希、本地化 key、事件 ContentHash、文件白名单。

验证：

- 构建 0 警告 0 错误。
- SdkSmoke 全 PASS。
- 本地化校验全绿。
- 游戏内：存读档后无重复周报、Messenger 历史不跨档残留。

退出条件：

- 所有 P1/P2 已知问题闭环或至少进入待游戏内验收。
- 发布脚本能一次跑完并给出“通过/失败”。

## 三、B1：双模式对话

目标：第一版同时具备场景独立 AI 对话和原版对话窗口 AI 模式。

依据：`PLAN-SceneVisualSelection-20260816.md`，先签收再实现。

范围：

- `SceneDialoguePreviewMath`：角度曲线、扇形段数、视锥判定。
- `SceneDialoguePreview`：标记实体池、候选高亮、降级只高亮。
- `AwakeTerminalBehavior`：T/Y/松开 T 交互，候选重校验，LOS。
- `NativeConversationAIMode`：状态跃迁检测、目标稳定 debounce、上下文门。
- `NativeConversationAIOverlay`：折叠按钮 + 展开 AI 层，输入捕获，恢复原版。
- MCM：`EnableSceneVisualSelection`、`EnableNativeConversationAIMode`、`NativeConversationAIAutoOpen`。
- 本地化：新 UI 文案双语 key。
- 开发者自测：`awake.scene.visual_selftest`。

验证：

- `dotnet build -c Release -p:BannerlordApi=1.3.15` 0 警告 0 错误。
- SdkSmoke：预览数学、状态跃迁、目标 debounce、上下文门。
- 本地化校验全绿。
- 游戏内：T 扇形/候选高亮、Y 切换、松开 T 打开 AWAKE 覆盖层。
- 游戏内：原版对话出现切换按钮，AI 模式开启/关闭不破坏原版对话，任务/强制对话不出现按钮。

退出条件：

- 场景来源日志出现 `scene_native_skipped`，无原生对话堆栈。
- 覆盖层 `focus_pending` 后输入仍可用。
- 标记实体最大距离可见、不可拾取、不碰撞。

## 四、B2：会话服务统一

目标：消灭“每个入口一套会话状态”。

范围：

- 抽出统一 `AwakeDialogueSessionCoordinator`。
- 场景、遭遇面谈、通讯录、原生对话 AI 模式共用 `NpcDialogueService`、记忆、世界书上下文。
- UI 保持独立：沉浸覆盖层、Messenger、原生对话切换层。
- 统一会话来源标记：`scene` / `encounter` / `messenger` / `native`。

验证：

- 同一 NPC 跨入口切换时历史不丢。
- 通讯录打开时场景弹窗不抢入口。
- 原生对话 AI 模式关闭后回到原版，不残留会话状态。

退出条件：

- 四个入口都能打开同一个 NPC 会话服务，且日志来源正确。

## 五、B3：规则/提示词 schema 注册表

目标：避免 AF 式 140KB 无版本 JSON。

范围：

- 定义规则 manifest schema：`schemaVersion`、`id`、`group`、`priority`、`enabled`、`fingerprint`。
- 新增 `AwakeRuleRegistry`：加载、校验、查询、日志。
- 未知字段/未知规则 fail-closed。
- 提供一次性迁移脚本，禁止无版本改 ID。
- 把现有世界书 manifest 校验扩展为通用规则注册表。

验证：

- 合法规则通过，非法规则被拒绝并记录。
- 同 ID 重复注册失败。
- SdkSmoke 覆盖加载、查询、迁移。

退出条件：

- 运行时不再依赖无版本 JSON 直接读取。

## 六、B4：事件引擎数据驱动化

目标：内容包能注册事件，运行时只做触发、冷却、结算。

范围：

- `AwakeEventDefinition` 数据模型：ID、条件、冷却、每日上限、选项、对话动作。
- `AwakeEventEngine` 改为注册表驱动，移除硬编码演示规则。
- 事件元数据持久化与日滚动。
- 事件选项接入关系命令/世界命令结算。

验证：

- SdkSmoke：注册、冷却、每日上限、选项结算。
- 游戏内：内容包事件能触发并进入对话，不崩溃。

退出条件：

- 运行时自身不包含任何内容事件。

## 七、B5：记忆结构化与衰减

目标：日常记忆会衰减/合并，重大事件保留，承诺单独建模。

范围：

- 结构化记忆：时间、地点、人物、事件类型、结果。
- 日常记忆按游戏日衰减与合并。
- 承诺账本：誓言、债务、婚约、效忠。
- 记忆回读在存储未就绪时安全降级，不永久跳过。

验证：

- SdkSmoke：写入、衰减、合并、承诺检索。
- 游戏内：NPC 记得重大事件，不把日常闲聊当永久事实。

退出条件：

- 外部数据库只是历史镜像，不覆盖存档权威状态。

## 八、B6：主动聊天动机可注册

目标：动机表由内容包扩展，不硬编码。

范围：

- `NpcProactiveService` 动机注册接口。
- 冷却、疲劳、打开失败恢复保留。
- 场景弹窗、地图通知、来信三入口。
- 无名 NPC 只使用身份内动机。

验证：

- SdkSmoke：注册动机、权重、冷却。
- 游戏内：新动机能进入候选池并正常弹窗。

## 九、B7：内容包公开 API

目标：运行时零世界观内容。

范围：

- 注册接口：事件、规则、世界书、信件模板、主动动机。
- `SlaneshsEmbraceContent` 通过接口接入。
- 内容包 manifest 校验与发布白名单。

验证：

- 不带内容包时 AWAKE 仍能启动。
- 带内容包时功能按声明注册，不污染运行时。

## 十、B8：Messenger / 诊断 / 首启 UI

目标：体验层闭环。

范围：

- Messenger 统一入口：通讯录、写信、来信、未读、通知。
- 开发者检查面板：结构化诊断 UI。
- 首启向导：无模型时引导配置 Provider/Key/Route。
- 热键冲突检测：场景 T/Y、命令台 U。

验证：

- 游戏内三入口互不抢焦点。
- 诊断面板只读，不执行写操作。
- 首次无模型配置后能直接进入 AI 对话。

## 十一、B9：性能、日志、存储契约

范围：

- 倒排索引 + 指纹 + 分层召回，禁止 ONNX/全量扫描。
- 主线程与 tick 预算。
- 结构化日志、错误码、关联 ID。
- 存储 key 冻结并带 schema 版本，迁移可重入。

验证：

- 性能探针无慢 tick。
- 错误信息不弹游戏内详情，只提示日志位置。
- 存读档迁移连续执行不重复。

## 十二、落地顺序与风险

顺序原则：

- 先稳定，再功能。
- 先对话基座，再世界系统。
- 先 schema，再内容。
- 先内部验证，再游戏内验收。

主要风险：

- 双模式对话依赖 overlay 焦点修复，必须先游戏内验证。
- 原生对话 AI 模式的输入捕获不能破坏任务/强制对话。
- 规则注册表一旦开始校验，旧内容包可能被拒；迁移工具必须先行。
- 事件引擎数据驱动后，原演示事件会消失；需要内容包提供替代事件。
