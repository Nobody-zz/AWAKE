折中取了什么

取自稿 01：左右分区；说话人有独立的立绘与信息位；左区信息有名字、身份、关系、状态。
取自稿 02：只留一个「面」（对话区 660×491）；只留一个时间落点（最新条 2px 金条）；未选中不描边；模式键无常驻边框；在场人物压成底部一条，不占左栏；金总计 5 处。

舍了什么

1. 左栏「在场人物 236×85 ×3」竖列表 —— 位置让给立绘，在场改由底部在场条承担（点选切左区）。
2. 属性行 ×3 · 状态说明行 · 在场人物的身份/关系两行 —— 信息只保留「关系 / 状态」两行，且只归说话人一个人所有。
3. 右区面内的「说话人一行」 —— 左区已经承担了说话人，面内再放一次就是重复信息。
4. 立绘槽的边框与底色 —— 稿 01 的立绘槽是一块「空的深色重块」，那是上次显杂的元凶；本稿改为无框无底、底部渐隐，让图像自己成形。

控件的坐标与尺寸（相对稿 02 作废了两处）

输入区、头带、模式行一律没变（关闭 40×40 / 模式 高 35 / 输入框 680×56 / 结束 100×35 / 发送 110×35）。
作废两处：稿 02 的「对话区 920×491 @20」→ 本稿「660×491 @280」；稿 02 的「对话流 640 宽」→ 本稿「612 宽」。
新增：立绘 240×300 @20/109；左区信息 240×185 @20/415。

这一稿的关键手法

左右分区最容易犯的病，是两块同等重量的色块并排互相打架（这正是稿 01 显杂的根）。
本稿的解法：右区是「面」（靠底色聚拢文字，必须有框才成形）；左区是「图」（图像天然成形，所以不加框、不加底）。两者重量相当但不互斥 —— 因为一个是面、一个是图，形态不同。
左区宽 240 : 右区宽 660 ≈ 1 : 2.75，主次一眼分得开。
