## 二、实测家底（都不是估算，逐条可指）

### 2.1 ⚠ 头号问题：**给最底层身份的授权，全配错了**（平民/村民几乎什么都拿不到）

> **勘误**：本计划书 v1 曾写"40 条里 24 条全死"。**这个说法错了**——我没读继承链就下结论。正确结论见下。

**机制（`WorldbookIdentityEvaluator.CapabilityMatches` L95–105，逐行核实）**：
```csharp
requiredScope  = ScopeRank(rule.Scope);
requiredDetail = DetailRank(rule.MinDetail);
return ScopeRank(身份.EffectiveScope)  >= requiredScope
    && DetailRank(身份.EffectiveDetail) >= requiredDetail;
```
→ **`scope` 与 `min_detail` 都是硬门**：身份的实际范围/详细度**达不到** grant 要求 ⇒ grant 不匹配 ⇒ 这条表达**该身份取不到**。
→ ⚠ **契约文档与实现有出入**：`PERMISSION-CONTRACT.md` 第 6 条写"表达层不足时降级到更低层"，但代码在 grant 匹配阶段就当**硬条件**拒了。**以代码为准**；契约文本要不要改，属跨线，另行登记。

**身份继承链**（`IdentitiesForRole`，同文件）：headman / merchant / soldier 的链**含 `commoner`**；tavernkeeper / ransom_broker = 自身 → merchant → commoner；**noble 的链只有 `noble`**。

**因此 12 档 40 条表达的真实可达性**：

| grant 写法 | 条数 | 谁能取到 | 谁取不到 |
|---|---|---|---|
| `commoner + scope=regional + min_detail=summary` | **24** | headman / merchant / soldier / tavernkeeper / ransom_broker（链含 commoner 且范围够） | **平民、村民**（自己够不着自己名下的 grant） |
| `villager + scope=local + min_detail=summary/detail` | 4 | 链含 commoner 且 detail 达标的高身份 | **村民**（EffectiveDetail=rumor，够不着） |
| `townsfolk + scope=regional + min_detail=detail` | 5 | 链含 townsfolk 的更高身份（若有） | **城镇居民**（EffectiveDetail=summary < detail） |
| `merchant ×2`、`notable ×4` | 6 | 对应身份 | — |
| `noble_high_steward + elite + detail` | 1 | **大概率谁也取不到**（运行时只产 `profile.noble`，不产 `noble_high_steward`） | 待核（取决于包内 identity registry 的 parents） |

**结论**：
- 内容**不是全死**——高身份经继承链能拿到（这与早前模拟"四身份拿到文本"吻合）。
- **真正的问题是反的：不是内容太少，是授权配错了方向。** 平民、村民这两类**最该有内容**的身份，在现有 12 档里**几乎拿不到任何东西**；能拿到的反而是 headman/merchant 这类高身份。**分层做反了。**
- 与"门控只走过'人人皆知'那半边"的观察互相印证。

> **待实证（本批第一件事）**：以上是**读码推演**。要用模拟器跑一遍「身份 × 问题」矩阵，把"平民拿不到"从推演变成实测，再据此定新档口径。（推演与实测分开写，这条规矩今天已经救了我三次。）

### 待裁 2｜先实证 `min_detail` 行为 → ✅ **已定案（读码，比预想更干脆）**

`WorldbookIdentityEvaluator.CapabilityMatches` L95–105：

### 待裁 5｜敢不敢用 `deny`

**背景**：`deny` 优先级最高（Deny > Grant > 继承默认 > unknown）。golden case 1（村民有 Grant 但命中贵族秘密 Deny → 拒）**非用它不可**，否则那条 golden case 永远没有内容覆盖。

**风险**：既有实测记忆是「`WorldKnowledgeQueryService.cs:52` 命中即 `continue` 掉**整条**」——即波及面可能比直觉大。如果 deny 挂在**档级**且范围写宽了（比如 `settlement_ids` 忘了限定），会把整档对某类身份**全部灭掉**。

**建议：用，但分两步走，不上来就进真内容。**
1. **先读码+实测确认 deny 的作用域**（挂在档级 / 断言级 / 表达级）——这跟待裁 2 是同一类零风险核实工作，**不用你批**；

**如果 (1) 验出来 deny 真是"整档核弹"，就有一个设计问题要你裁**：
- **要么** deny 只能挂在极窄的范围上（实际用途 ≈ 只针对"身份未知者/外地人"）；
