# 世界书知识模型 v2 纲要 — 2026-09-12

> 触发：Max 定调「不能全部依赖编年史。编年史反响不好、问题很多。我们要做的比编年史更好——更能模拟知识的流动、更能模拟不同人视角、归类划分关联更规范、对用户来说更便于维护。」

## 零、先把话挑明：编年史到底差在哪

之前我把编年史当主源，这个定位现在改掉。但"改掉"得说清理由——不是因为它写得差（其实写得不差），是**它的组织方式决定了它成不了知识库**。

拿真实文件举证：`workspace/authoring/sources/chronicle-lakonis-lake.txt`。
它是旧规则格式（`rule_*` / `ragShortTexts` / `variants[].When` / `content`），三条 variant：村民 / 领主 / 侦察 100 以上的流浪者。文字质量很高。问题在结构：

| # | 问题 | 证据（同一文件） |
|---|---|---|
| 1 | **整段不可分** | 领主那段 600+ 字，里面混着 4 个各自能独立成立的事实点（两河注入 / 沿岸四城 / 终年不冻 / 船坞扩建）。但只能"整段给"或"整段不给"，**不能只给其中一点** |
| 2 | **没有中立内核** | 每段都自带立场（"我们帝国北方防务体系的核心环节"）。**没有一层"谁都不带立场的客观事实"**，所以表达不了"这事其实没人知道"或"这事被传错了" |
| 3 | **换视角 = 换一整篇文** | 三段之间重叠极低，几乎不是"同一件事的三种说法"，而是"三个不同的话题硬塞进同一个词条"。真正的"视角"应该是**同一个事实点的不同说法** |
| 4 | **条件只有三种，且绑在段上** | `When` 只有 `cultures` / `roles` / `skillMin`。没有聚落、没有王国、没有时代、没有人物关系。想说"只有湖区四城的人才知道"做不到 |
| 5 | **只有"给谁看"，没有"不给谁看" / "不知道该问谁"** | 没有任何 deny 机制，也没有 referral（转介）。知识壁垒和知识寻路**一个都没有** |
| 6 | **不可维护** | 无引用哈希、无血缘记录；改一个数字要动整段；同一事实在多条 variant 间重复出现（这就是我上次测到的"德里亚特 21 字重合"的成因） |

**它唯一做对、而我们没继承的**：`keywords` 里存了别名（`拉科尼斯湖` / `拉科尼亚湖`）。
→ 对应我们的 `aliases` 字段 **0/12**。这一条要从编年史里捡回来，其余的不捡。

## 一、来源策略换血：编年史降级为"采风本"

### 新的三层来源

| 层 | 是什么 | 用在哪 | 现状 |
|---|---|---|---|
| **L1 硬来源** | 游戏官方数据（BannerlordSage v1.3.15，43 表 / 27 万条本地化） | 聚落、英雄、家族、王国、文化的事实 | **一条没登记** |
| **L2 原创** | `author_created` | 视角化说法、民间知识、传说、合理性推演 | **0 条（全走 sources）** |
| **L3 参考（仅采风）** | 编年史 | 只用来捞别名、俗称、民间叫法 | 现在是**唯一**来源 |

### 一个要更正的说法

我在缺口清单里写过「`sources` XOR `author_created` → 我们不能声明任何原创」。**这句话不准确，现更正**：

schema 是在 **assertion 层和 expression 层各自独立**做二选一（`assertion.allOf.oneOf` 与 `expression.allOf.oneOf` 是两个节点）。
所以**已经支持**：*断言走 `sources`（游戏硬数据） + 它的多条表达走 `author_created`（我们原创的说法）*。

这恰恰就是"不依赖编年史"的现成出路——**事实抄官方，说法我们自己写**。机制早就有了，我们没用。

### 素材优先级改为

```
游戏官方数据（硬事实 / 可复核 / 带 ID）
  → 我们的原创（视角、传说、民间知识，走 author_created）
    → 编年史（仅捞别名与俗称）
      → v1 旧归档（仅作交叉校验）
```

## 二、四个目标怎么落地

### 目标 1：模拟知识的流动

**现成零件其实够了**：`scope`（local→regional→national→faction→elite→private）+ `settlement_ids` / `kingdom_ids` / `culture_ids` + `layer` + `fallback_referral_ids` + `lifecycle.valid_from/valid_to`。
**缺的不是机制，是"必须这么写"的规则。**

提议一个**可检查的梯度规则**：

> **同一条断言挂多条表达时，必须满足"越近知道得越细、越远只剩传闻"——
> scope 越宽，layer 必须越低。**

例（拉科尼斯湖"终年不冻"）：

| 表达 | scope | layer | 谁 |
|---|---|---|---|
| 冬天湖心还有船走，姐夫跑这趟水路上的运费是夏天三倍 | local | detail | 湖区村民 |
| 这湖冬天不冻，是北边唯一还能动的道 | regional | summary | 北方住民 |
| 听说北边有个冬天不结冰的湖 | national | rumor | 南方人 |
| （不知道 / 反问"现在是几月？"） | — | unknown | 更远处 |

这条规则一旦写成校验，就**把"知识流动"从作者的自觉变成机器的检查项**。现在的 12 档里没有一档是这么写的。

另外两块：
- **断链与寻路** → `fallback_referral_ids`（C13，未接线，跨线）
- **衰减/过时** → `lifecycle.valid_from` / `valid_to`（**0/12 用了**）

### 目标 2：模拟不同人的视角

机制够了（`expression` + `layer` + `grants`/`denies` + `min_management`/`min_steward`/`min_skill`）。
**缺的是内容**：40 条表达里 24 条（60%）与断言逐字相同。

加一条硬规则：

> **同一断言下的多条表达，文本相似度超过阈值（建议 0.8）即校验报警。**

这条直接把 C14 裁定的"兜底载体"逼成真视角——不允许再靠复制过关。

顺带说一句：schema 的 `proposition` 定义里本来就有 `perspective` 和 `polarity`（肯定/否定），只是它目前只用在**审查记录**里（`authority` 块），没用在正文上。这是现成的参照。

### 目标 3：归类 / 划分 / 关联更规范

| 该填的字段 | 现状 | 说明 |
|---|---|---|
| `domain` + `subdomain` | subdomain 12/12 | 已做，好 |
| `related_domains` | **0/12** | 关联没建 |
| `entity_ids` | 12/12 但 **11 条是 lore** | 游戏实体几乎没锚 |
| `aliases` | **0/12** | 最实际的一条硬伤 |
| `lifecycle`（split_from / supersedes） | **0/12** | 血缘只记在 manifest 里 |
| `status` | 全 `needs_review` | 没有进 `canon` 的口径 |

**命名与归属的规矩**（建议定为硬规则）：
- 游戏里真实存在的 → 锚 `entity.<settlement|hero|clan>.<code>`，ID 一律小写
- 我们自己造的（湖、湾、部族）→ `entity.lore.*` + **必须登记 `aliases`**，否则检索不到

### 目标 4：便于维护

编年史"整段复制、改一句动全身"的毛病，靠四件事躲开：

1. **拆细**：断言粒度保持 30 字左右一条（现在做得不错，平均 30 字）
2. **可回溯**：`quote` + `quote_hash` + `locator`（现在做得最好，别丢）
3. **记血缘**：`lifecycle.split_from` / `supersedes` / `merged_into`
4. **不复制**：表达不许照抄断言（同目标 2 的相似度规则）

## 三、一个能立刻用起来的新发现：写"人"反而绕开编译阻塞

C16 说编译器只认 `entity.<hero|clan|settlement>`，`entity.lore.*` 会抛 `WB-DOC-003`，12 档里有 10 档编不过。

但登记表里的实体分布是：

| kind | 条数 | 编译器认不认 |
|---|---|---|
| `hero` | **415** | ✅ |
| `settlement` | 393 | ✅ |
| `clan` | **82** | ✅ |
| 合计 | 890 | — |

**英雄 + 家族 = 497 条，编译器全都认，而我们一条都没用。**
也就是说：**现在动笔写人物档 / 家族档，天然绕开 C16**，不用等编译器改。

而且这是玩家最常问的话题（"某某领主是什么人""这家跟那家什么关系"），也是编年史最弱的一块（编年史只有地）。

## 六、一句话

**编年史是"一篇写给人看的好文章"，我们要做的是"一台能回答谁、知道什么、怎么知道的机器"。**
前者靠文笔，后者靠结构。所以编年史里我们只捡别称，事实去游戏官方数据里拿，说法我们自己原创。
