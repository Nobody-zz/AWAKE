# 斯拉涅斯之拥 · 功能头脑风暴候选清单

> 状态：候选池（Brainstorm），不是开发承诺
> 日期：2026-08-13（v6，已通过独立审查）
> 基线：v0.0.2（已实现女神对话、AI 任务网关、世界状态底座、神谕愿力环）
> 目的：参考 AliceMM 与 AnimusForge 的已有功能和思路，把“以后可能做什么”先发散记录；选中项仍需逐个走 grill-me 审查并生成 PLAN 后才实现。

## 0. 怎么读这份文档

- **候选类型**：`参考` = AliceMM / AF / 马库斯套件已有同类实现；`发散` = 本项目自己推导，需谨慎验证；`外部灵感` = 来自项目外思路，未本地验证；`待定` = 机制可参考但目标不确定。
- **价值/成本**：`值H/成L` 表示玩家价值高、成本低，依此类推；成本含开发、AI token、UI、存档与性能。
- **状态**：未筛选 / 选中 / 已实现 / 已实现部分 / 否决 / 搁置。本清单默认全部为“未筛选”；D1/D2/D9 作为已实现部分例外。
- **内容门**：涉及成人内容、俘虏、身体开发的候选必须满足 18+ 硬校验（年龄不明确即不满足）、性别与身份视角分支；未满足前不得进入实施。
- **行内门禁标记**：18+门 表示年龄硬校验 + 性别/身份视角分支；涉及成人内容、俘虏、身体开发的候选必须带此标记才能进入 PLAN。
- 本清单不锁版号、不承诺排期；筛选标准见最后一节。

## 1. 参考来源盘点

参考对象：C:\Users\26811\Downloads\1.3.3密码2008\AliceMM-AI-World-v1.3.3-1.3.x（SubModule.xml 内 Version=v1.3.3）；与 _alice_decomp 交叉核对时以该目录为准。

- 对话框架：原生对话覆盖、对话历史日志、NPC 主动请求（如缺粮请求援助/购买食物）、信使来信与回复。

- AI 链路：预处理（话题路由、记忆选择、RP 模板选择、连接测试）、后处理（行动标签、情绪标签、荒野/皇家/亲密规则）、规则行为提示词、NPC 人设生成、统治者政策提示词、玩家自定义提示词。
- 记忆：每日/重大/总览三级压缩写作要求；周报写作要求。
- 知识：本地 ONNX embedding 与 rerank、VoiceMapping、世界书四档 PlayerExports（clean/dark/extreme/bloody）。
- 开发：开发者历史编辑、周报调试弹窗、大选择弹窗。

### 1.3 马库斯 AI 框架与玩法套件设计总纲（基础设施参考，非玩法来源）

- 马库斯是工具型前置框架：不内置外交、关系、剧情玩法；关系/传播/提案等“玩法套件”部分属于设计推演，不是已实现能力。
- 框架能力：CapabilityBroker、事件总线、受控命令、存储 namespace、RAG、媒体、MCM/本地化、权限治理、双版本。
- 设计推演（仅作机制参考，来源标为发散/外部灵感）：事实/传播/信念/叙述/影响分层、关系投影、提案卡、叙述不能自动升级为事实。
- Save 是权威，sidecar 数据库是历史镜像；回档不读未来。
- PlayerKnown 门：Context/RAG/云外发三处一致拒绝；秘密不进入普通 LLM。
- 影响命令必须预演、限幅、复核、回执；禁止通用 adjust-stat 与裸 JSON patch。
- 独立可玩 + 跨 Mod 可联动，通过 Capability 交换结构化上下文。

### 1.4 SlaaneshsEmbrace 基线核对（以当前代码为准）

- 四条 AI route：dialogue / preprocess / postprocess / memory.daily。
- 三个 Context Provider：player / hero / relationship。
- 四个存储 namespace：relationships / body_state / npc.memories / favor_state。
- 五个世界命令：relationship.delta / body.develop / estrus.tick / offering.accept / boon.grant。
- 两个 durable 事件：relationship.changed / favor.changed。
- 神谕愿力环、知识 RAG + 本地兜底、权限治理、会话边界与幂等。

## 4. 横切风险与默认门禁

- **AI token 预算**：每条 route 设最大输出/输入，长列表用摘要与分页；NPC 群聊、周报、季报分别设冷却与配额。
- **限流/降级**：Provider 不可用、权限拒绝、超时、坏输出全部走 typed 降级，不阻塞游戏主循环。
- **存档 schema 迁移**：新增 namespace/字段必须带 schema version 与旧档迁移；修改保存模型时核验 SaveDefiner。
- **读档重建**：非序列化引用（菜单、任务、层、缓存）在安全点重建，不依赖静态字段残留。
- **N+1 与事件风暴**：批量读取、事件订阅去重、同事件有限跟进；UI 长列表用 append/diff。
- **UI 生命周期**：layer/输入焦点/命令回调成对处理，关闭意图在安全 tick 统一移除。
- **统一权限门**：Context、RAG、云外发三处一致校验；命令 Preflight/权限/幂等/快照复核缺一不可。
- **18+门**：所有成人内容候选先做年龄硬校验（年龄不明确即不满足），再谈性别与身份视角分支。

## 5. 取舍与不做的范围

- 不做通用 adjust-stat、任意属性名、裸 JSON patch。
- 不直接反射或硬编码 AF/爱与恨内部签名。
- 不把外部数据库当游戏权威；Save 是权威。
- 不做全大陆 NPC 持续 LLM 模拟（成本与延迟不可控）。
- 不做无门槛的任意剧情改写；事件与叙述必须分离。
- 不优先做大规模世界观文本；先保证机制与触发链路。
- 不在版本不稳定时快速提升版号。
- 不把“AI 能说”当作“世界已经改变”；一切效果必须走命令与事件。

## 6. 筛选与落地建议

1. 按“玩家价值 × 马库斯复用度 ÷ 风险成本”给候选打分，每轮只锁定一条端到端纵向切片。
2. 一条端到端纵切可以包含三个层次（例如 NPC 主动对话 + 事件弹窗 + 周报），但三个层次必须在同一批验收标准内，不能无限铺开。
3. 优先纵切建议：B4（NPC 主动对话）+ E1（事件弹窗）+ C1（周报），证明“世界会动”的最小闭环。
4. D8（女玩家视角）与 D4（俘虏事件）列为高优先，但需等 P1 关系/事件机制稳定后进入 P2，避免在未稳定的地基上做重内容。
5. 每批选中项分别走 grill-me → PLAN → 实施 → 游戏内验证；候选清单本身不承诺实现。
6. 状态列随开发更新：实现/否决/搁置的条目标记状态，避免死清单。
