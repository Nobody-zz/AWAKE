# 暗面批「补传言」· 来源对照表（2026-09-24）

> **背景**：09-24 甲方裁定「补传言」，并选定**甲案**——**只在有原句支撑处补**，不许替它们编。
> 我原以为要一档一档凑料，实况是：**这批料按「势力」与「事件」组织，一条料能同时喂多档的不同层**，
> 而这正好就是「同一件事、不同人嘴里不一样」。
>
> **本表用途**：把「哪些料 → 能喂哪档哪层 → 谁在说」一次列清，作为下一步写文本的**唯一依据**。
> 表内所有引文均为**来源文件连续子串**（校验器查 `WB-SOURCE-001`），未经改写。

## 〇、两类料，性质完全不同

| | 出处 | 内容性质 | 能否撑 rumor |
|---|---|---|---|
| **A 类** | 游戏本地化（`bannerlord.db`） | 操作提示、地名、任务台词 | **多数不能**（是"事实的凭据"）|
| **B 类** | 编年史 `knowledge/rules/*.json`（336 文件 / 1924 变体）| **人的话**：说法、成见、转述 | **能**（是"人怎么说的凭据"）|

⇒ **甲案的结论**：暗面档要补 rumor，**料必须来自 B 类**。

## 〇之二、★ 取料的四步（**本节是 09-24 甲方追问后补齐的**）

> **我第一版只做了第 ②③ 步，跳过 ①，结果把「一个教派的自述」误读成「黑社会收保护费」。**

**① 读 `When`** → **谁在说**。每个变体自带条件，这是出处里最要紧的一栏，**不能跳**：

```json
{"Priority": 0,
 "When": {"Cultures": ["empire"], "Roles": ["lord"], "KingdomIds": null, ...},
 "Content": "……"}
```

| 字段 | 含义 |
|---|---|
| `Cultures` | 说话人的文化（如 `empire`）|
| `Roles` | 说话人的身份（如 `lord` 领主）|
| `KingdomIds` | **说话人所属派系**（如 `embers_of_flame` ＝ 火焰余烬本人）|
| `HeroIds` / `SettlementIds` / `IdentityIds` | 具体人 / 地点 / 身份限定 |

**② 读 `Content`** → 他说了什么。
**③ 判性质** → 「事实的凭据」（A 类）还是「人怎么说的凭据」（B 类）。
**④ 定落点** → 喂哪档的哪一层。

**⚠️ 三层既有约束只管「字对不对」，不管「话是谁说的」**：
校验器 `WB-SOURCE-001` 查连续子串、`quote_hash` 查字节、生成器查 A/B 两类齐否 ——
**没有一层能拦「把领主的话当街坊的话用」**。那一层只能靠 ① 人工读 `When`。

## 〇之三、★ 出处链（两处来源、三层约束）

| | 出处 | 记什么 | 校验 |
|---|---|---|---|
| **A 类** | `bannerlord.db` 本地化表 | `stringId` ＋ `quote_hash` | 改一字哈希即不符 |
| **B 类** | `knowledge/rules/*.json` | `[文件名, 变体号, 原句]` 三元组 | 变体号是硬索引，取错即另一句话 |

生成器放行条件：**A、B 两类引文都齐**（跑时打印 `引文校验通过：A 56 条 / B 7 条`）。

## 四、⚠️ 噪声警告（务必不要误用）

粗关键词搜索会大量误伤，**已知误伤样例**（搜出来但与本档无关）：

- **巷子头目** ← 「厄尔辛是**森林的守护者**」「苏丹是**信仰的守护者**」
  —— "守护者"命中的是神祇与君主，**不是巷子里那个头目**。
- **帮派** ← 伊拉 / 加里俄斯 / 元老院的一堆政争台词
  —— 命中"帮"字，实为帝国政治，与城镇帮派无关。
- **巷子争夺** ← 奥斯里克 / 北帝国等争地台词（"夺我们西疆"）
  —— 国家间夺地，**不是巷子争夺**。

⇒ **两条判据，缺一不可**：
1. **必须是"同一条街面上、同一批人"的事**，别见字就收。
2. **必须读 `When` 确认说话人**，别拿正文字面猜（本轮 §一 就是栽在这条）。

## 五之二、★ 一处流程坑（2026-09-24 踩到）

`.yaml` 里中文会被 `json.dumps` 写成 `\uXXXX` 转义吗？—— **不**，`yaml.safe_load` 读 `runtime.json`
（`\uXXXX`）后**直接 `json.dumps(ensure_ascii=False)` 才可搜**。
⇒ 「新句进/旧句退」这类对质，**必须先把 json 解析再重排成明文**，
直接在 raw 文本上 `count()` 会得到**全 0 的假红**（本轮第一版就栽在这，差点误判成"料没落进去"）。
