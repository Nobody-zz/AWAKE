# UI 真渲染（离线出图）· 2026-09-16

> 目标：不进游戏，出一张**看起来就是那个面板**的图 —— 真贴图、真底色、真文字。
> 不是线框，不是分析图。
> 入口：`python awake_ui.py check --render` → `out/render/<面板>.png`（**与几何图分开放，互不覆盖**）。

## 1. 两种图，别混

| | 推导几何（`out/shot/`） | 真渲染（`out/render/`） |
| --- | --- | --- |
| 画什么 | 分类色底 ＋ 描边 ＋ 尺寸标注 ＋ 50px 网格 | 真贴图 ＋ 真底色 ＋ 真文字 |
| 用途 | 查布局：哪个框在哪、多大、属于哪类控件 | 看效果：这东西长什么样 |
| 每个控件 | 都画（连透明的也画个框） | **只画真机会画出来的** |

改后端：`preview/preview_prefab_geometry.py` 的 `svg_for(..., render=True)` 走另一条分支。

## 2. 真渲染的纪律

- **不拿分类色补空**：一个控件若既没有贴图、也没有自己的 `Color=`，那它在真机里什么都不画 —— 渲染图里也不画。用分类色补上去，就又变成分析图了。
- **Brush 的 `FontColor` 不当底色**：那是字色。只有控件自己的 `Color=` 才算底色。混用会把透明容器画成一块字色板。
- **没有绑定的文字就是没有**（见 §3）。
- **不画网格、不画描边、不画尺寸标注**。

## 3. 文字：字体是真的，内容要分可信不可信

### 3.1 字体

游戏简中字体就叫 `simkai`（楷体），字体文件在
`<game>/GUI/GauntletUI/Fonts/simkai/`，但里面**只有 `.fnt`（度量 XML）和 `.bfnt`，没有字形位图** ——
字形位图在 `.tpac` 资产包里，不在磁盘上。

⇒ 不去抠 8192×8192 的字形图集，直接用**同源的系统字体**：Windows 自带 `simkai.ttf`
（字体族名 `KaiTi`）。用字体族名让浏览器自己找，**不复制字体文件**（`file://` 与 http 两种打开方式都能用）。

字号取自真 `.fnt` 的度量（`ui_text_metrics`），所以**换行与位置是游戏口径**，只有字形轮廓是系统字体。

### 3.2 内容可信度（**这一节是踩出来的**）

`Text="@属性名"` 在游戏里是 DataSource 绑定，**值来自运行时**，本无静态文本。
本项目把属性名取成了本地化 id 的同名，所以能按名查出来 —— 但这个巧合在**重名**时会崩：

> 实测：`@TitleText` 在对话面板被画成了「醒世 · 开发者检查」。
> 因为 `NpcDialogueVM.TitleText` 是**运行时数据**（`private set`），
> 而 `DeveloperCheckVM.TitleText` 是写死标题。按属性名全局建表、先到先得 ⇒ 串到了别处。

**判据**（`ui_text_metrics.TextResolver.is_static`）：

1. 能确定这个面板的 ViewModel 类时（`movie → VM`，由 `LoadMovie("X", ds)` ＋ `new YVM(` 成对取得），
   **只看那个类里**的定义：
   - 有 `AwakeLocalization.Resolve(...)` / 字面量 ⇒ **可信**，照画；
   - 只有运行时实现（`=> _contact.DisplayName`、`StatusText = evt.Text`）⇒ **不画**；
   - 同一类里同名多份、id 不一致 ⇒ **不画**（那是随状态变的）。
2. 定不到 VM 类时退回全体：所有定义必须解出**同一串字**才算可信。

**为什么必须较真**：渲染图看起来越像真的，串号越没人怀疑。分析图上写错字有人会愣一下，渲染图上写错字会被当成事实。

### 3.3 结果：哪些字画不出来

下面这些**渲染图里是空的，属正常**，不是 bug：

- 联系人名 / 对话内容（`@DisplayName` `@Speaker` `@Text`）—— 运行时数据；
- 窗口标题（`@TitleText`）—— 同上，且重名；
- 关系文案（`@RelationshipText`）、提示文案（`@NoticeText`）—— 随状态变；
- 输入框里的字（`@InputText`）。

**含义**：面板看起来会偏空，尤其是对话区与名册行。这是**如实反映**"这些位置的内容由运行时填"，
不是渲染失败。

## 4. 已知画不出来的（除文字外）

- **互相排斥的状态文字会叠在一起**。例如「正在生成全身像…」与错误提示是两个控件、靠运行时 `IsVisible` 决定谁显示 —— 静态出图会两张都画，看起来糊成一团。看到同一位置有重叠文字，先想这条。
- **`IsVisible="false"` 的控件照画**：同上，运行时才决定。
- **列表行用的是夹具**（默认 3 行），不是真实数据行。
- **`{DAY}` 这类富文本变量不替换**，原样显示。

## 6. 还差什么

- **真机验证**：渲染图过不等于真机过。真机要验的是焦点、层序、点击、以及字体在游戏里的实际渲染。
- **`.tpac` 资产**：本机磁盘上没有 `simkai` 的字形图集，所以字形用的是同源系统字体。要做到字节级一致，得从 `.tpac` 里把 `simkai.png` 抠出来 —— 有现成技能（`bannerlord-tpac-extraction`），但只有在对字形轮廓较真时才值得做。
- **离屏渲染器**：本模式是「按 XML 推导几何 ＋ 按属性填色填字」的**仿真**，不是 Gauntlet 的渲染器。
  不覆盖：富文本内联标签、文本自动换行的引擎细节、Brush 的 Hover/Pressed 态、动画。
