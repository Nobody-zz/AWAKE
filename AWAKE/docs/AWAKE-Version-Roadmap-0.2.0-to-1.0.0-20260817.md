## 1. 产品目标

AWAKE 1.0.0 首先必须是一个完整、稳定、可长期游玩的 AI 世界模组，其次才是第三方开发平台。

1. 玩家能够在场景、地图、遭遇、通讯录和事件中自然进入统一 AI 对话。
2. NPC 能够形成可追溯的记忆、关系、承诺、恩怨和长期行为变化。
3. 对话和关系能够触发真实事件、世界结算、社会传播和政治后果。
4. 模组具备清晰的安装、配置、引导、诊断、存档迁移和失败降级。
5. 官方内容包能够提供可安装即玩的世界书、事件、角色规则和内容示例。
6. 第三方内容包可以通过稳定 API 接入，但不需要修改 AWAKE 核心源码。

## 2. 双轨版本策略

### 2.1 AWAKE 核心轨

AWAKE 核心负责通用运行机制：对话、会话、记忆、关系、事件、命令、通信、世界状态、UI、诊断、性能和公开 API。

核心不得内置：

- 固定女神人格；
- 成人内容；
- 特定世界观事件正文；
- 依赖某一内容包才能工作的存档模型；
- 绕过公开接口的内容专用逻辑。

### 2.2 官方内容轨

官方内容使用独立 ModId、版本号和兼容范围，通过 AWAKE 公开接口接入。

官方内容分为三个互不强制依赖的支线：

1. **基础内容包：斯拉涅斯之拥**：世界书、角色规则、信件、事件、主动动机、政治与社会内容。
2. **女神人格支线**：独立 Persona、神谕或梦兆入口、关系与事件内容，不依赖成人插件。
3. **成人内容插件**：独立 ModId、DLL、配置、存储和 ContentTier；关闭或未安装时不得影响 AWAKE 与基础内容包。

### 2.3 兼容关系

- 核心与内容包不要求同步提版。
- 内容包 manifest 必须声明最低/最高 AWAKE API 版本。
- AWAKE 核心发布不依赖成人插件。
- AWAKE 1.0.0 必须至少有一个兼容的官方基础内容包稳定版本。

## 3. 版本方法

采用“可玩闭环为主体、测试阶段为门槛”的方式。

每个大版本必须同时包含：

- 一个主要玩家体验闭环；
- 支撑该闭环的底层机制；
- 对应 UI、MCM 和即时反馈；
- 官方内容包的可验证样例；
- 存读档、性能和真机验收。

### 3.1 版号规则

- `0.x.0`：一个新的主要体验闭环。
- `0.x.1`、`0.x.2`：修复、补验收、小范围完善，不混入下个版本的大机制。
- 未达到退出门槛时不得升版。
- 可延期功能移入后续版本，不能以“代码存在”冒充完成。
- `0.9.0` 后原则上禁止新增玩法。
- 普通修复不擅自提版。

## 5. v0.2.x：稳定当前基础

### 5.1 版本定位

把当前已经完成的代码从“离线验证通过”推进到“可以交给小范围玩家测试”。本阶段不扩张大型机制。

### 5.2 v0.2.0 当前开发基线

当前已有：

- NPC、地图、场景、遭遇和通讯录 AI 对话入口；
- transcript 对话历史、联系人索引、历史固定和旧档迁移；
- 结构化记忆、关系状态和承诺账本；
- `give_gold` 可恢复结算；
- 世界书加载、索引、相关性过滤和运行时注入；
- 数据驱动事件引擎、世界状态账本和周报；
- 主动对话动机基础；
- 事件收件箱、周报、通讯录、开发者检查和多步引导 UI；
- 双版本构建、SdkSmoke、发布检查和同步脚本。

这些功能仍有多项 `fixed_pending_game`，因此当前 `0.2.0` 不是正式技术内测完成态。

### 5.3 v0.2.1：真机稳定与 Level 0

必须完成：

- 完成 `VAL-20260817-1`；
- 关闭 `FB-20260817-10/11/12`；
- 验证地图、场景、通讯录和写信历史；
- 验证引导进度、跳过和覆盖层焦点；
- 验证金币扣除、补偿和读档恢复；
- 验证记忆摘要落盘与读取；
- 验证退出时无 dropped write；
- 验证 Provider、Route 和云外发策略；
- 主动对话使用安全默认值；
- 形成安装、已知问题、日志收集和存档备份说明。

退出门槛：

- 新档、现有测试档、保存重载均可进入大地图；
- 连续运行至少 1–2 小时无 P0；
- 无重复扣款、存档损坏和 UI 锁死；
- Level 0 技术内测可开放给 10–20 人。

### 5.4 v0.2.2：Level 0 反馈修复包

仅在 Level 0 产生足够反馈时发布：

- 修复安装、兼容、配置和 Provider 问题；
- 修复日志确认的 UI、存储和存档问题；
- 补充诊断导出与错误指引；
- 不加入 `0.3.0` 的新玩法。

### 5.5 官方内容并行轨

- 接入基础世界书、信件模板、事件样例和 NPC 动机；
- 不要求女神人格或成人插件；
- 无内容包时 AWAKE 必须独立启动。

## 6. v0.3.0：对话与社交闭环

### 6.1 版本定位

让玩家在所有合理场景中都能找到 NPC、继续同一人物历史并保持联系，不再面对多个割裂入口。

### 6.2 核心功能

- B1 双模式对话：AWAKE 独立覆盖层 + 原版对话窗口 AI 模式；
- 原版任务、强制剧情、竞技场等上下文隐藏 AI 模式；
- 场景、遭遇、地图、通讯录和事件入口共用统一会话状态；
- 统一取消、关闭、超时、焦点和会话 token；
- 远程写信正式加入送达流程；
- NPC 主动来信和玩家回信；
- 未读计数和大地图通知；
- 联系人附近/远方状态、头像、身份和关系摘要；
- 等待动画、流式状态和取消反馈；
- 主动对话支持场景邀请、地图通知和来信；
- 所有入口使用 canonical identity 和统一 transcript。

### 6.3 数据和运行规则

- `AwakeDialogueSession` 是会话权威；
- `AwakeDialogueHubLifecycle` 管理对话型覆盖层；
- transcript 是原始历史权威；
- NPC 记忆只保存摘要和结构化事实；
- 信件记录创建时间、发送者、接收者、送达、已读、回复关联、过期和失败原因；
- 所有入口走相同权限、Prompt、世界书和命令策略。

### 6.4 明确延期

- 群体议事和群聊；
- 媒体与 TTS；
- 复杂信使距离模拟；
- 流言网络；
- 王国外交和阴谋。

### 6.5 官方内容并行轨

- 身份差异对话规则和写信模板；
- 第一批主动来信动机；
- 世界书驱动角色口吻；
- 女神人格可做独立技术原型，但不是本版依赖。

### 6.6 退出门槛

- 所有入口继续同一人物历史；
- 原版任务对话不被破坏；
- 覆盖层关闭后焦点完整恢复；
- 写信、送达、未读、阅读和回复形成闭环；
- 达到 Level 1 玩法内测门槛。

## 7. v0.4.0：记忆与关系闭环

### 7.1 版本定位

NPC 根据真实经历形成长期态度、承诺、恩怨和关系变化，而不是只保存聊天记录。

### 7.2 核心功能

- S/A/B/C 记忆等级；
- 按游戏日衰减、合并和压缩低等级记忆；
- 固定历史不自动清理；
- 承诺状态：请求、接受、拒绝、完成、违背、取消、过期；
- 关系轴：信任、爱意、敌意、恐惧；欲望或利益依赖由内容包扩展；
- 区分公开关系、NPC 隐藏态度和 NPC 之间的社会关系；
- 家族、亲族、婚姻、主从、王国和封臣关系作为永久事实；
- 关系阶段影响语气、主动联系、秘密、请求、条件和报复；
- 记忆管理器提供查看、固定、隐藏和清理，但不能直接修改真实态度。

### 7.3 数据权威

- 存档状态是关系和承诺权威；
- 外部数据库只保存历史镜像；
- 摘要记录来源和证据；
- 关系改变只来自原版世界事实、已结算命令、已确认事件、玩家选择和明确衰减规则；
- 记忆检索必须有 top-k 和字节预算。

### 7.4 官方内容并行轨

- 关系阶段对话和小型事件；
- 女神人格可进入独立 Alpha；
- 成人插件可在本阶段之后启动，但必须独立 ContentPolicy、18+ 校验和视角分支；
- 两个可选支线都不是 `0.4.0` 退出条件。

### 7.5 退出门槛

- NPC 跨存档记住重大事件和承诺；
- 日常对话会压缩；
- 违背承诺影响后续对话和事件；
- 关系变化有可追溯来源；
- 不同关系阶段产生明显但不过度跳跃的行为差异。

## 8. v0.5.0：事件与世界反应闭环

### 8.1 版本定位

让对话、记忆和关系真正影响卡拉迪亚世界，而不是停留在文本中。

### 8.2 核心功能

- 事件条件：人物、身份、文化、王国、地点、关系、近期事件、世界状态、冷却和每日上限；
- 多阶段链、延迟后续、过期、互斥、失败分支和后果追踪；
- 世界效果：关系、金币、事件记录、繁荣、忠诚、治安、粮食、犯罪或名誉、后续事件；
- 高风险效果使用上下文和权限 gate；
- 周报汇总重大事件、关系、承诺、王国变化、传闻和线索；
- NPC 由世界事件触发求助、警告、谈条件、报复、报信、索债、邀请和试探；
- 事件结果写回世界账本并影响后续对话。

### 8.3 结算规则

- AI 只能选择已注册命令；
- 命令必须参数校验、权限、主线程结算、幂等、回执和失败补偿或 fail-closed；
- 内容包事件不能直接调用 Bannerlord API；
- 事件内容与运行时引擎分离。

### 8.4 官方内容并行轨

- 先制作约 20–40 条高质量事件，不立即迁移数百条旧内容；
- 每条事件具备触发、真实结算、后果、冷却、中英文和复验路径；
- 女神人格和成人插件通过统一事件接口与 ContentPolicy 注册。

### 8.5 明确延期

- 完整国家外交模拟；
- 大规模阴谋网络；
- 刺杀行动；
- 借贷经济；
- 头衔和称号；
- 群体议事和媒体。

### 8.6 退出门槛

- 事件由真实条件触发；
- 玩家选择产生真实世界效果；
- 保存重载后事件链和冷却不丢失；
- 周报能解释世界变化；
- 至少一个官方内容包完成触发、选择、结算、后果和后续对话全链路。

## 9. v0.6.0：通信与社会传播

### 9.1 版本定位

把通讯录升级为卡拉迪亚的通信与信息传播网络。

### 9.2 核心功能

- 信件发送地点、接收者所在地、预计送达日、送达、延误、退回和失效；
- 同城/同行快速送达，跨地区按距离估算，战争、被俘、失踪可阻断；
- NPC 主动来信：求助、报信、索债、警告、邀请、试探和谈判；
- 未读计数、大地图通知和联系人筛选；
- 群体会话使用家族议事、战团议事、宫廷会议、阴谋小圈等世界观入口；
- 区分实际在场、可见消息、发言资格、发言顺序、私下回复、公开与真实态度；
- 秘闻和流言记录来源、知情者、可信度、传播范围、公开程度、过期和推翻；
- 不在场 NPC 不得凭空知道即时谈话。

### 9.3 数据和性能规则

- 通信队列和送达状态机持久化；
- 信件、主动来信和群体议事继续使用 transcript；
- 流言传播结构化事实，不传播完整聊天文本；
- 传播必须有来源、路径和接收者；
- 群体会话使用单一会话 ID、多参与者和独立可见性；
- 限制同时生成回复数和 token 预算。

### 9.4 媒体与 TTS

- 头像、立绘、插图、语音和 TTS 通过 capability 探测；
- 不可用时降级为文字；
- 不绑定特定 Provider；
- 不作为 `0.6.0` 硬门槛。

### 9.5 官方内容并行轨

- 身份化信件模板；
- 家族、宫廷、战团和阴谋议事样例；
- 第一批流言、秘闻和来信事件；
- 女神人格通过消息队列发送神谕或梦兆；
- 成人插件可提供私密信件，但必须独立门控。

### 9.6 退出门槛

- 跨地点送达、延误、阅读和回复可验证；
- 不在场 NPC 不会无理由知情；
- 流言沿明确路径传播并影响后续对话；
- 群体议事不无限生成或锁死 UI；
- 通信队列不重复投递。

## 10. v0.7.0：权力、王国与阴谋

### 10.1 版本定位

让 NPC 根据身份、领地、家族和王国利益进行决策。

### 10.2 核心功能

- 王国/派系对玩家、其他王国、家族、政策和战争的态度；
- 王国卡：统治风格、军事倾向、经济压力、文化立场、对外关系和危机；
- 正式头衔、民间称号、知名度、恶名、传播范围和来源；
- 身份差异影响对话和事件；
- 政令与政策提案影响繁荣、忠诚、治安、粮食、税收、征兵和贸易；
- 阴谋记录目标、发起者、参与者、动机、准备度、风险、暴露度、结果和报复；
- 刺杀作为高风险结构化行动，必须有准备、失败、暴露和政治后果；
- 借贷、还款、违约、利息或代价进入交互账本；
- 战俘转化等高风险机制单独立项，不混入核心。

### 10.3 结算规则

- 区分建议、玩家批准、系统结算和已发生结果；
- 未批准的政策或阴谋不能写成已发生；
- 高风险行动必须有上下文、风险策略、幂等、补偿和审计；
- 王国状态按游戏日或事件更新，不在 tick 中调用 AI。

### 10.4 官方内容并行轨

- 王国性格、文化冲突和派系立场；
- 宫廷、领地、阴谋和权力交易事件；
- 称号、流言和政治后果文本；
- 女神人格只能提出条件或影响选择，不能绕过结算；
- 成人插件中的权力交易使用同一身份、风险和后果机制。

### 10.5 退出门槛

- 身份和国家利益影响 NPC 决策；
- 政策必须经玩家选择；
- 阴谋有准备、暴露、失败和后果链；
- 借贷和承诺跨存档追踪；
- 周报解释王国、派系和阴谋变化。

## 16. 延期规则

以下情况自动延期，不拖住整个版本：

- 框架 capability 不可用；
- 无安全降级路径；
- 无法通过存读档；
- 会破坏原版任务或对话；
- 没有真实调用方；
- 只有 AI 文本，没有代码结算；
- 无玩家可观察结果；
- 无法满足性能预算；
- 尚未完成 PLAN、审查和用户签收。

不可延期的核心闭环必须修复或缩小范围，不能带半成品升版。

## 18. 路线图治理

- 本文件是版本方向，不替代任务队列和单项 PLAN。
- 每个大版本开始前必须建立独立版本 PLAN，并将功能拆成可审查批次。
- 新想法先进入候选池，不自动塞入最近版本。
- 每次升版必须写清：完成、延期、删除、已知问题和兼容范围。
- 当前实际工作仍应优先完成 `0.2.1` 真机验收；路线图确认后不会自动启动 `0.3.0`。
### 18.1 计划必须绑定版本目标

以后新建或重新安排任何 PLAN、Batch、修复包或体验任务，必须在标题或首部明确写出：

- `TargetVersion`：目标版本，例如 `0.3.0`、`0.2.1`；
- `Milestone`：属于该版本的哪个可玩闭环；
- `Status`：`draft / approved / implemented / pending_game / paused / done`；
- `Dependencies`：前置计划、框架能力、内容包或真机证据；
- `Scope`：本批次包含什么；
- `OutOfScope`：明确不做什么，防止版本膨胀；
- `ExitCriteria`：入口、调用、结算、可观察结果和验证命令；
- `ReleaseImpact`：是否阻塞该版本升版。

任务提醒、队列检查点和每轮计划汇报必须先显示版本目标，再描述当前动作。若任务中途改变版本归属，必须同时更新路线图、PLAN 索引和任务队列，不能只改口头优先级。
