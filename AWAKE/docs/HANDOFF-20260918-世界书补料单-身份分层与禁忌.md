## 三、要补三件（按优先级）

### ① 补"密档层"（最重要）
现在"最细"只到 `detail`，全包只有 2 条 `secret`。**没有密档，就没有"这事只有极少数人知道"**，
角色也就没有"我知道、但我不便说"的余地。
⇒ **每个类别各挑若干条**，补一条比现有 `detail` 更细的说法，只授权给上层身份（`noble`／`notable`／`headman`），
`min_detail` 写 `detail` 或 `secret`、`scope` 写 `elite`／`national`。

### ② 补"硬拒绝"（denies）
全包 **3 条，全在一个条目里**。`denies` 的语义是**"这件事对这类人来说根本不该存在"**——
今天没有它，低身份角色遇到密档时只会"什么都没查到"，而不是"知道有这回事、不该他打听"。
⇒ 与 ① 配对：**同一条目补了密档，就同时给它写一份 denies 名单**（谁连"有这回事"都不该知道）。

### ③ 补齐覆盖缺口（对齐身份词汇）

**⚠️ 这里有个词汇口径要你们定**：内容侧大量授权写的是 `villager`（村民），而
**`commoner` 与 `villager` 在包里是两个不同身份**，代码侧由"游戏职业"映射过来的：
`Villager`/`Farmer` → `villager`；**没有任何游戏职业直接产生 `commoner`**。
⇒ 所以 `commoner` 那 30 条缺口**可能不是漏写，是这个词本来就不该被用**（或代码侧该多映一些职业过去）。
**请先定口径：底层身份统一用哪个词。** 这条不定，第 ③ 项补了也会错位。

## 四、字段口径（照抄样板即可）

**全包唯一的完整样板**：`awake:entry:politics.clans-charas-cortain-secret`（"沙拉斯·科尔坦家的账"）。
它的结构：同一件事挂多条说法，各配各的授权；再给不该知道的人写 `denies`。

一条说法（expression）长这样：
```json
{
  "id": "awake:expression:<条目>-<说法名>",
  "detail": "secret",                      // 这条说法本身有多细：rumor < summary < detail < secret
  "text": { "zh-CN": "……", "en": "……" },
  "grants": [
    { "identity_id": "awake:identity:noble", "min_detail": "secret", "scope": "elite",
      "conditions": {}, "referralIds": [] }
  ],
  "denies": [
    { "identity_id": "awake:identity:anonymous", "min_detail": "rumor", "scope": "local", "conditions": {} }
  ]
}
```
- `detail`（说法自身档位）与 `min_detail`（看这条要求的最低档）**都要写**，两者含义不同：
  前者是"这条话有多细"，后者是"你至少要多懂行才看得到"。
- `scope` 取值：`local` < `regional` < `national` < `faction` < `elite` < `private`。
- `identity_id` 取值就是包里的 12 个身份（`identities` 表），加 `awake:identity:public`（人人可得）。
- **低档说法不要授权给上层身份**（他们从自己的高档说法取；授权叠了会被高分那条盖住，白写）。
- `denies` 命中即**整条不给**（连"有这回事"都不说），比"不给细档"重，别乱用。
