# AWAKE 讨论阶段保存协议

## 目的

本协议用于 AWAKE 产品方向、架构边界和玩法机制的长对话讨论。它不替代实现批次 checkpoint，也不把讨论结论伪装成已实现功能。

## 保存时机

在当前讨论线程中，满足以下任一条件就更新 checkpoint：

1. 一组 P0/P1 问题完成确认；
2. 累计确认约 5–8 个重要结论；
3. 用户纠偏产品方向或否定上一版推论；
4. 从一个大方向切换到另一个大方向；
5. 发生上下文压缩、任务迁移、暂停或交接前；
6. 结束一轮较长的连续讨论前。

按现实时间计，连续活跃讨论约 30–45 分钟时也应检查一次；如果当前回合没有文件写入能力，则在下一次可写回合立即补写。

## 每次 checkpoint 必须记录

- 当前讨论主题和日期；
- 已确认结论；
- 被否定或暂缓的方向；
- 与现有实现/契约冲突的地方；
- 尚未决定的问题；
- 当前没有实现、同步或游戏验证的事实；
- 唯一下一步讨论动作；
- 下一次保存触发条件。

## 文件策略

- 同一大方向连续讨论时，更新该方向的活动 checkpoint；
- 发生重大方向切换时，创建新的日期化 checkpoint，不覆盖旧结论；
- `AWAKE-CURRENT.md` 只保留当前讨论 checkpoint 的路径、状态和下一步，不复制全文；
- 讨论 checkpoint 不替代 `PLAN-*`、合同、实现批次 checkpoint 或游戏验证记录；
- 任何结论从讨论进入实现前，仍必须经过适用的 `grill-me-codex`、计划、审查和用户签收。

## 诚实边界

如果没有发生文件写入，就不能声称“已保存”。Codex 不能在没有新回合或工具调用时于后台自主写文件；“定时保存”在本项目中按上述讨论里程碑和活跃时间检查执行。
