## 一、结论先说：三个入口，两个真用，一个挂名，另有两处空位

运行时会往云端发请求的路由一共 4 条（`src/AiTaskConstants.cs:99-105 AllRouteIds`）：

| 路由 | 提示词 ID | 正文放在哪 | 谁在调 | 走不走模板渲染 |
|---|---|---|---|---|
| `AWAKE.route.npc.dialogue` | `awake.npc.v1` | `NpcPromptTemplate.TemplateText` | `NpcDialogueService` | ✅ 走 |
| ↑ 同一路由的喊话模式 | `awake.scene_shout.v1` | `SceneShoutPromptTemplate.TemplateText` | 同上 | ✅ 走 |
| `AWAKE.route.memory.daily` | `awake.npc.memory.summary.v1` | **不在模板里**，在 `NpcMemorySummaryTemplate.BuildInput` 手拼 | `NpcMemoryService` | ❌ 不走 |
| `AWAKE.route.preprocess` | 无 | — | **全仓零调用点** | — |
| `AWAKE.route.postprocess` | 无 | **无** | **全仓零调用点** | — |

⇒ 一句话：**"内置提示词"在这个项目里等于"三段开场白"，其中只有两段真的被当模板用。**

## 二、三个提示词逐个说

### 1. `awake.npc.v1` —— 跟一个具体 NPC 说话（唯一的主力）

- **谁触发**：玩家在对话面板里说一句（`NpcDialogueService`）。
- **版本**：`v1` / revision `context-grounding-v2`（`src/NpcDialogueConstants.cs:8-11`）。
- **输出契约**：`awake.npc.output.v1`，字段 `reply` / `mood` / `effects` / 可选 `command`（`NpcPromptTemplate.cs:95-106`）。
- **13 个变量**（`:108-109`），全在 `NpcDialogueService.cs:1170-1189` 一处装配：

| 变量 | 装的是什么 | 从哪来 |
|---|---|---|
| `retrieved_knowledge` | 世界书命中的知识 | `WorldKnowledgeDecisionPolicy.BuildPromptBlock`（`WorldKnowledgeModels.cs:243-255`） |
| `persona_dsl` | 这个人是谁、什么脾气 | `PersonaSessionHydrationAdapter` → `BuildPersonaProjection`（`NpcDialogueService.cs:1136-1145`） |
| `npc_memory` | 跨会话记忆摘要 | `_memoryBlock`（打开面板时载入） |
| `npc_state` | 身体、处境、未命名约束 | `_npcState` + `AwakeUnnamedProfileService.BuildStateConstraint`（`:1160-1167`） |
| `npc_commitments` | 未履行完的承诺 | `_npcCommitments` |
| `npc_identity` | 身份 | `BuildNpcIdentity()`（`:1174`） |
| `player_known` | 玩家姓名/家族/王国 | `SerializePlayerKnown`（`:1180`，按天刷新） |
| `scene` | 当前场景词 | `_sceneKeywords` |
| `scene_people` | 在场的其它人（仅喊话） | `BuildScenePeopleBlock()`（`:1182`） |
| `opening_hint` | 开场提示 | 面板打开时定 |
| `player_turn` | 玩家这一轮的原话 | 直接透传 |
| `npc_id` | 角色 ID | `_heroId` |
| `dialogue_action_mode` | 聊天 / 谈条件 | 面板开关（`:1186-1188`） |

- **正文骨架**（`:14-93`）——开场定调一句，加 **12 个材料段**（每段一个标签 + 一个 `{{变量}}`）：

```
开场定调      你是卡拉迪亚的{{npc_identity}}……态度变化必须有可追溯的触发点
【角色人格模板】 + 一句"它不是本轮发生的事实，不要凭空增加模板未提供的硬事实"
【检索到的知识】 ← ★ 后面没有说明句
【跨会话记忆】   + "若此处为空，表示这是你们第一次深谈，不要编造共同经历。"
【当前NPC状态】  + "这段状态会影响你的态度，但不剥夺你的意志。"
【当前未决承诺】 + "只列已进账本未履行完毕的；不要把待确认说成已完成，也不要编造清单之外的承诺。"
【NPC身份】
【对话历史】
【玩家情报】
【当前场景】
【开场提示】     + "若此处为空，表示这是一次普通交谈，不要编造刚被邀约或刚应允的开场。"
【本轮动作模式】
【玩家本次言语】
对话要求（10 条）
两个 JSON 输出示例
```

- **★ 一个值得记住的写法规律**：**每放一段"会空、容易被编"的材料，后面就跟一句"这段是什么 / 为空意味着什么 / 不许拿它编什么"。**
  12 个材料段里带就地说明的是 5 段：**人格 `:19`、记忆 `:26`、状态 `:30`、承诺 `:34`、开场 `:50`**；
  另外 7 段不带说明，原因是它们通常总有值 —— 而**【检索到的知识】是其中唯一一段"可以整段消失"的**。
  ⇒ 它一旦为空，渲染出来就是一个 JSON 空串，后面直接接下一段标签，**没有任何一句话告诉模型"这个格子空着是正常的"**。
  要补的那一句，句式、位置、口径全有现成的 5 个样例可照。

- **对话要求区**（`:58-68`）里有几条硬规矩，注意**它们与具体材料段无关，是全局的**：
  - 中世纪语气、80–180 字、不用现代词（`:59`）
  - "只有〔知识／记忆／状态／承诺／玩家情报／场景／历史／本轮言语〕能作为本轮事实依据；**资料为空或没有提到时，要承认不知道**"（`:61`）
  - 允许拒绝、谈条件、沉默、转移话题（`:63`）
  - "人物说出来的不等于游戏状态已经改变"（`:64`）
  - `chat` 模式必须省略 `command`（`:65-67`）

### 2. `awake.scene_shout.v1` —— 对场景喊话（不绑定具体人）

- **版本**：`v1` / revision `release`（`src/SceneDialogueModePolicy.cs:5-8`）。
- **输出契约**：`awake.scene_shout.output.v1`，**只有 `reply`/`mood`/`effects`，没有 `command`**。
- **6 个变量**（`SceneShoutPromptTemplate.cs:60-61`）：只有知识、在场人物、玩家情报、场景、开场提示、玩家言语。
  ⇒ **没有记忆、没有角色卡、没有状态、没有承诺**——因为回应的不是某个人，是"听见声音的在场者构成的声音"（`:13`）。
- **正文**（`:12-46`）：与主模板同构，同样带"若此处为空"的就地说明（在场人物段 `:20`：附近没人也照样可以回应）。
- **硬约束**（`SceneDialogueModePolicy.cs:10-12`）：不读记忆、不读关系、不许 `command`。

### 3. `awake.npc.memory.summary.v1` —— 关掉对话后压缩成一句记忆

- **版本**：`v1` / revision `release`（`src/NpcMemoryService.cs:16-19`）。
- **★ 正文不在模板里**：`TemplateText` 只有 `"{{input}}"`（`NpcMemorySummaryPrompt.cs:14`）。
  真正的提示词是 `BuildInput()` 里用 `StringBuilder` 拼的一段话（`:44-55`）：
  「你是卡拉迪亚的记忆书记官……只依据下面提供的事实与对话提示，不编造、不评价、不使用现代词汇……事实：… 对话提示：…」
- **为什么还登记一个空壳**：`NpcMemoryService.cs:486` 要先 `RegisterPromptBestEffortAsync` 才允许发请求（路由前置检查），
  正文则直接 `SubmitAsync(route, input, …)`（`:511-520`）——**注册和正文是两件事**。

## 四、机制：登记、编译、预算（决定"改了会不会生效"）

1. **登记**（`src/AwakePromptRegistry.cs:20-44`）：内存字典，键是 `promptId|version|revision`（`:37`）。
   ⇒ 同键再注册就是**直接覆盖**，所以改正文不升 revision 也照样生效——**但日志 `prompt_registered`（`:40-42`）会显示同一个 revision，
   事后分不清是哪一版正文**。这才是"改模板必须升 revision"的实际理由，不是技术限制。
2. **编译**（`:46-91`）：查不到定义就返回 `prompts.unknown_definition`（`:68-79`，`retryable: true`）。
   渲染只有一份实现：`NpcDialoguePromptPipeline.RenderTemplate`（`:82`，实现见 `NpcDialoguePromptPipeline.cs:122-132`）——
   单趟正则替换，值做 JSON 序列化，**未提供的占位符原样保留**。
   （`NpcPromptTemplate.BuildDirectInput` 只是转发到它；2026-09-15 同源化，原先另有一份平行实现会导致"值里含 `{{}}` 被二次替换"。）
3. **预算**（`NpcDialoguePromptPipeline.cs:40-95`）：硬上限 **32768 字节**（`NpcDialogueConstants.cs:18`）。
   先整段直拼；超了才按固定顺序截断，最多 6 轮：
   `player_turn → dialogue_history → npc_memory → retrieved_knowledge → opening_hint → npc_state`（`:30-38`）。
   6 轮仍超才降级成 `IsDirectOnly`（`:83-86`），调用方直接用直拼文本（`NpcDialogueService.cs:1199-1202`）。
   ⇒ **知识排在第 4 位**，只有前三个都砍完还不够才会被动。
4. **对话历史**（`:134-149`）：只取最近 **12 轮**、每轮截 400 字（`NpcDialogueConstants.cs:16`）。
5. **诊断**（`:169-201`）：每次装配会留一行 `dialogue_context.knowledge = present/absent`（`:181`，判据见 `:210`）——
   这是产品里现成的"这轮有没有世界书事实"观测点。

## 五、三条与当下那件事（拆开"知道"与"开口"）直接相关的事实

1. **知识段是唯一一段"会整段消失、却没写就地说明"的材料段。**
   它一旦为空，模板渲染出来就是 `""`（JSON 空串），后面紧跟下一段标签——模型看到的是一个空的知识格，没有任何解释。
   而"为空怎么办"的句式，模板里已有 5 处现成样例可照。
2. **`dialogue_context.knowledge` 是现成的观测点**，语义正好是"这轮送给模型的材料里有没有世界书事实"。
   ⚠️ 前提是知识块为空时变量要真的为空——若改成在知识层硬塞一段文案，这个诊断会一律变成 `present`，就废了。
3. **"NPC 主动开口"这条腿完全没有提示词。**
   `src/NpcProactiveService.cs`（20,774 B）全文没有 `Submit` / `Route` / `Prompt` 任何命中，
   只做存储读写（`GetProactiveAsync` / `UpdateProactiveAsync` / `GetRelationshipAsync`）。
   ⇒ 主动话题目前是纯本地逻辑生成，**不经过模型、也读不到世界书**。而 v0.3 的过版判据恰恰是"NPC 会主动找你、会提起旧事"。
