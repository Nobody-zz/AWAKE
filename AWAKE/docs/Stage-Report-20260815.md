## 3. 优点

1. 边界清晰：触发由代码决定，AI 只产结构化意图，效果走受控命令，杜绝“AI 说什么都算数”。
2. 降级安全：AI/存储/知识不可用时对话仍可开、记忆退化为事实账、知识退化为空，不阻塞游戏。
3. 预算可控：知识 4096B、记忆 2500B、总 prompt 32KB，且按文本元素截断，防上下文爆掉。
4. 可审计：conversationId 幂等、命令结算先于事实、生命周期 drain 顺序明确，读档/重开/崩溃语义清楚。
5. 过程可追溯：每个新功能都有 PLAN + 对抗审查 + 修复记录，后续维护有据可查。

## 4. 缺点与风险

1. 记忆摘要仍是 best-effort：摘要 AI 慢或会话结束时未完成，只保留事实账；语义层可能偏冷。
2. 本地知识索引召回有限：没有 RAG 与语义检索，玩家问法偏离关键词时知识命中率低。
3. 游戏内验证不足：菜单“深谈”、记忆跨存档回读、知识命中这三条只过了 SdkSmoke，未做真实战役验证。
4. 事件引擎入口未接：事件还不能打开 NPC 对话，玩法联动靠直接调用点，覆盖面窄。
5. 内容仍少：388 条事件、四版世界书、角色卡变体尚未入库，框架“能跑”但“内容不厚”。
6. 版本仍为 0.2.0：可玩性尚未达到真正 0.3 的标准，不宜急着提版。

## 7. 架构分层评估

- 输入/触发层：事件引擎、NPC 主动、玩家菜单深谈、俘虏/营地行为。优势：触发由代码决定、有冷却与忙锁；薄弱：事件尚未数据驱动，入口覆盖不全。
- AI 编排层：AiTaskGateway + route + prompt + 输出校验。优势：单次结构化输出、命令白名单、取消/超时语义明确；薄弱：NPC 对话命令面窄（仅 relationship.delta）。
- 状态/存储层：WorldStateStore + Marcus Storage。优势：pending/outbox/幂等、final drain、记忆 reserve 机制；薄弱：事件元数据未持久化、知识检索仅本地索引。
- 命令/效果层：WorldCommandBridge + adapter + 权限。优势：target 强锁、限幅、typed 错误；薄弱：效果仍以关系为主，body/estrus 未接入对话。
- UI 层：Gauntlet 覆盖层与菜单。优势：独立 prefab、焦点校验；薄弱：字体/布局细节与游戏内实测不足。
- 内容层：事件/世界书/角色卡。优势：内容与机制解耦方向明确；薄弱：388 事件与四版世界书尚未入库。
