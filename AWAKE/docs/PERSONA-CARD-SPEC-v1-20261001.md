## 0. 定位：为什么需要这一份

现有 [`AUTHORING-GUIDELINES.zh-CN.md`](../tools/persona-workbench/AUTHORING-GUIDELINES.zh-CN.md)（v4.3）已经很成熟——W1–W10 管取证与归属，M1–M9 管表达质量，O1–O6 管观测，另有盲评协议。**本规范不取代它，只补它够不到的那一层。**

理由是一次实测对比：

| 判据形态 | 对 279 张违规卡的结果 |
|---|---|
| **schema（代数）**：`additionalProperties:false` + 枚举 + pattern | **279/279 抓出**，一个不漏 |
| **指南（散文）**：M1–M9 讲「什么算好例子」 | **一条也没抓住** |

**所以本规范的唯一设计目标：把每一条规则变成"一个可计算的量 + 一个阈值 + 一个门禁入口"。**
凡是写不出量、写不出阈值的条款，**不进本规范**（留在指南里当原则）。

### 三条元规则

- **R0-1 可计算**：每条规则必须给出指标定义、阈值、判定脚本。给不出就不写。
- **R0-2 阈值由基线标定**：一律以「老卡 76 张（已入库、经人工过审）」的实测分布定线，**不得拍脑袋**。本文所有阈值都附老卡实测值。
- **R0-3 先告警后判死**：新规则先以**告警**上线，观察一批之后才收紧为硬门。避免一次把好卡判死。

### 基线标定表（本规范全部阈值的依据）

用 `py -3.11` 实测 355 张卡，按 git 跟踪状态分组：

| 指标 | 老卡 76（好） | 新卡 279（坏） | 判别力 |
|---|---|---|---|
| 不同标签集合数 | **72** | **5** | ★★★ |
| 最大同标签集合组 | 4 张（5%） | **235 张（84%）** | ★★★ |
| 只出现一次的标签集合 | 70 | **0** | ★★★ |
| 每卡 tag 数取值分布 | `{4:2, 5:4, 6:29, 7:10, 8:11, 9:7, 10:8, 11:5}` | **`{5: 279}`** | ★★★ |
| 类目覆盖分布 | `{3:10, 4:66}` | `{4: 279}` | ★（只作下限） |
| 单 tag 最大占比 | 61% | **85%**（4 个并列 84%） | ★★ |
| **跨卡样板句负载**（见 B1） | **mean 0.000 / max 0.000 / 100% 卡为零** | **mean 0.513 / median 0.600 / 仅 6% 为零** | ★★★ |
| 未注册 tag 卡数 | **0 / 76** | **276 / 279** | ★★★ |
| 叙事正文字数 mean | 735 | 272 | ★★ |

**"跨卡样板句负载"是本次发现的最强判别量：老卡 76 张全部为 0，新卡平均 0.513。二值分离。**

## 1. T 系列 · 标签层（本规范的核心，现有指南完全未覆盖）

> 背景：实测新卡 279 张里 **235 张声明了完全相同的性格**——
> `trait.pragmatic, trait.ruthless, expression.cold, behavior.calculating, trigger.family_interest`。
> 而 W7 规定**只有三样东西进运行时：叙述文本 / 边界 / tags**。新卡的叙述文本是逐卡独特的，
> 但**边界字段与 tags 是批量共用的** ⇒ 三样里两样是常数。
> ⇒ **这不是"词汇缺口"，是"按批次盖章"。** 把缺的 tag 注册进去，只会让 235 个一模一样的人格通过所有门禁。

### T1 · 标签集合必须逐卡有别 ★核心

- **指标**：同一批内，出现次数最多的那个「标签集合」的卡数 / 占比
- **阈值**：硬门 **≤ 4 张且 ≤ 5%**；告警 **> 2 张**
- **基线**：老卡 4 张（5%）✅ ／ 新卡 235 张（84%）❌
- **理由**：老卡 76 张有 72 种不同组合——**标签层在真正干活**。

### T2 · 每卡 tag 数必须有分布，不得是常数

- **指标**：全批「每卡 tag 数」的不同取值个数，以及任一取值的最大占比
- **阈值**：硬门 **取值数 ≥ 4 且任一取值 ≤ 50%**；告警 取值数 ≤ 3
- **基线**：老卡 8 种取值、最大 29/76 = 38% ✅ ／ 新卡 1 种取值、100% ❌
- **理由**：**279 张全部恰好 5 个 tag** —— 这是机器盖章的指纹。

### T3 · 类目覆盖下限

- **指标**：每张卡覆盖的 tag 类目数（`trait` / `expression` / `behavior` / `trigger`）
- **阈值**：硬门 **≥ 3 个类目**
- **基线**：老卡 `{3:10, 4:66}` ✅ ／ 新卡 `{4:279}` ✅
- 说明：两批都通过，**只作下限，不用于判别**。保留是因为"只有 2 个类目"的卡信息量明显不足。

### T4 · 单 tag 全局占比上限

- **指标**：任一 tag 在全集的出现卡数占比
- **阈值**：硬门 **≤ 70%**；告警 **> 50%**
- **基线**：老卡最大 61%（`trait.pragmatic`）✅ ／ 新卡最大 85% ❌
- ⚠️ **已知既有弱点**：`trait.pragmatic` 在老卡里也占 61%、全集占 80%。它事实上接近"全员默认"，作为区分项价值很低。**这是老卡就有的问题**，应单独处置（提高门槛逼出替代 tag），**不要**用本规则把老卡判死。

### T5 · 未注册 tag 必须为 0

- **指标**：`tags[].id` 不在 `tag_registry.json` 中的卡数
- **阈值**：硬门 **= 0**
- **基线**：老卡 0/76 ✅ ／ 新卡 276/279 ❌
- 说明：这是 W7-a 的**可计算化**。W7-a 已说明后果（整卡降级 `IDENTITY_ONLY`）与分流顺序（改卡 / 补注册表 / 删卡），本规范只给它一个判据。
- 运行机制出处：`AWAKE/src/PersonaDslGenerator.cs:123,127,132`（`!expanded` → `BuildLegacyFallback` → `IDENTITY_ONLY`）。

### T6 · 同义 tag 不得跨类目重复

- **指标**：语义同义的两个 tag 落在不同类目
- **阈值**：硬门 **= 0**（同义只能存在一个类目）
- **实测违规**：`trait.warm` ↔ 已注册的 `expression.warm`；`trait.compassionate` ↔ `trait.kind`；`expression.reserved` ↔ `trait.reserved`；`trigger.tradition` ↔ `trait.traditional`；`behavior.loyal` ↔ `trait.loyal`
- **做法**：维护一张 **alias 表**（`同义 tag → 规范 tag`），门禁按表判；**alias 表本身进版本控制**，不允许各调用点各写一套（对齐 `AGENTS.md:92` 对权限字符串的要求）。

## 2. B 系列 · 边界字段反模板（现有指南只到 O5 告警）

> 背景：现有 M1–M9 几乎全部针对 `selfClaimExamples`；跨卡印章只有 **O5 告警（不判死）**。
> 而实测最严重的重复恰好落在**另一个盲区**：`selfClaimRules` 与 `realSelfBehaviors`，
> **而这两个字段会进 prompt**（W7 的"边界"）。

实测逐字串（`selfClaimRules` + `realSelfBehaviors`）：

| 卡数 | 逐字串 |
|---|---|
| **247** | `与族中上下论事，先听后断，不独断而行` |
| **151** | `在外人面前少谈家事，多谈职守` |
| **111** | `提及家眷时语气温和，不吝赞许` |
| 13–15 × 24 个变体 | 骨架 `逢年节必亲省{X}的存用，算无遗策`（X 填地名） |

### B1 · 跨卡样板句负载 ★核心判据

- **指标**：对某张卡，统计 `selfClaimRules` + `realSelfBehaviors` 的句子（按 `。！？；\n` 切分、去空白、长度 ≥6），其中**出现在 ≥10 张其它卡上**的句子占比
- **阈值**：硬门 **≤ 5%**；告警 **> 0**
- **基线**：老卡 **mean 0.000 / median 0.000 / max 0.000 / 76 张全部为 0** ✅ ／ 新卡 **mean 0.513 / median 0.600 / 仅 6% 为零** ❌
- **这是全规范判别力最强的一条。** 老卡是完美的 0，新卡过半。

### B2 · 单句跨卡出现上限

- **指标**：任一句子在多少张卡上出现
- **阈值**：硬门 **≤ 5 张**；告警 **> 3 张**
- **基线**：老卡 **0 句**达到 ≥10 张 ✅ ／ 新卡 **20 句**，最高 **247 张** ❌

### B3 · 骨架句覆盖上限

- **指标**：去掉变量后 head/tail 相同的"骨架句"覆盖多少张卡
- **阈值**：硬门 **≤ 3 张**；告警 **> 2 张**
- **基线**：新卡 24 个骨架变体各覆盖 13–15 张 ❌

### B4 · 字段形状必须与 schema 一致

- **指标**：`realSelfBehaviors` 是数组而非 `{}`；`selfClaimRules` 非空
- **阈值**：硬门 **违规 = 0**
- **实测**：8 张卡 `realSelfBehaviors` 为 `{}`（物化器在源字段缺失时输出空对象）❌

## 4. I 系列 · 身份与模式（现有指南的缺口）

> 审计确认：**指南全文没有 `id` 模式的任何条款**，而 279 张卡正是踩这一条。

### I1 · `id` 必须符合 authoring schema 的 pattern

- **判据**（引自 `tools/persona-workbench/contracts/persona-workbench.character.v1.schema.json:13`）：
  ```
  ^calradia\.[a-z0-9_]+(\.[a-z0-9_]+){1,2}$
  ```
  ⇒ `calradia` 之后 **2–3 段、全小写**
- **阈值**：硬门 **违规 = 0**
- **实测违规 279 张**：写成 `calradia.Ulman.khuzait`（**大写名段**）❌
- 正确形：`calradia.ulbos.empire.south`

### I2 · `characterId` 必须符合 definition schema 的 pattern

- **判据**（`AWAKE/docs/persona-contract/awake.persona.definition.v1.schema.json:80`）：
  ```
  ^awake:[a-z][a-z0-9_]*:[a-z0-9_.]+$
  ```
- **实测违规 76/76**：写的是 `lord_1_14` ❌

### I3 · `status` 与 `scope` 取值合法

- `status ∈ {approved, draft, disabled}`；`scope ∈ {character, identity, role, culture, global}`
- **实测**：355 张 persona + 76 张 definition **全部 `draft`**，`approved`/`disabled` 各 0 —— 与路线图「审批 76 张全 draft」一致。

## 5. F 系列 · 物化新鲜度（新发现，任何文档未记录）

## 6. S 系列 · 规范与 schema 的冲突（**需裁定，不擅自选边**）

实测三处，**两边都保留原文，由甲方裁定**：

| # | 冲突 | 出处 |
|---|---|---|
| **S1** | 指南正文要求 `core` 多段，而 definition schema 的文本字段 pattern 是 `^[^\u0000-\u001F\u007F]*$`，**禁换行** ⇒ 多段 `core` 在 schema 下不可能合法 | schema L93/97/102；指南 M 系列 |

**处置建议**：S1 二选一（放宽 schema 允许 `\n`／改指南允许单段）；S2/S3 先确认「运行时是否真的按 schema 校验」，若只是设计期契约，则在文档里明确标注"未强制"。
