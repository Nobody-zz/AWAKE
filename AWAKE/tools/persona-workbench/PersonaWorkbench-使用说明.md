# Persona Workbench Free Preview 使用说明

版本：AI 批量闭环测试版（2026-08-30）  
适用系统：Windows 10 / Windows 11（64 位）  
软件性质：本机独立人格作者工具 / 免费预览版

---

## 1. 这是什么

Persona Workbench 用于把人物设想整理成结构化 Persona 数据和 canonical Persona DSL。

它目前提供两条互相独立的 AI 辅助链路：

1. **扩展人物形象**：把几句简短描述扩充成较完整、可继续编辑的人物文本。
2. **将确认文本转换为 DSL**：把你已经确认过的自然语言人物描述转换成结构化 Persona 字段、人格轴和 DSL 草稿。

你也可以完全不使用 AI，手动填写人物资料、调节人格轴并生成 DSL 预览。

本工具是独立程序：

- 不需要启动《骑马与砍杀 II：霸主》；
- 不修改游戏目录；
- 不自动调用任何 AI Provider；
- 不会自动保存、覆盖或批准 Persona；
- 只监听本机地址 `127.0.0.1:51337`。

> **预览版说明**：当前版本适合制作、试验和评估 Persona。生成内容必须由用户自行检查；AI 草稿不等于正式角色设定。

## 2. 运行要求

### 必需

- Windows 10 或 Windows 11，64 位；
- 一个现代浏览器。程序会优先使用 Microsoft Edge 的独立应用窗口，也可回退到默认浏览器。

发布包已内置所需的 .NET 与 ASP.NET Core 运行时，普通用户无需另行安装。

### 仅在使用 AI 时需要

任选一种兼容 OpenAI Chat Completions 格式的 Provider：

- 本机 Provider，例如 Ollama、LM Studio 或其他本机兼容服务；
- 云端 HTTPS Provider，以及对应的模型权限与 API Key。

工作台本身不附带模型、云端额度或 API Key。

## 3. 解压与启动

1. 删除旧版解压目录，将 ZIP **完整解压到一个新的空文件夹**。不要覆盖 r44 及更早版本的旧目录，也不要直接在压缩软件内部运行 EXE。
2. 双击 `PersonaWorkbench.Launcher.exe`。
3. 在蓝色启动器中点击绿色按钮：
   - 服务未运行时显示 **“启动并打开 Persona Workbench”**；
   - 服务已运行时显示 **“打开 Persona Workbench”**。
4. 浏览器或 Edge 独立窗口会打开工作台页面。

启动器还提供：

- **仅打开页面**：服务已运行时重新打开页面；
- **停止后台服务**：关闭本机工作台服务；桌面也提供“Persona Workbench - 停止”快捷方式；
- **打开程序目录**：打开当前解压目录；
- **关闭启动器**：只关闭启动器窗口，不停止工作台服务。

> 如果你只是关掉浏览器或启动器，后台服务可能仍在运行。需要彻底退出时，请重新打开启动器并点击“停止后台服务”。

## 4. 三分钟快速开始：完全不用 AI

这是最稳定、最容易理解的使用方式。

1. 启动工作台。
2. 在 **“2 · 确认或修改角色”** 中填写：
   - **本地工作区**：Persona 文件保存目录，例如 `D:\PersonaWorkbench\MyCharacters`；
   - **文件名**：必须以 `.persona.json` 结尾，例如 `lin.persona.json`；
   - **稳定 ID**：角色的长期唯一标识，例如 `free.generated.lin`；
   - **显示名**：玩家看到的角色名；
   - **核心人格**：角色最稳定、最重要的人格描述；
   - **身份事实**：不会随当前场景轻易变化的身份信息，可留空。
3. 按需要调节五组内容：
   - 整体印象；
   - 说话方式；
   - 做事方式；
   - 压力与冲突反应；
   - 价值排序与承诺机制。
4. 点击 **“生成 DSL 预览”**。
5. 检查页面底部生成的 Persona DSL。
6. 确认需要保存时点击 **“保存草稿”**；最终人工确认后再点击 **“批准当前 Persona”**。

> “生成 DSL 预览”是本地确定性整理，不调用 AI。它会把已经填写的字段按规范顺序输出，不会替你补写缺失设定。

## 5. 推荐流程：从少量提示词开始

### 第一步：输入人物描述

在页面最上方输入几句人物印象，例如：

> 二十岁，身材娇小，涉世未深，是个坚强的女战士；对敌人毫不仁慈，面对恋爱却手足无措。

### 第二步：可选——用 AI 扩展人物形象

需要控制扩写方向时，先展开 **“扩写方向与关键词（可选）”**：

- **扩写方向**：用一句话说明希望重点深化什么；
- **扩写重心**：在均衡、人格与行为、身份与经历、关系与情感、外貌与表现之间选择；
- **重点关键词**：最多添加 12 个关键词，并为每个关键词选择轻微、适中或重点；
- **避免或弱化**：用逗号或换行列出不希望本次扩写占用篇幅的主题。

这些内容只是本次扩写的控制参数，不是人物事实，不会自动写入 Persona、DSL、标签或审核状态。留空时仍按均衡方式扩写。

点击 **“扩展人物形象”**。

成功后，结果只会进入 **“AI 扩充结果”** 文本框：

- 不会自动改写 Persona；
- 不会自动设置人格轴；
- 不会自动生成或批准文件；
- 你可以先修改、删减或重写。

确认文本后有两种选择：

- **将扩充结果填入核心人格**：只把文本放入核心人格，之后由你手动调节其他字段；
- **将确认文本转换为 DSL**：再次调用 AI，把确认文本转换成结构化 Persona 草稿与 canonical DSL。

### 第三步：人工复核

重点检查：

- AI 是否擅自添加了原描述没有支持的身份、经历或关系；
- 人格轴方向是否符合你的原意；
- 核心人格和身份事实是否混在一起；
- 角色是否出现自相矛盾或过度夸张；
- 显示名、稳定 ID 和文件名是否正确。

AI 转换成功后仍是 **草稿**。只有你点击“批准当前 Persona”才会写入 approved 状态。

## 6. AI 批量制作：资料直接变成多条草稿

这是给“大批量制作”准备的入口。你负责提供资料和最后审阅，工作台负责本地整理、逐条调用 AI 并保留每条结果。

### 6.1 四步操作

1. 在页面顶部 **“AI 批量制作”** 中粘贴资料，或选择多个 `.txt` / `.md` 文件。
2. 点击 **“1. 读取资料”**。这一步只在本机读取，不调用 AI，也不会上传资料。
3. 点击 **“2. 整理资料并分段”**。检查每个资料段：可以取消勾选、改标题、修改正文；不合适的段落不要提交。
4. 点击 **“3. 下一步：进入 AI 批量制作”**。工作台按资料顺序逐条制作，不会自动保存、批准或覆盖当前编辑器。

### 6.2 制作过程与结果

- 页面会显示 **已完成 / 总数**、成功数、失败数和当前正在处理的资料段。
- 一条资料失败不会抹掉其他成功结果；失败卡片会保留原资料和错误说明。
- 批量制作期间可以点击 **“停止批量制作”**。当前正在等待的 Provider 请求结束后，不会启动下一条。
- 成功卡片点击 **“载入当前编辑器”** 后才会进入编辑区；仍需人工检查，点击“保存草稿”才会写文件。
- **“导出批量结果”** 会下载本次页面结果，包含来源资料、草稿和 DSL，不包含 API Key 或会话密钥。

### 6.3 一次处理多少资料

- 一批最多 32 段资料；单段正文最多约 24 KB；整批正文最多约 256 KB。
- 资料很多时，先按主题或人物拆成几批，通常比把整本资料一次提交更容易检查。
- 刷新页面后批量结果不会假装持久化；需要保留时，请先导出 JSON。

### 6.4 如果“下一步”没有出现

请按下面顺序检查：

1. 是否已经点击“整理资料并分段”；
2. 分段卡片中是否至少保留一段且正文不为空；
3. “AI 设置”中是否填写了接口地址和模型 ID；
4. 云端 Provider 是否已经设置本次会话 Key，并确认云端地址；
5. 是否仍然打开着旧页面。关闭旧页面，从当前包目录的启动器重新打开。

## 7. AI Provider 设置

展开页面中的 **“AI 设置（高级）”**。

### 7.1 本机 Provider

适用于 Ollama、LM Studio 等本机服务。

操作顺序：

1. 选择 **“本机 Provider”**；
2. 填写完整的 Chat Completions 地址；
3. 填写服务端实际存在的模型 ID；
4. 本机服务通常不用填写 Key；
5. 点击“扩展人物形象”或“将确认文本转换为 DSL”。

Ollama 常用示例：

- 接口地址：`http://127.0.0.1:11434/v1/chat/completions`
- 模型 ID：填写 `ollama list` 中实际安装的模型名，例如 `gpt-oss:20b`

注意：本机 Provider 必须已经启动，模型必须已经安装。工作台不会替你下载或启动模型。

### 7.2 云端 Provider

云端地址必须使用 HTTPS。

操作顺序必须完整执行：

1. 选择 **“云端 Provider”**；
2. 填写完整 Chat Completions 接口地址；
3. 填写 Provider 实际开通的模型 ID；
4. 将 API Key 填入“本次会话 API Key”；
5. 点击 **“设置本次会话 Key”**；
6. 点击 **“我确认使用这个云端地址”**；
7. 再点击“扩展人物形象”或“将确认文本转换为 DSL”。

DeepSeek OpenAI 兼容接口示例：

- 接口地址：`https://api.deepseek.com/chat/completions`
- 模型 ID：请填写你的 DeepSeek 账户当前实际支持的 API 模型 ID，不要把网页产品名称或宣传名称当作模型 ID。

### 7.3 Key 与隐私

- Key 只提交给当前本机工作台会话；
- 设置成功后，页面输入框会被清空；
- Key 不写入 Persona 文件；
- Key 不写入浏览器存储；
- 停止后台服务后，会话 Key 不再可用；
- 分享压缩包、Persona 文件或 DSL 时，不应包含你的 Key。

不要将自己的 API Key 发给其他人，也不要把带 Key 的截图公开发布。

## 8. 两个 AI 按钮到底有什么区别

### 扩展人物形象

输入：少量人物描述。  
输出：较完整的自然语言人物文本。  
用途：帮你补充人物形象、矛盾、表达习惯和行为倾向。  
不会做：不会直接生成正式 Persona，不会自动填表，不会自动保存。

### 将确认文本转换为 DSL

输入：你已经阅读、修改并确认过的人物文本。  
输出：结构化 Persona 草稿、人格轴、受限标签和 canonical DSL。  
用途：把自然语言设定变成程序可读格式。  
不会做：不会自动批准，不会覆盖失败前的表单和 DSL。

### 生成 DSL 预览

输入：当前表单中已经存在的内容。  
输出：本地确定性 DSL 预览。  
用途：检查最终结构和导出格式。  
**不会调用 AI，也不会扩充人物。**

### 生成 AWAKE authoring-v2 预览

这是当前开发批次提供的迁移预览，不是旧版 DSL 的替代按钮。

输入：当前表单快照，以及页面中单独存在的 AI 扩充结果（如果有）。  
输出：`awake.persona.authoring.v2` canonical JSON、迁移警告和校验诊断。  
用途：检查 Workbench v1 数据将如何进入后续 AWAKE 作者层。

- AI 扩充结果仍与“核心人格”分开；只有当前单独的扩充文本会进入 JSON 的 `source.expandedText`；
- `Tags`、人格面板和人格轴只按 AWAKE 权威 crosswalk 转换；不能映射的旧值会保留在迁移数据并给出警告，不会伪装成运行时标签；
- 没有游戏选择 sidecar 时，工具不会根据显示名、文件名或稳定 ID 猜测游戏内角色身份；
- 预览和下载都是显式操作，不会自动保存、批准、写入 AWAKE 或修改游戏文件；
- 下载的是预览返回的 canonical UTF-8 字节，与页面显示的 JSON 和 SHA-256 一致；
- 该 JSON 仍是草稿迁移材料，不是 AWAKE 批准文件、运行时定义、游戏可直接加载文件或游戏内实时角色卡。

如果 authoring-v2 预览失败，页面只显示诊断，不会覆盖现有表单、AI 扩充结果、DSL 或已保存草稿。

## 9. 人格字段怎么填写

### 稳定 ID

用于长期识别角色，不应随显示名改变。建议：

- 使用英文小写、数字和点号；
- 同一角色始终使用同一个 ID；
- 示例：`free.generated.lin`、`author.pack.lord.rhagaea`。

### 核心人格

写角色长期稳定的性格骨架，而不是当前场景：

- 推荐：谨慎自持，不轻易交出真实意图；对自己人有强烈保护欲，但受到公开羞辱时会直接反击。
- 不推荐：她现在站在酒馆里，非常生气。

### 身份事实

写相对稳定的身份信息，例如出身、职业、长期阵营身份。会变化的当前地点、临时情绪和一次性任务不应写成硬事实。

### 五组人格轴

数值不是善恶评价，而是两种倾向之间的程度：

- **未设定**：不写入该轴；
- **平衡**：角色会视情境采用两边；
- **略偏**：存在稳定倾向，但容易受场景影响；
- **强烈**：倾向明显，通常需要较强刺激才会偏离。

不要为了“填满”而设置所有轴。没有可靠设定的项目保持未设定，通常比胡乱补全更好。

### 压力与冲突反应

描述角色偏离常态时如何反应，例如面对羞辱、威胁、失败或亲近者受伤。这里不是日常动作清单。

### 价值与承诺

用于描述角色如何承诺、优先保护什么、在何种代价下才会破例。不要把它写成简单的“好人/坏人”标签。

## 10. 保存、打开与批准

### 本地工作区

填写一个你拥有读写权限的本地目录。目录不存在时，工作台会尝试创建。

建议单独建立目录，例如：

`D:\PersonaWorkbench\Characters`

不要选择系统目录、浏览器目录或正在被云盘冲突处理的复杂目录。

### 文件名

- 必须是单个文件名，不能包含子目录；
- 必须以 `.persona.json` 结尾；
- 示例：`lin.persona.json`。

### 保存草稿

将当前 Persona 以 `draft` 状态保存。后续可以继续编辑。

### 批准当前 Persona

将当前 Persona 以 `approved` 状态保存，表示你已进行人工检查。批准后继续编辑会使其重新回到草稿状态，需要再次批准。

### 历史与冲突保护

- 覆盖已有文件前，工作台会在工作区的 `.history` 中保存历史版本；
- 如果文件被其他程序或另一个会话修改，工作台不会直接覆盖，而会在 `.conflicts` 中保留冲突草稿；
- 未完成写入会使用 `.pending` 和提交日志进行恢复；
- 同一工作区在同一时刻只允许一个写入操作；并发写入会被拒绝。

这些目录由程序维护，不建议手动删除正在使用的恢复文件。

## 11. 常见问题与排查

### 双击后没有出现工作台

1. 确认已经完整解压 ZIP；
2. 直接双击 `PersonaWorkbench.Launcher.exe`，不要先运行 VBS 或 PowerShell；
3. 查看启动器状态文字；
4. 点击“打开程序目录”，先检查始终有内容的 `.runtime\startup.log`；Web 错误再看 `.runtime\server.stderr.log`；
5. 如果 `.runtime\startup.log` 不存在，说明程序目录不可写或安全软件在脚本执行前拦截了启动器，请重新完整解压到桌面或文档目录；
6. 检查安全软件是否阻止本机 EXE、PowerShell 或端口 51337；如果服务立即退出，将日志发给发布者排查。

### 提示端口 51337 被占用

- 先用旧工作台启动器点击“停止后台服务”；
- 关闭重复打开的旧版本；
- 不要同时运行多个 Persona Workbench 解压目录。

### 页面提示“本机会话未就绪”

不要直接收藏并长期复用旧的 `127.0.0.1:51337` 页面。关闭旧页面，从当前版本启动器重新打开工作台，以获得新的本机会话。

### 云端端点确认失败

检查：

- 地址是否是完整 HTTPS Chat Completions 地址；
- 地址中是否误带空格、引号或 API Key；
- 是否把网页聊天地址当成 API 地址；
- 域名解析是否正常；
- 云端地址是否解析到了内网地址。出于安全原因，云端域名解析到私有地址时会被拒绝。

### provider.session_key_missing

当前会话没有 Key。重新填写 Key并点击“设置本次会话 Key”。重启后台服务后需要重新设置。

### provider.http_400

请求已到达 Provider，但请求参数、模型 ID、账户权限或 Provider 兼容格式有问题。优先检查模型 ID，而不是反复重新设置同一个 Key。

### 429 / provider.cooldown_active

Provider 正在限流。工作台不会自动连续重试，并会进入短暂冷却。等待冷却结束，只重试一次；同时检查额度、并发和其他正在使用同一 Key 的程序。

### provider.transport_error 或 provider.timeout

检查 Provider 是否启动、地址和端口是否正确、防火墙是否拦截、云端服务是否可访问。失败时当前表单内容不会被覆盖。

### provider.persona_structure_empty

AI 只返回了人物摘要，没有足够的人格轴、标签或行为结构。把确认文本写得更明确，例如补充：

- 对风险的态度；
- 说话方式；
- 信任与谈条件方式；
- 面对羞辱或威胁的反应；
- 承诺和价值排序。

### 转换结果少于预期

工作台会删除没有原文证据支持的字段，而不是让 AI 凭空补全。请在确认文本中明确写出你希望保留的特征，然后重新转换。

### 保存失败或 workspace.locked

- 关闭其他正在写同一工作区的页面或进程；
- 确认目录有写入权限；
- 避免两个工作台版本同时操作同一目录；
- 如果发生外部修改，检查 `.conflicts` 中的冲突草稿。

## 12. 安全与数据边界

- Web 服务仅接受本机回环请求，并固定使用 `127.0.0.1:51337`；
- 本机 Provider 只允许 `localhost` 或回环 IP 的 HTTP 地址；
- 非本机 Provider 必须使用 HTTPS；
- Provider 重定向会被拒绝；
- 云端域名在请求前会检查解析地址，避免访问私有内网地址；
- 请求有超时、响应大小和并发限制；
- 429 不会触发无限自动重试；
- Provider 失败、取消或格式不合法时，不会把失败结果伪装成本地成功，也不会覆盖现有表单和 DSL；
- 只有用户主动点击保存或批准，才会写入 Persona 文件。

使用云端 Provider 时，你主动提交的人物描述会发送给对应 Provider。请自行遵守 Provider 的服务条款、隐私政策和内容规则。

## 15. 文件校验

`package-free-preview.ps1` 会在目录包同级生成 `PersonaWorkbench-FreePreview-*.zip` 和对应的 `.zip.sha256` 文件。ZIP 是自包含发布物；目录包仅用于本地回读和审计，不要把 ZIP 内容覆盖到旧目录。

用户可在 PowerShell 中执行：

`Get-FileHash -Algorithm SHA256 .\PersonaWorkbench-FreePreview-*.zip`

将结果与同名 `.zip.sha256` 文件中的哈希逐字比较。发布者也可以直接公布该 sidecar 文件中的哈希；ZIP 的哈希不能写进 ZIP 自身，因为修改说明书会再次改变整个压缩包的哈希。

包内的 `PACKAGE-MANIFEST.sha256.txt` 用于核对解压后的内部文件。下载来源不明、ZIP 哈希不一致或 Manifest 校验失败时，请不要运行。
