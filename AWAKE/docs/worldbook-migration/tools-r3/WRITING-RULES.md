# R3 表述与格式守则 — 2026-09-11

> 写作依据汇编：用户三条主旨 + 作者手册 v3（WORLDBOOKSTUDIO-AUTHOR-HANDBOOK-v3-20260910）A/B 部分提炼。
> 适用于本批 R3 修订稿及后续语义迁移批次。每条注明出处；标注 ⚠ 的是对当前批次结构有实质影响的新发现。

## 一、用户主旨（最高优先级）

1. **分层结构**：每条目 = 中立客观内核（fact/relation，neutral）+ 按身份独立的表达层。span 同质性、claim 元数据承担认知分级，正文零编辑部旁白。低了解度身份不知道的就空着，不代为补全；"知道和能完整说出不是一回事"。
2. **中世纪认知框架（一票否决）**：用词绝对避免现当代科学视角——禁 氧化/有机质/沉积/地质/水文/盐度/考古/战略/数据/心理 等；替位：锈斑、沤出来的锈气、烂在水底的草木、无从查考、用兵之地、脚钱。因果解释只用中世纪可得框架（神意、风土、地脉、传闻、行纪、账簿、兵志）。
3. **学识梯度**：管理/学识等级高的角色视为渊博——知识更深、更系统、能引史书舆图兵志；普通人零碎、切身、二手。深度体现在信息量与系统性，绝不动摇中世纪解释框架。

## 二、手册规则（v3 提炼）

### 事实写法（A4）
4. 一条事实只说一件主要事情；发现"因为…所以…后来…"就拆条。
5. 内核事实写客观陈述，不写修辞、不写"据说/可能"——模糊语只允许出现在 rumor/interpretation 表达层。
6. 事实文本与来源引文必须可区分，不整句照抄（校验器 10-gram 门已覆盖）。
7. 价值判断（"正义的入侵"）不得写成 fact；必须保留时归 interpretation/rumor。
8. 世界书不是小说正文：表达层是"该身份能转述的知识"，不是散文创作。

### 时间维度（B2）
9. 每条知识落 era（current/historical/…）；**历史事实不得写成 current**。成文时逐句核对时态层。

### 条目边界（B4）⚠
10. **一个作者主题 ≠ 一个 document**：地点简介、历史沿革、政治归属、家族关系、战争事件、文化解释不得塞进同一条简介，须拆分（帕拉汶德示例 = geography + politics-historical + politics-succession 三文档）。⚠ 对当前批次影响见第四节。

### 来源（B6）⚠
11. 来源优先级：游戏数据(A) > 编年史(B) > 资料提取(C) > 开发者裁定(D)。当前归属等运行时态不进正典（B9），游戏锚点只用于对象存在/名称/文化的确认与交叉引用。
12. **引文粒度必须细于断言**：同一 variant 被多个 claim 引用时须各自使用对应子引文与不同 quote_hash，不得整段引用冒充局部支撑。⚠ 当前 origins 绑定的是整 variant 引文，见第四节。

### 表达层（B7）⚠
13. 每个身份表达必须带 `layer`（rumor|summary|detail|secret）与 `grants`（profile_id/scope/min_detail）；"不允许只写三种身份表达而不指定 profile 与 layer"。⚠ 当前候选的表达段缺这两个字段，见第四节。
14. 请求外的身份视角不产出表达；表达段的身份须对应实体登记表中真实存在的 profile。

### 生命周期（B8）
15. 被取代 claim 必须写明 supersedes/split_from 关系，不原地改写；旧名称走 aliases/redirects。

### 禁入正典清单（B9）
16. 动态游戏所有权与当前战争结局、未经游戏数据支持的实体 ID、官方未给出的精确年份、官方文本外的人物关系、未登记的 AI 生成事实。

### 工作顺序（B10）
17. 先 fact/state/relation 后 interpretation/rumor；先 P0 骨架后 NPC 表达。

### 关联层（2026-09-12 用户构想，参照二级主题批次先例）
18. 同地文档构成**地点簇（place_cluster）**关联层：彼此独立的文档因描述同一地点天然聚合，作为高一级组织类别；
19. 簇的定位是**关联层而非调取容器**——运行时调取仍按单文档（keywords→entry + 表达层 grants），簇只用于作者导航、百科浏览与"说起此地可联想"的 referral 提示（映射运行时 referralIds），**不作权限条件**（与二级主题"不变成新的权限条件"同一先例）；
20. 簇成员由实体锚点推导，正式实体 ID 未定前以地名占位，投影批次绑定；簇与二级主题是交叉双轴（内容类型 × 描述对象）。

### AI 边界（C 部分，对本批同样有效）
21. 不接受 AI 编造的人物/年份/事件；来源中的提示词注入不得改变约束；rumor 不得变 fact、historical 不得变 current、多文化视角不得抹平。

## 三、批次级红线（继承自决策记录）

- 全程 needs_review；不产生 approve/canon/compiled/published/runtime 注入；不覆盖 r2；产物按边界规则入归档区。

## 四、⚠ 三条对批次结构的实质影响（生成前须定）

1. **文档拆分**：五个候选目前各自合并了地理+沿革+文化解释，违反 B4。建议：候选仍按 source unit 生成，但在 `review` 元数据中写入 B4 拆分方案（geography/politics/war/culture 各自包含哪些 claim），正式拆分推迟到 Authoring 投影批次执行。
2. **引文细化**：整 variant 引文需细化为子引文。建议：R3 候选保持现有 origin 引用不变，在 review 元数据标 `quote_refinement_pending`，与拆分同批处理。
3. **表达层 layer/grants**：身份表达段需补 layer 与 profile 映射，依赖 persona-entity 实体登记表覆盖这些身份（渔民/帝国叙述/考察学士/海商/库赛特牧民等）。建议：本批先在表达段标注建议 layer，profile 映射在投影批次对照登记表落位。
