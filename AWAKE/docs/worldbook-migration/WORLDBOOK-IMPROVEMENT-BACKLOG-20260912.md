## 一句话判断

**现在不是"缺功能"，而是三层都停在"通电前"的状态：**

| 层 | 完成度 | 证据 |
|---|---|---|
| 机制（机器） | **已实现** | 权限契约、分层、转介、编译、导出、发布全都有 |
| 内容（人写的） | **走了约 1/4** | secret/unknown 0 条、denies 全空、三维度 0 用、身份只用 6/12 |
| 生产链 | **0% —— 从没跑通过** | `compiled/` 与 `export/` 实测全空 |

所以第一优先级不是"多写内容"，而是**先把电通上**。

## 路线选择：先完善编辑器，还是先创作内容？

（Max 2026-09-12 提问）

### 结论：**先创作内容 + 调整知识结构**，但前置一件极小的编辑器工作——**把编译打通**。

### 为什么不是先完善编辑器

1. **编辑器已经够用了**——12 档就是它造出来的：能建档、能校验、能保存、能预览。唯一致命的只有**编译从没跑通**（C16）。
2. **没有内容，你不知道编辑器该改什么。** 工具要被真实内容撞才有改进方向。**C16 就是被内容工作（查锚点）撞出来的**——反过来，坐在工具里凭空想，想不出该改哪里。
3. **"完善编辑器"是个无底洞。** AI 体验、批量流程、UI 打磨……可以一直磨下去，容易变成"工具越做越好，内容永远没有"。
4. 那些已知的坑（本机 Worker 没配、提示词超长、批量卡第二步）**多半是外部依赖**，不是编辑器代码的问题，光在编辑器里使劲也没用。

### 为什么选先创作内容

1. **内容本身就是发现结构问题的引擎**：写 → 撞出问题 → 反推工具/结构该怎么改 → 下一轮写得更顺。这是正循环。
2. **现在的样本太单一，结构问题还没暴露**：12 档只覆盖 **4/5 个 domain**——

   | domain | 档数 |
   |---|---|
   | geography | 5 |
   | culture | 4 |
   | politics | 2 |
   | economy | 1 |
   | **war** | **0** |

   `war` 一档没有，`economy` 只有 1 档。这种分布下，说"知识结构对不对"是没有依据的。**要验结构，先得让样本够杂。**

3. 内容创作的主力路径目前是**编年史 → 投影 → 建档**（W1–W4 已验证可行），不完全依赖 AI 批量，所以编辑器的 AI 坑暂时不阻塞。

### 诚实的风险

- **风险**：编译修完可能还有别的坑，内容会积压在"能写不能上"的状态。
- **对冲**：所以前置动作不是"完善编辑器"，而是**只做一件事——让编译跑通并试跑一次**，确认"写了能上"。**做完立刻转内容**，其余编辑器改进一律推迟，等被内容撞出来再做。

### 建议的启动顺序

```
第 0 步（1 次，很小）：修 C16 → 试跑一次编译 → 确认"写了能进游戏"
第 1 步：补多样本 —— 至少把 war 和 economy 补上，让 5 个 domain 都有货
第 2 步：挑 2–3 个地点做完整样本，把门控走一遍（secret / denies / 三维度）
第 3 步：回头看 —— 结构哪里别扭、工具哪里碍事，此时才该动编辑器
第 4 步：才谈扩量与 AI 批量
```

**判断依据一句话**：**工具是为内容服务的；内容不够多的时候改工具，是在没有靶子的情况下练枪。**

## P0 · 不做，后面全是纸面

### 1. 让编译真正跑通一次

- **现状**：Studio 的 `compiled/` 与 `export/WorldbookV2/` **全空**，12 档从未编译成功过。已知硬错误是 **C16**（10 档含 `entity.lore.*`，编译器只认 hero/clan/settlement，直接抛 `WB-DOC-003`）。
- **为什么是问题**：修完 C16 就能编，这**目前只是假设**——从没跑过，谁也不知道后面还埋着什么。在跑通之前，内容做得再多也进不了游戏。
- **建议**：
  1. C16 修复（Studio 侧改编译器 kind 白名单 + 测试夹具）
  2. **立刻试跑一次编译**，把真实报错一次全暴露，而不是修一个猜一个
  3. 跑通后固定成"每次内容变更都编译一遍"的习惯
- **归属**：改编译器 = Studio 侧；试跑诊断 = 本侧可做（需等签收解禁）
- **成本**：低。**收益**：从"不知道能不能用"变成"确定能用"

### 2. 入库的那份不是真产物

- **现状**：`projection/authoring-out/`（**入库**）与 `workspace/authoring/`（**实际产物**）**12/12 全部不同步**——前者全是 rev1 草稿，后者全是 rev2 落库版。
- **为什么是问题**：
  - 我们进版本控制的**不是最终产物**，落后一整版；
  - 真产物只存在于**被 gitignore 的本机目录**里，机器一坏/目录一清就没了；
  - 两份并存，谁改了哪份说不清（本次修锚点就踩到了：改一处漏一处就不同步）。
- **建议**（二选一，我倾向前者）：
  - **A（推荐）**：定一条规程——**落库后把 `workspace/authoring/` 回写 `authoring-out/`**，让入库的那份始终是最新。不改 `.gitignore`（那是仓库级文件，动它要跟其他 agent 打招呼）。
  - **B**：把 `workspace/authoring` 从 `.gitignore` 里放出来，直接进版本控制。更彻底，但要动仓库级配置。
- **归属**：本侧可做（A 是规程，B 需跨线确认）

## P1 · 做了收益最大

### 3. 给门控喂真内容（对应批次 1）

- **现状**：`denies` **40/40 全空**（而它是**必填字段**）；`secret` / `unknown` 层**各 0 条**；`culture_ids`/`kingdom_ids`/`settlement_ids` + 年龄 + 管理等级**全为 0**；12 个身份只用了 6 个；契约 golden case 6 条**一条没覆盖**。
- **为什么是问题**：门控机器**完整实现了一次都没执行过**。这等于买了台机器从没开机。
- **建议**：**不要全面铺开**。挑 2–3 个地点做"完整样本"——给它们配上 secret 层、写真实 denies、挂上文化/王国/聚落条件。做成模板后，后面扩写照抄即可。
- **参考**：游戏数据现成给弹药（23 文化 / 8 王国 / 494 聚落），不必自造取值。
- **归属**：本侧（内容）

### 4. 从"谁能看"升级到"说法不同"

- **现状**：40 条表达里 **24 条（60%）与断言正文逐字相同**——它们是 C14 裁定的"兜底载体"（中立内核若无表达段则对任何身份不可达），**不是真正的身份化说法**。
  真正做了差异化的 16 条，几乎全集中在 `*-tales`（传说/叙事）和少数几档：

  | 档 | 表达数 | 与断言逐字相同 |
  |---|---|---|
  | dawn-taboo / kach-tales / lac-tales / sara-tales | 11 | **0**（100% 差异化） |
  | der-furs / lac-lake | 7 | 6 |
  | dawn-mtn / kach-own / sara-bay / der-vill | 10 | 10 |

- **为什么是问题**：世界书跟"游戏官方描述"拉开差距的地方，恰恰是**同一件事不同人说法不同**。现在只有传说类做到了，客观事实类全是同一句话。
- **建议**：客观事实保持内核一致没问题，**但至少给差异大的身份（商人 / 贵族 / 士兵 / 头人）各写 1–2 条不同说法**。这是内容价值最高的增量。
- **归属**：本侧（内容）

### 5. 素材策略修正（我上次的判断差点推广错）

- **实测**：拿 5 份编年史跟游戏官方文本做逐字重合比对——

  | 地点 | 最长逐字重合 | 官方文本全长 |
  |---|---|---|
  | **德里亚特** | **21 字** | 47 字 |
  | 黎明山脉 | 12 字（是别名"柯希·罗希尼——黎明山脉"） | 60 字 |
  | 拉科尼斯湖 | 7 字 | 71 字 |
  | 卡恰尔半岛 | 6 字 | 44 字 |
  | 沙拉斯湾 | 4 字 | 50 字 |

- **结论**：**"编年史抄游戏文本"只是德里亚特的个例，不是普遍现象。编年史基本是原创。**
  （我上次在锚点修正里说"编年史该段本就是从游戏官方描述派生的"——那只针对德里亚特，不能推广。特此更正。）
- **所以策略是**：编年史是**主源**（有独立价值）；游戏官方文本（27 万条）是**补充与交叉校验**，不是主源。
- **建议扩写顺序**：编年史 → 游戏官方文本（佐证 / 补地名 / 校别名）→ v1 归档（759 文件，最后挖）。

## 我建议的顺序

```
① 通电：修 C16 → 试跑编译 → 确认能出包          ← 不做，后面都是纸面
② 归位：落库产物回写 authoring-out              ← 顺手，防内容丢失
③ 做样本：挑 2–3 个地点，把门控走一遍（secret / denies / 三维度）
④ 拉开差距：给差异大的身份写不同说法
⑤ 才谈扩量：素材按 编年史 → 官方文本 → v1 归档 的顺序扩写
```

**最小的第一步**：① 和 ② 都很轻。① 的关键不是修代码，而是**跑一次看看真实报错是什么**——这个信息现在完全没有，猜下去不划算。
