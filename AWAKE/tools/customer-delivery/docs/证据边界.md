# 证据边界

交付 manifest 的 `verification` 只反映当前包和哈希链，不代表游戏内成功。

- `E0`：计划、静态契约或未运行项。
- `E1`：编译、解析和自动化检查。
- `E2`：离线测试或本地协议 smoke。
- `E3`：最终客户包、展开树、ZIP 与源绑定哈希通过。
- `E4`：用户从匹配 BuildId 的客户入口运行并完成首次工作流，或提供匹配游戏入口日志。
- `E5`：在 E4 基础上完成用户观察的存读档和至少 30 分钟长跑回归。

本次 package-only 运行最高只能达到包级 `E3`。没有用户日志时，不宣称 `E4` 或 `E5`。

`delivery-manifest.zip_sha256` 是排除根 `delivery-manifest.json` 与 `package-verification.json` 自描述字段后的规范归档内容哈希；根 ZIP 的原始字节哈希记录在 sibling `.zip.sha256` 中。这样既能复算 ZIP 内容，又不会制造 manifest 对自身 ZIP 哈希的循环依赖。
