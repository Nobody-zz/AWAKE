## 一、这份路线图要解决什么

投影批（W1–W6）已把 12 档正式落库，闭合复验 **PASS 14 / FAIL 0 / OPEN 0 / BLOCKED 1**。**内容有了骨架，结构有了契约**，但两件事还没做：

1. **结构里有一半从没被内容走到过。** 门控（分层 / 授权 / 否决 / 转介）机器是齐的，内容只走了"人人皆知"的那半边。
2. **内容只有 5 个地点。** 在册来源仅 5 份编年史（合计约 28KB）。

所以顺序应当是：**先把结构验完，再把内容铺开。** 理由很直白——结构现在改一处只动 12 档；等铺到上百档再发现结构要改，改的就是全部。

### 批次 0：术语与账目整顿（前置，先做）

- **目标**：让下一个人（包括三个月后的我）不靠猜就能读懂账。
- **三件事**：
  1. **编号索引**：内容侧 B 系列（现仅见于 `ENTRY-LINKAGE-MAP-20260912.md` 的 B2=era / B6=冲突裁定 / B8=valid_from / B9=ID 命名空间）在本工作区**找不到定义文件**；而 `AWAKE-Landing-Plan-20260816.md` 另有一套 B0–B9（运行时，B4=事件引擎数据驱动化）。**两套同名不同义。** 要么补一份定义索引，要么改用可读名。
  2. **账目命名**：`41 claim / 40 断言 / 40 表达 / 40 授权 / 22 新增 / 19 孤儿 / 9 被取代 / 23 动作 / 24 决策` —— 现在全靠数字区分，极易看错。给每个起唯一名。
  3. **术语统一**：`对象簇` / `语义实体` / `表达层` / `层` / `范围` / `详细度` 这几个词在文档里交叉使用，含义不完全一致。
- **产出**：`AWAKE/docs/worldbook-migration/GLOSSARY-AND-LEDGER-INDEX-20260912.md`（或并入既有索引）。
- **为什么排最前**：零风险、不改任何产物，而批次 1–3 都要用这套词。**先立词，后干活。**
- **红线**：纯新增文档，不动任何已落库产物。

### 批次 1：授权结构做真（建议紧接批次 0）

- **目标**：让内容把门控的**后半段**走一遍——把契约里写下、却从未被执行过的规则真的执行一次。
- **依据（不是我发明的，是契约要求的）**：`docs/worldbook-studio-plan/PERMISSION-CONTRACT.md` 有 6 条 golden case，内容一条都没覆盖：
  1. 普通村民有 Grant、同时命中贵族秘密 Deny → **拒绝**（Deny 优先）
  2. 高管理贵族没有 `scope=elite` Grant → 不能读贵族秘密
  3. 酒馆老板只有 `layer=rumor` Grant → **不得返回 detail**
  4. 文化匹配但国家不匹配 → 两个维度必须同时满足
  5. **空 grants / denies → 返回 unknown，不得默认 public**
  6. 未知 profile → 编译阻止
- **做法**：挑内容本来就该限的档补结构。天然目标：
  - `dawn-taboo`（黎明山脉·禁忌）：来源明写「山脉核心历来对外来者封闭，擅入即亵渎」→ 该有 **secret 层** + 一条针对 `profile.anonymous`（身份未知）的 **deny**。对应 golden case 1。
  - `lac-lake`（拉科尼斯湖）：已有 1 条 `noble_high_steward / elite` → 顺手补「高管理贵族不知情」的对照面。对应 golden case 2。
  - 物产 / 田产档（`der-furs` 毛皮、`kach-own` 田产）→ 用 `profile.merchant` / `profile.ransom_broker` + `scope=faction`。
  - 传闻档（`lac-tales` / `sara-tales`）→ 用 `profile.tavernkeeper`（酒馆老板只该说传闻）。对应 golden case 3。
  - 另：把 `culture_ids` / `kingdom_ids` 至少各用一次，覆盖 golden case 4。
- **验收（全部离线可验，不涉及游戏）**：
  - Studio 只读结构校验 **0 诊断**；
  - Studio 预览诊断（`author_diagnostics`）能显示**拒绝原因与命中规则**——契约规定 `npc_preview` 不得含这些字段，正好拿来反向验；
  - 闭合复验工具加检查项：`secret` 层 ≥1、`denies` >0、`scope` 至少用满 5 档、profile 使用数 ≥8、golden case 1–5 各有对应内容；
  - 每条改动都能指回来源引文（沿用既有 `claim→origin` 规矩）。
- **红线**：不改 `referral-registry.v1.json` / `profile-registry.v1.json`（被 Studio golden 钉死，改字节即打掉测试套件）；**不新增 profile**（同上，只能用现有 12 个）；不碰任何 C#。
