# AWAKE 事件类型清单 v0.1 草案

> 日期：2026-08-16
> 状态：先划清边界，确认后落成 `AwakeEventCategory` 等枚举并接入事件定义校验。

## 1. 事件的定义与边界

事件是引擎在安全点触发的一次完整互动：有明确入口、可选内容、可结算结果、可持久化状态。

以下内容不属于“事件类型”，不放进本清单：

- 场景活动：城镇散步、扎营准备等属于活动/玩法，不是事件弹窗。
- 普通对话轮次：AI 对话本身不是事件。
- 任务与剧情：有原版任务系统承载，不混入事件引擎。
- 身体开发、发情、俘虏互动等：属于内容包机制，事件可以引用它们，但事件类型不按它们划分。
- “参与话题”：这是事件选项形态，不是事件类型。

每个事件至少声明一组类型元数据，未声明的事件注册失败。

## 2. 第一层：触发来源

| 类型 | 说明 | 当前状态 |
| --- | --- | --- |
| `PresetRule` | 内容包注册的预设事件，正文固定，触发由条件控制 | 引擎已支持 |
| `Situational` | 预设事件按当前局势筛选，再按权重随机触发 | 引擎已支持基础条件 |
| `PlayerInitiated` | 玩家主动发起，例如从菜单、通讯录、遭遇面谈进入 | 运行时入口已有，不属事件引擎 |
| `NpcInitiated` | NPC 主动发起，例如靠近、邀约、来信 | 未开始 |
| `DynamicAI` | AI 根据局势现场生成事件正文与选项 | 未做，明确不纳入近期 |

边界：`PresetRule` 与 `Situational` 只是同一预设内容的两种触发声明；`DynamicAI` 属于独立能力，不能和预设规则混用。

## 3. 第二层：场景空间

| 类型 | 场景 | 可用的基础条件 |
| --- | --- | --- |
| `MapMarch` | 大地图行军 | `Always` 加主队移动状态 |
| `Camp` | 扎营等待 | `Camping` |
| `Settlement` | 城镇、城堡、村庄 | `InSettlement` |
| `Sea` | 海上或停航 | 后续补 `AtSea` |
| `Encounter` | 地图遭遇、战后 | 后续补遭遇状态 |
| `Scene` | 场景内近距离互动 | 场景任务/Agent 存在 |

边界：一个事件只能有一个主场景；跨场景延续必须拆成链式事件。

## 4. 第三层：主体范围

| 类型 | 主体 | 典型目标 |
| --- | --- | --- |
| `PlayerNpc` | 玩家与单个 NPC | 稳定 HeroId |
| `NpcNpc` | NPC 之间 | 两个稳定 HeroId |
| `Clan` | 家族/亲族关系 | 家族与成员 |
| `Kingdom` | 王国、领地、宫廷 | 王国/领地 |
| `World` | 全图局势 | 无特定玩家 |
| `Environment` | 环境、天气、资源 | 无稳定角色 |

边界：`PlayerNpc` 事件必须能解析到目标；`World` 事件不能假设玩家在场。

## 5. 第四层：内容性质

| 类型 | 内容范围 | 边界 |
| --- | --- | --- |
| `Daily` | 日常、闲聊、生活琐事 | 不结算重要状态 |
| `Survival` | 粮食、伤病、物资、营地生存 | 可结算资源，不做身体内容 |
| `Military` | 行军、战争、雇佣、劫掠 | 可结算军势/关系 |
| `Politics` | 宫廷、政令、外交、家族利益 | 可引用王国/家族状态 |
| `Trade` | 交易、商队、物价、财富 | 可结算金币/商队 |
| `Relationship` | 信任、爱意、敌意、私交 | 运行时已可结算关系 |
| `Intimate` | 情色、身体、俘虏等成人内容 | 内容包专属，运行时门控 |
| `Mystic` | 神谕、禁忌、宗教、神秘力量 | 内容包专属 |
| `World` | 世界事件、流言、势力变化 | 必须走世界状态命令 |

边界：`Intimate` 与 `Mystic` 不进入 AWAKE 纯净运行时；运行时只定义通用内容类别。

## 6. 第五层：结算方式

| 类型 | 结算 | 现状 |
| --- | --- | --- |
| `NarrativeOnly` | 纯叙事，不改变数值 | 已支持 |
| `DialogueEntry` | 选项后打开 NPC AI 对话 | 已支持 `参与话题` |
| `NumericSettlement` | 关系、资源、状态数值结算 | 关系命令已支持 |
| `Chain` | 选择后进入下一事件 | 引擎已支持基础链式 |
| `WorldEffect` | 政令、世界状态、公告 | 未开始 |

边界：同一选项可以同时触发 `DialogueEntry` 和 `NumericSettlement`，但结算必须由受控命令完成，不能由 AI 文本直接改数值。

## 7. 第六层：玩家选项形态

| 形态 | 说明 |
| --- | --- |
| `Informational` | 只有确认，无实质选择 |
| `TwoChoice` | A/B 两选一 |
| `MultiChoice` | 三个及以上选项 |
| `DiscussionEntry` | “参与话题”，进入 AI 对话 |
| `Timed` | 有限时间内必须决定 |

边界：`DiscussionEntry` 可以单独存在，也可以和 A/B 并存；它不是事件类型。

## 8. 第七层：持久性

| 类型 | 说明 | 现状 |
| --- | --- | --- |
| `Repeatable` | 冷却后再次出现 | 已支持 |
| `DailyCapped` | 每日次数上限 | 已支持 |
| `OneTime` | 整个存档只触发一次 | 未接唯一标记 |
| `ChainUnique` | 链式事件不重复 | 未接唯一标记 |
| `CampaignPersistent` | 读档后继续 | 事件元数据已持久化 |
| `CrossSave` | 跨存档保留 | 未做 |

边界：`OneTime` 和 `ChainUnique` 需要持久化“已触发”标记，不能只靠冷却。

## 9. 组合规则

一个事件必须声明：

- 触发来源
- 主场景
- 主体范围
- 主要内容性质
- 主结算方式
- 选项形态
- 持久性

允许：

- 一个事件带多个可选项，每个选项独立结算。
- 一个事件同时带 `参与话题` 和普通选项。
- 一个事件由多个条件共同筛选。

不允许：

- 未声明类型通过校验。
- 一个事件同时声称两个主场景。
- 运行时事件直接引用 `Intimate` / `Mystic` 内容。
- AI 输出直接结算数值，必须走命令。

## 10. 落地顺序

1. 把本清单落成代码枚举：`EventSource`、`EventContext`、`EventSubject`、`EventContent`、`EventResolution`、`ChoiceShape`、`PersistenceMode`。
2. 事件定义增加这些字段并纳入校验。
3. 内容包注册时按类型过滤，运行时不做硬编码事件。
4. 先支持 `PresetRule + Situational` 的日常、关系、生存、军事、政治、贸易基础事件。
5. `Intimate` / `Mystic` / `DynamicAI` 全部留到内容包和后续版本。
