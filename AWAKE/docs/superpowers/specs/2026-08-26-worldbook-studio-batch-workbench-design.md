# AWAKE Worldbook Studio 批量创作工作台设计

- date: 2026-08-26
- status: user-approved-slice
- parent_contract: `docs/superpowers/specs/2026-08-25-worldbook-studio-batch-authoring-contracts-r14.json`
- contract_sha256: `7D07B08DA4CE5AB27DFE70F2F81BB098597A04FD170160612E09C32DA4540808`
- scope: 只接通现有批量 AI 后端的内容编辑者工作台；不升级 R14 公共契约。

## 1. 目标

把已经存在的批量 AI 后端变成普通内容编辑者可以直接操作的生产流程：

```text
打开批量创作
→ 选择或拖入参考资料
→ 扫描并查看资料分段
→ 创建批次并明确 AI 读取范围
→ 批量提取事实
→ 逐项目快速审核事实
→ 批量生成标题、分类、二级主题和摘要候选
→ 审核元数据
→ 批量生成 needs_review 世界书草稿
→ 回到主编辑器逐档复核
```

完成定义采用：`入口 → 调用 → 状态结算 → 可观察结果 → 草稿落盘`。

## 2. 已确认事实与硬边界

### 已确认事实

- R14 已提供 scan、create、get、report、item-detail、consent、start、pause、cancel、claim、retry、review、create-documents 路由。
- 现有批量结果包含事实、证据、来源单元和元数据候选的公开投影。
- 生成档案被后端固定为 `needs_review`。
- 当前后端不生成 `expressions`，不做人物、家族或身份绑定，不发布正典，不写游戏目录。
- 当前 `start` 请求在一次 HTTP 调用内执行目标项目；现有 pause/cancel 主要改变持久批次状态，不能保证中断已经发出的 Provider 请求。
- 当前工作室是本机工作区；真实云端 Provider、Worker 部署和 Bannerlord 实机证据不属于本工作台的离线 UI 验收。

### 不可突破的边界

- 不修改 R14 合同、路由、保存格式或批量后端状态机。
- 不自动把 AI 候选视为正典，不提供“自动发布”按钮。
- 不把人物、家族、身份权限作为本批次输入或输出。
- 不生成 NPC 表达，不把参考资料直接当作世界书正文。
- 不读取或修改游戏目录，不启动 Bannerlord，不同步冻结 AWAKE 候选。
- 不把模拟 Worker 的 Smoke 结果描述为真实云端生产证明。

## 3. 方案选择

### 方案 A：主编辑页内嵌批量区域

- 优点：入口少，复用现有页面状态。
- 缺点：继续扩大单体 `index.html`，与主档案编辑互相抢空间，批量项目列表、原文、审核和 AI 操作会形成多重嵌套滚动。
- 结论：不采用。

### 方案 B：独立全屏批量创作工作台（采用）

- 优点：批量任务有独立心智模型；中间空间可稳定展示资料、事实和证据；右侧 AI 操作不会被主编辑器压缩；可保存最近批次。
- 成本：需要一个独立前端模块和最小入口接线。
- 兼容：完全复用现有 R14 HTTP 路由，不改变公共契约。

### 方案 C：新增后台作业 API

- 优点：可以真正异步执行和取消 Provider 请求。
- 成本：需要新增公共契约、后台队列、取消令牌、恢复语义和新的测试/发布门禁。
- 结论：本批次不采用；UI 必须诚实显示现有同步执行限制，后台作业作为后续独立批次。

## 4. 工作台布局

工作台以现有 Studio 页面内的全屏 `dialog` 覆盖层呈现，不新开窗口、不破坏现有档案编辑器。入口固定为顶栏“批量创作”按钮；关闭时回到打开前的档案和编辑模式。

默认三栏：

```text
左栏：批次与项目列表
中栏：当前项目的原文、事实、证据、元数据
右栏：AI 操作、批量动作、Provider 状态、边界提示
```

- 左右栏均有可拖拽分隔线，宽度保存在浏览器 `localStorage`。
- 小窗口自动切换为上下分区，不能把 AI 操作藏到不可见的窄栏。
- 中栏只保留一个主要滚动区域；原文和审核卡片在同一工作上下文内切换。
- AI 面板始终显示当前阶段允许的操作，不再只是主编辑页的附属小卡片。
- 所有内部 ID 只显示为“批次编号/项目编号（高级信息）”，默认不要求用户理解。
- 如果主编辑器有未保存修改，点击入口先提示“批量工作台不会带走未保存内容”；用户可取消进入，也可先保存后进入。
- 工作台关闭后不清空主编辑器状态；批次状态通过服务端重新读取，不能依赖页面内存作为权威。

## 5. UI 阶段与行为

### 阶段一：选择资料

- 支持文件选择和拖放。
- 显示已选文件名、大小、数量和总大小。
- 前端提示后端限制：最多 200 个文件、总计 64 MiB、单文件 16 MiB。
- 点击“扫描资料”调用 `POST /api/ai/batch/scan` multipart。
- 扫描成功后显示来源快照、段落数量、字符数和可进入下一步的状态。
- 空选择、超限、后端错误均显示中文解释和下一步建议。

### 阶段二：创建批次与授权

- 选择 Provider：本机 Worker 或云端 Provider；读取现有 `/api/ai/providers` 状态。
- 模型参数使用易懂的字段：模型、创造性、最大输出长度、推理强度；默认值来自现有配置。
- 点击“建立批量任务”调用 `POST /api/ai/batch/create`。
- 创建后显示“AI 将读取哪些资料”和“不会读取哪些内容”的同意预览。
- 用户必须主动点击“同意本批次读取范围”，调用 `POST /api/ai/batch/{batchId}/consent`，首次授权固定使用 `scope=facts_and_metadata`，这样事实审核通过后才能进入元数据阶段；失败重试时再按目标项目重新授权。
- 默认授权所有扫描项目，但允许取消选择；UI 以项目标题/文件名显示，不显示裸 ID。

### 阶段三：事实生产

- 点击“提取客观事实”调用 `POST /api/ai/batch/{batchId}/start`，`stage=facts`。
- 启动前显示授权项目数、预计生成项目数和 no-canon/no-binding 提醒。
- 执行中轮询 `GET /api/ai/batch/{batchId}` 与 `/report`，显示已完成、处理中、待审核、失败和未知结果数量。
- 事实卡片显示：事实正文、证据引用、来源文件、原文段落、风险等级和审核状态。
- 每个项目支持“接受事实”“退回重做”“逐条保留/驳回事实”。
- 多项目快速审核必须显示影响数量并二次确认；实际仍按项目逐项调用 R14 review，禁止静默覆盖或宣称原子提交。

### 阶段四：元数据生产

- 只有事实审核通过的项目才能进入元数据阶段。
- 点击“生成档案信息”调用 `start`，`stage=metadata`，目标只包含满足契约的项目。
- R14 当前只支持批量生成和建档所需的四个字段：标题、摘要、领域、二级主题。工作台只显示这四个字段，不伪装提供时期或确定程度的批量写入能力。
- R14 没有独立的元数据审核保存路由，且 `create-documents` 要求提交值与当前候选一致；批量阶段因此只允许“采用 AI 候选”，不提供会被后端拒绝的手工改写或留空按钮。
- 如果编辑者不接受候选，先不生成该档案；生成草稿后再回到主编辑器修改标题、摘要、分类或二级主题。
- “所属时代”和“确定程度”由生成的 `needs_review` 草稿回到主编辑器后人工补充；它们不作为本批次的 AI 元数据结果。
- 元数据生成失败或未知结果显示“重新授权后重试”的说明，不把失败伪装成空结果。

### 阶段五：生成草稿

- 只有 facts 与 metadata 都审核通过的项目可勾选。
- 点击“生成世界书草稿”调用 `POST /api/ai/batch/{batchId}/create-documents`。
- 默认 `create_mode=needs_review`，前端固定显示“只生成待审核草稿”。
- 成功显示生成数量和“打开主编辑器复核”按钮；不会直接跳过人工复核。
- 失败项目保留在批次中，可查看原因并逐项重试。

## 6. 项目详情模型

项目列表只展示编辑者需要的字段：

- 文件/段落标题
- 当前阶段
- 当前状态
- 事实数量
- 证据数量
- 元数据是否完成
- 是否需要人工处理

点击项目后请求 `GET /api/ai/batch/{batchId}/items/{itemId}`，中栏按四个折叠区显示：

1. 原文依据：来源文件、引用段落、可展开的原文。
2. 客观事实：事实卡片与逐条决策。
3. 档案信息：标题、分类、二级主题、摘要候选；附带提示“时期和确定程度请在主编辑器补充”。
4. 处理说明：风险、失败原因、重试建议、系统边界。

## 7. 暂停、取消、重试的诚实语义

- “暂停批次”：调用现有 pause，并停止前端继续发起新的 start；当前同步 `StartAsync` 可能继续处理当前请求甚至后续项目，UI 必须显示“已发出的 AI 请求可能继续完成”，刷新后以服务端状态为准。
- “取消批次”：调用现有 cancel，并停止前端继续发起新的 start 或建档；当前同步 `StartAsync` 不承诺立即中断，UI 不显示“已终止请求”。
- 前端在请求处于 `running` 时不显示“立即停止”或“已终止请求”等误导文案。
- `retry` 必须要求人工确认，并按当前阶段重新授权；前端显示会重新读取哪些项目。
- 轮询发现 revision 变化时，放弃旧按钮状态，先刷新批次再允许写操作。

## 8. AI 辅助交互

右侧 AI 面板按当前阶段提供快捷动作，且每个动作都有现有 R14 路由对应：

- 提取客观事实（`start(stage=facts)`）
- 生成档案信息（`start(stage=metadata)`）
- 查看事实证据（读取 `item-detail`，不是再次调用 AI）
- 重试失败项目（`retry-item`，随后重新授权并启动）
- 生成待审核草稿（`create-documents`，固定 `needs_review`）

“检查事实证据”和“检查权限风险”在本批次不作为虚构的 AI 按钮；证据由 R14 返回并由编辑者审核，权限风险继续由主编辑器的 AI 助手或人工流程处理，不能借批量 UI 暗中增加未定义的绑定。

每个 AI 动作均显示：输入范围、Provider、输出是否会写入、需要的人工确认。候选采用“送入审核区”而不是“直接应用”。

## 9. 状态持久化

浏览器 `localStorage` 只保存 UI 状态，不保存 API Key、原文或 AI 输出；键名固定使用 `awake.worldbook.studio.batch.v1.*` 前缀，并在读取批次 ID 时校验 ID 格式和服务端是否仍存在：

- 最近批次 ID
- 左栏/右栏宽度
- 当前阶段
- 当前项目 ID
- 是否显示 AI 面板

- 只恢复已创建的 `batch_id`；扫描尚未建批次时不承诺刷新后恢复，用户需要重新选择资料并扫描。
- 记录 `saved_at`；超过 30 天的批次引用自动清理。
- 恢复失败时只清理无效引用并显示“最近批次已失效”，不把旧 ID 继续提交给服务端。

服务端批次和事实/元数据结果仍以 R14 工作区文件为权威。刷新页面后，若最近批次仍存在，工作台提供“恢复上次批次”按钮。

## 11. 明确不做

- 不新增后台作业队列、WebSocket、真正的 Provider 取消令牌。
- 不修改 R14 JSON 契约，不添加新公共路由。
- 不承诺原子“批量审核”；多个项目的快速操作只是按 R14 单项目 review 路由顺序提交。
- 不把时期、确定程度、证据检查或权限检查包装成 R14 尚未支持的批量 AI 输出。
- 不在本批次实现批量自动发布、自动绑定人物/家族/身份或生成 expressions。
- 不在前端实现新的世界书编译器或游戏读取器。
- 不以本机 fake Worker 结果替代真实云端 Provider 试运行结论。

## 12. 未解决风险与后续建议

- 现有 `start` 是长请求；在没有后台作业机制前，UI 只能显示轮询状态和诚实的暂停/取消语义。
- 真实云端 Provider 的延迟、配额、超时和结构化输出质量仍需单独做 provider 试运行评估。
- 批量生成的档案质量需要内容作者使用真实资料进行离线试用，不能仅靠前端测试证明。
- 若未来需要真正暂停/取消，应新建独立 R15 设计，不在本工作台暗中改写 R14 语义。
