## 1. 产品定位

AWAKE 是构建在 Bannerlord 之上的 AI 原生开放世界体验模组。对话是主要交互入口，但不是功能边界；长期目标是形成一个能够承载关系、知识、交易、任务、政治、战争、阴谋、生活和内容扩展的世界运行平台。

AWAKE 的主打差异化不是单独的“有 AI 对话、记忆或 NPC 行动”，而是：

> **知识驱动的社会沙盒：每个人知道的卡拉迪亚，都不是同一个卡拉迪亚。**

玩家可以询问、验证、传授、隐瞒、欺骗、传播和利用信息，并承担信息传播造成的关系、事件和世界后果。

## 2. 核心玩家循环

```text
玩家用自然语言提出意图
→ AI 解析或补充理解
→ 代码检查权限、条件、知识和代价
→ 代码结算允许的行为
→ 世界事件、关系和认知状态更新
→ 信息传播到合适的 NPC 或渠道
→ AI 以角色化语言表达结果
→ 后续行为继续改变世界
```

核心优先级暂定为：

- 系统主循环：自然语言意图进入可验证的世界结算；
- AWAKE 差异化：知识、可信度、传播和社会后果；
- 玩家体验形式：自然对话和关系交互；
- 长期扩展：在同一链路上接入生活、经济、政治、战争和创作玩法。

## 3. 玩家输入与行动边界

- 默认使用自然语言，不要求玩家学习专门命令语法。
- 内置提示词、关键词和可见按钮作为辅助，不作为唯一判定依据。
- 代码可识别高频、明确的“确认”和“取消”；其他关键词只提高分类置信度。
- 玩家输入需要区分普通台词、询问、传授/传播、社交行为、世界行动和系统操作。
- 行为按后果分级：普通表达、低影响社交行为、可持续影响行为、重大/不可逆行为。
- 低影响行为可以自然结算；重大或不可逆行为必须经过代码检查并请求明确确认。
- “说过”不等于“世界已经发生”；只有通过结算的行为才写入持久状态或世界事件。

## 4. 世界事件、季度周报和玩家知识

三者不是同一层：

```text
世界事件 = 世界实际发生的事实
报道内容 = 某个渠道对事件的说法
季度周报 = 承载多条报道内容的玩家信息载体
玩家知识 = 玩家阅读、亲历、询问或听闻后形成的认知
```

### 4.1 世界事件

- 事件发生时即时生成并结算；不等待报告周期。
- 事件进入事件账本，驱动状态、关系、资源、战争和后续事件。
- 事件是世界事实源，不能因为玩家不知道或周报写错而被改写。
- AI 可以提出事件候选，但必须经过代码范围、条件、身份、时间和冲突检查后才能提交。

### 4.2 季度玩家周报

本轮已确认的产品方向是：**按游戏内季度定期整理生成一份玩家可读的世界报告**。它是玩家获取信息的一种渠道，不是玩家已有知识的总结，也不是世界事件原始日志。

```text
季度内事件即时发生
→ 季度结束后代码筛选、合并、去重和排序
→ 生成报告结构
→ AI 可将结构化事实编排为可读文本
→ 代码检查引用事实闭包
→ 报告发布并保存
→ 玩家取得并阅读后获得相应知识
```

周报主体采用自上而下的层级：

1. 世界概况：本季度最大趋势、战争外交、经济文化变化和未决危机；
2. 各国概况：国家状态、政治、经济、文化、战争、主要势力变化；
3. 地区和聚落动态：只展示有重大变化或与玩家有关的地点；
4. 重大事件详报：事实、影响、相关势力、各方说法和未确认问题；
5. 传闻与争议：明确标记来源、可信度和未证实状态。

阅读体验采用渐进披露：

- 第一层为 30 秒左右的 3–5 条重点摘要；
- 第二层为各国状态卡片或短摘要；
- 第三层按需展开国家、地区和事件详情；
- 没有变化的国家不重复生成长文；
- 完整结构化数据可以保存，但默认不强迫玩家阅读全部内容。

报告的主文采用中立编纂风格；只有重大争议事件才追加官方、地方、敌对势力或传闻等代表性说法。中立不等于全知：报告只能发布该渠道能获得和确认的内容。

报告访问采用混合模式：公共概况可以通过公共信息渠道获得，详细国家、战报、商情和特殊消息需要对应渠道；第一阶段可以用游戏内报告界面表示玩家取得并阅读了报告，不强制模拟纸张物理流转。

## 5. NPC 知识结构

NPC 知识采用“身份基线 + 个人修正”的来源模型：

```text
身份知识基线
→ 地域、文化、年龄、教育和技能修正
→ 亲身经历修正
→ 关系与信息渠道修正
→ 最近事件和报告修正
```

身份只决定通常能接触到的知识范围，不把同一身份的 NPC 做成完全相同的复制品。

基础倾向包括：

- 普通农民：本村、本地习俗、传说、粮食和治安；
- 酒馆老板、公证商人、赎金经纪人：作为知识中介，拥有更广的渠道知识；
- 村庄或城镇头人：本地治理、税赋、治安和本国常识；
- 士兵：本国战争、军队常识和亲历战事；
- 贵族：政治、家族、外交和权力结构，按年龄、管理能力和经历增加；
- 贵族兵种：以军事知识为主，并按其身份获得缩减后的贵族知识。

### 5.1 知识边界

- 秘密类知识采用硬权限；没有合法来源不能直接知道。
- 普通知识可以采用软可信度；同一内容在不同 NPC 处表现为不同详细度和确定程度。
- 越界知识必须有来源：亲历、参与、任职、被告知、周报、战报、商人渠道或身份变化。

### 5.2 详细度

“能接触”与“知道多少细节”分开：

```text
未知 → 听说/传闻 → 简要事实 → 实用细节 → 背景因果 → 专业/机密细节
```

NPC不能因为玩家追问就把摘要自动扩写成不属于其身份和经历的完整知识。

### 5.3 回应、记忆、信念和行动

```text
当前对话反应
→ 短期记忆
→ 认知状态
→ 是否愿意表达
→ 是否影响计划或行动
```

必须区分：

- 听到不等于记住；
- 记住不等于相信；
- 相信不等于愿意说；
- 愿意说不等于愿意服从或行动。

普通对话下，NPC 的交流意愿应略偏向愿意回应，但不保证完整、准确、主动或热心地提供答案。隐瞒、误导和完全拒绝必须有具体的身份、风险、利益、场合或关系原因；不能把 NPC 做成默认的任务指引员。

如果 NPC 不知道，应当自然地说不知道、说明自己只知道哪一部分，只有在它确实知道更合适渠道时才进行转介。关键玩法信息应通过多渠道保证可获得，而不是强迫当前 NPC 每次都提供线索。

## 6. 关系、可信度、信任和行动

不能建立一个统治所有行为的单一“信任分数”。

- 原版个人关系、家族关系和族长关系保留原含义，作为社会态度输入，不直接等于信任；
- 家族关系不能自动覆盖家族所有成员的个人判断，族长变更时按原版动态关系处理；
- 具体说法的可信度按当前事件、来源、证据、亲历和 NPC 专业经验判断；
- 对玩家的可信历史只在重要 NPC、重大关系或必要事件中轻量保存，不为所有背景 NPC 维护复杂长历史；
- “相信内容”“愿意透露”“愿意接受建议”“愿意服从”“愿意承担风险”分别判断。

推荐使用少量离散状态而不是每次让 AI 计算复杂连续公式：

```text
关系：敌对 / 冷淡 / 中立 / 友好 / 亲近
可信判断：拒绝相信 / 保留 / 暂时相信 / 基本接受
证据：无 / 间接 / 直接
表达：开放 / 保留 / 条件 / 隐瞒
```

代码负责判断和结算，AI 负责角色化表达。

## 7. 多阶段 AI 接口

AWAKE 应保留类似 AF 的多阶段 AI 接口，但“接口很多”不等于“每次调用很多次”。

### 同步交互阶段

1. 前处理：意图、实体、歧义和风险识别；
2. 上下文/检索辅助：在代码权限筛选后做候选匹配或压缩；
3. NPC 认知与行动提案：输出 belief/response/action/memory proposal；
4. 回应生成：根据代码结算结果生成角色表达；
5. 后处理：代码结构校验、事实权限检查，必要时 AI 修复格式或风格。

### 异步或批量阶段

- 记忆压缩与长期条目晋升；
- 季度周报编排；
- 世界事件提案；
- 作者工具的世界书和角色卡辅助。

所有阶段都只产生候选、解释、表达或结构化提案，不能直接写入世界事实、关系、财产、身份、知识权限或行动结果。默认应有代码快速路径、缓存、Provider 路由、超时、取消和降级；简单闲聊不应串联所有阶段。

## 11. 增量决策记录（2026-08-26）

自本 checkpoint 首次写入后，继续讨论并确认了以下内容：

- AWAKE 保留类似 AF 的多阶段 AI 接口，包括前处理、上下文/检索辅助、NPC 认知与行动提案、回应生成、后处理校验，以及异步的记忆压缩、季度报告、事件提案和作者辅助接口。
- 多阶段接口是可插拔处理阶段，不代表每次交互都串联多次 AI；简单闲聊应走代码快速路径，复杂场景才按需增加阶段。
- AI 接口只输出解析、候选、提案或表达；代码仍然拥有世界事实、权限、关系、知识、行动和持久化结果的最终决定权。
- NPC 的身份知识基线需要与地域、年龄、技能、经历和渠道结合；秘密类知识硬限制，普通知识使用可信度和详细度限制。
- “知道”“愿意回答”“完整披露”“相信”“服从”和“行动”继续保持独立；不能由一个通用信任分数统治全部行为。
- 普通交流中 NPC 的回应意愿可以略偏正面，但不等于默认完整披露；隐瞒、误导和拒绝必须有具体上下文原因，也不能强制所有 NPC 充当任务指引员。
- 玩家传授错误信息时，NPC 可以忽略、怀疑、暂时相信、相信但不传播，或在风险压力下采取低成本防范；结果不能只由好感或单一信任值决定。
- NPC 形成相信状态后，不应直接跳到世界行动；“观察/核实/准备/转告/等待命令”是行动前的中间结果。行动还要检查相关性、紧迫性、能力、资源、风险、利益和命令压力。

### 11.1 当前 NPC 认知到行动链

```text
接触信息
→ 判断能否理解和接触
→ 形成听说、保留或相信状态
→ 判断与自身目标和职责的相关性
→ 忽略、观察、核实、准备、转告或等待命令
→ 满足条件后形成行动候选
→ 代码验证并结算
→ AI 表达行动前后的角色反应
```

此链路仍属于产品方向讨论，不代表已有运行时入口或游戏内闭环。
## 12. 增量决策记录（2026-08-26，时间与纠错）

- 当前保存日期按系统时间记录为 **2026 年 8 月 26 日**。
- 普通传闻和临时判断可以随时间衰减；世界事件本身不会因为 NPC 忘记而消失。
- 与身份、职责、亲历、重大关系、生计或长期政治变化有关的认知应保留更久。
- 被证伪的信息不直接删除，而是标记为已纠正、已被证伪或来源不可靠；NPC 可以保留“曾经相信过”的历史。
- 纠正不应自动成功；新证据强度、来源可信度、亲自验证、利益冲突、公开传播和承认错误的心理阻力共同影响纠正结果。
- 错误信息被纠正后，已经发生的错误行动、关系损害和传播残余不自动回滚。
- 衰减和纠错由代码按事件、日结或季度批处理；AI 只在重要记忆晋升、冲突解释或纠正总结时按需参与。

### 12.1 当前认知生命周期

```text
接触信息
→ 当前反应
→ 听说或暂时相信
→ 记忆保留与强化
→ 传播、验证或产生后果
→ 衰减、修正或被新证据替代
→ 历史认知归档
```
## 13. 时间维度纠偏（2026-08-26）

用户提醒的“注意时间”主要指**角色记忆和世界状态必须使用游戏内时间**，不是要求把讨论保存日期误当成角色记忆时间。本 checkpoint 的现实保存日期仍为 2026 年 8 月 26 日；NPC 记忆设计必须另行使用 Bannerlord 战役日、季度、季节和事件时间。

角色记忆至少要区分：

```text
事件发生时间
→ NPC 获取信息时间
→ NPC 形成记忆时间
→ 最近一次被强化或回忆时间
→ 当前游戏时间
```

必要时还要保留：

- 记忆类型和预计有效期限；
- 记忆的重要性和持久性；
- 当前新鲜度或衰减状态；
- 是否已经过时、被证伪或被新事件替代；
- 记忆来源和传播渠道。

时间效果不应只表现为“删掉记忆”，而应先改变：

- NPC 是否认为事情刚发生还是很久以前；
- 叙述时使用的时间语气和细节完整度；
- 信息对当前决策的紧迫性；
- 旧传闻的可信度和新鲜度；
- 事件是否已经从当前问题变成个人历史。

建议的持久性方向：

- 普通闲聊：小时到数日；
- 临时传闻：数日到数周；
- 近期承诺、债务、威胁和任务：在完成、取消或失效前保留；
- 亲历战争、重大伤害、家族背叛和重大关系事件：长期保留，衰减的是细节和即时性，不是事件曾发生过的事实；
- 公共稳定知识：不因时间简单删除，但可以因世界变化而过时。

记忆年龄必须由当前游戏日减去记忆时间计算，读档后重新计算；不能使用现实时间戳作为角色记忆年龄。

- `review_scope`: 角色记忆时间链、调取与衰减方向；只读检查，无代码、游戏、Provider 或存档验证。

主要发现：

1. “最近一次被强化”和“最近一次被回忆”不能共用一个时间字段。回忆只是读取，不应自动提高可信度或刷新传闻寿命；再次获得信息、获得新证据或亲自验证才算强化。
2. 事件发生时间、报道/声明发布时间、NPC 接收时间和角色记忆形成时间属于不同对象；不能把它们全部塞进一条无来源的记忆记录。
3. 记忆类型尚未正式决定，需区分哪些由事件系统、知识/声明系统、承诺账本、关系状态或记忆系统负责。
4. 时间影响应拆成可调取性、细节清晰度、可信度、新鲜度、行动紧迫性、表达措辞和长期保留等独立结果，不能使用一个笼统的衰减值。
5. 当前 `weekly-report.v1` 的七日契约与季度玩家报告方向仍是迁移边界，不得直接视为同一运行时行为。
6. 当前游戏时间是比较输入；记忆年龄应读档后由当前战役时间重算，不应保存现实时间或把当前时间复制进每条记忆。
7. NPC 记忆容量、T0–T3 保留规则和批处理时机尚未确定，不能假设所有 NPC 都保存完整冲突历史。

审查结论：此前“时间影响调取机制”的方向保留，但在对象边界和字段语义锁定前，不进入实现计划。
