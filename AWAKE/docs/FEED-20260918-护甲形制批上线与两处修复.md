## 三、发现一：语义臂对「库里没有的东西」不弃权（**待甲方定口径**）

挂/不挂语义臂对拍，**只有 8 行状态变化**，其中 5 行是同一件事：

* **不是本批造成的**（证据：拿 **v14 包**（护甲批之前）跑同一探针，红的还是同样这 5 条；
  不挂语义臂时 5 条全部 `not_found`）。语义臂是 09-17（`a96adfd`）接进模拟器的，
  而矩阵探针自 09-16 之后就没跑过 ⇒ 这个变化此前没有任何读数。
* 机制：字面两通道空手时，语义腿仍会给一个最近邻，且只要余弦 ≥ `MinimumScore 0.45`
  （`MarcusAwakeStorage/src/SqliteStorageAndRagBackend.RagSemantic.cs:44/172`）就升到 `known`。
* **不能简单抬门槛**：0.45 是可调的唯一旋钮，而「这边的人怎么样」的 0.4732
  落在真问题命中区间 0.4708–0.7951 里，抬门槛必砍真题。
* 建议口径（三选一）：① 严格——语义**单腿**命中（字面空手）时不升 `known`；
  ② 折中——可以答，但降级为 `partial` 并显式说「没听过这个说法，最接近的是 X」；
  ③ 接受现状，把三条对照题改成 `known`。
  这条正好落在已经认出来的「判断层入口段（值不值得处理）整段缺席」那个缺口上。
* 另 3 行状态变化是**正向**（本批 `环甲`／`柳条盾` 从 `partial` 升 `known`）。
  另有 152 行状态不变、只是候选池变大（`keyword → hybrid`）。

## 四、发现二：世界书**断言正文不进上线包、也不参与三哈希**

v17 改的是 `assertions[].text`（就是 `prose_qc` 当正文扫的那一面），结果：

* 三个包哈希**一个都没变**；要发运的 `index/manifest/runtime` 与在挂包**逐字节相同**；
* 全库搜 `runtime.json`：**没有**任何一条断言正文。玩家看得见的是 `summary` 与 `expressions`。
* ⇒ ①「改断言正文」这类批次**不需要重新发布**（也不会动包校验）；
  ② 反过来说，只改断言正文**不会**改变玩家听到的话 —— 要让玩家听到，必须落到 expression 或 summary。
* ⚠️ 对拍纪律：**只比 `runtime.json` 会漏掉这类改动**（v17 链第一版就这么误判过，判了自己一个假 FATAL）。
  「改正文」的批次必须比 `documents.json` 那一面；「改表达/关键词/标题」的批次才在 `runtime.json` 面看得见。

## 五、本轮修掉的真缺陷

1. **检索侧（产品代码，`src/WorldKnowledgeQueryService.cs`）**：`FindLiteralCandidates` 原为
   「关键词层命中即独占、兜底通道整个跳过」⇒ **候选集被压成一条**：句子越长、越像人话，
   越容易因一个词碰巧撞上某条目而被它独自接管（实测两次：`腮帮子和耳朵` 5→1、
   `大圆盾扔飞斧` 5→1，后者把 `RETRIEVAL_GATE` 的 B 组打掉一条）。改成两通道并集（keywords 在前、
   兜底去重补齐），既有 `MatchQuality` 位次一字不动 ⇒ 恢复 HIT、`ALL_hit3 18→19`。
2. **本批内容（两处）**：① `torso-ring`／`shield-wicker` 缺「通用 detail 层」
   （19/21 张卡是「a1 rumor＋通用 detail、a2 文化 detail」的写法，这两张例外）⇒
   不带文化的商人/头人/士兵/贵族问它们只拿得到 rumor 层、且 partial 不渲染标题，
   正文变成一段没有出处的口语 —— 矩阵 IWA6／IWA19 两条红的根因；
   ② `torso-civil`／`torso-gambeson`／`torso-mail`／`cape-mantle`／`hands` 两个断言各生成一条
   `<slug>-detail`，**表达 id 重复**（谁按 id 取都只拿到第一条）。两处都已在生成器里加硬断言钉住。
3. **本批文风**：`shield-round` 正文里混进「（一条写着四百三十五的，是**游戏数据**里的孤值）」
   —— 编纂口吻，`prose_qc` 硬项。那个 435 是快照 `armor.southern_oval_shield`
   （强化椭圆盾，盾类大盾）的"长"，不是笔误；已把数字移出正文、只留"另有一路椭圆盾、归大盾档"。
