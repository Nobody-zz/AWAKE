世界书机制 + 世界书编辑器 · 全景梳理

AWAKE（骑马与砍杀2 模组） · 世界书侧 · 2026-09-12 · 现状快照，含实测数据
一句话：世界书是一套「NPC 知道什么、肯说多少」的知识系统。 人负责写内容（中世纪味的客观事实 + 不同身份的说法），机器负责判定（这个 NPC 该不该知道、能说到多细）。 两者之间隔着一套权限契约——那才是世界书的机制本体。

一、三层结构：内容 → 生产 → 运行

二、内容模型：一个词条长什么样

四层嵌套

这套结构是 Max 定的硬规矩的落地：断言是共用的客观内核，表达是按身份分层的说法。同一个事实可以有好几段说法，机器按问话人的身份挑一段给他。

真实例子

# authoring/der-vill.yaml（节选）
assertions:
- id: assertion.der-vill-1
  kind: fact
  text: 德里亚特是卡琉斯堡左近的一座村庄，夹在瓦尔切格湾和埃博半岛之间的山脊上。  # ← 中立内核
  expressions:
  - id: expr.der-vill-1-summary
    layer: summary                                                            # ← 层级
    text: 德里亚特是卡琉斯堡左近的一座村庄，夹在瓦尔切格湾和埃博半岛之间的山脊上。  # ← 这一层的说法
    grants:
    - profile_id: profile.commoner   # 平民
      scope: regional                # 在本地区域内
      min_detail: summary            # 至少知道到 summary 这一层
    denies: []

三个旋钮：决定"谁能知道多少"

layer · 知道多细

unknown → rumor → summary → detail → secret
（由浅到深五档）

scope · 知道多广

local → regional → national → faction → elite → private

conditions · 具体是谁

文化 / 王国 / 聚落 / 角色 / 性别 / 是否族长 / 年龄 / 管理等级 / 技能

另有一个独立维度 profile（身份，共 12 个）：村民 · 市民 · 平民 · 头人 · 乡绅 · 商人 · 酒馆老板 · 赎金经纪人 · 士兵 · 贵族 · 贵族总管 · 身份未知。

判定顺序：Deny > Grant > 继承 > 未知

另外还有 转介（referral）：NPC 不知道时不是沉默，而是指路——"这方面我不清楚。你可以去问：……"。登记表现有 4 条（公证商人 / 赎金经纪人 / 酒馆老板 / 头人）。

两条创作路径

A · 单份（Quick Authoring）

导入资料 → 填"我想整理什么" → 选内容范围 → 生成草稿 → 看来源和警告 → 逐条人工采纳 → 创建待审核档案 → 补二级主题/权限/时代 → 保存

B · 批量

扫描资料 → 提升为批次 → 勾选读取范围（不勾就不读）→ 提取事实 → 逐条人工审 → 生成草稿 → 回编辑器补字段保存

额度：最多 200 文件 / 总 64 MiB / 单文件 16 MiB / 单单元 8 万字符；并发本地 1、云端默认 2。有租约防并发打架，结果不确定的项记「待确认」需人工确认。

共同的铁律：
  • AI 草稿必须逐条人工采纳，改了字要重新采纳，绝不自动写入正典。
  • AI 建档后一律 needs_review。不会因为你点了生成就自动发布、自动同步游戏。
  • 不配 API Key 也能用「先做本地检查」查空字段、占位、权限问题。

权限链 Authority Gate：为什么要点"申请授权"

这么重是为了防止未审核 / 已改动的内容混进游戏包，且崩溃重启能 fail-closed、不产生半成品。编辑者会撞到它，但 UI 已包成一步——点「申请编译授权」自动串起四连，成功后编译/导出按钮才亮。

六、做内容时必须记住的硬约束

  1. 锚点两类不可混：游戏里有同名对象的 → entity.settlement.*；游戏里没有的 → 才用 entity.lore.*。出处 B9 + ID-MIGRATION-CONTRACT。
  2. 实体 ID 一律小写（entity.settlement.town_v7），游戏原生写法是 town_V7——别照抄。
  3. 动基线数据前先查是否被 golden 钉死：grep -rin <哈希前8位> --include=*.cs --include=*.json。被钉死 → 属跨线批次，别在内容侧硬做。
  4. AI 草稿必须人工逐条采纳，改字要重采纳；AI 不会自动发布。
  5. 知识要分层：内核绝对中立，观感按身份分层；管理等级高 = 更渊博，不是更"科学"；严禁现当代科学视角。
  6. 不为拆分而拆分——按边界拆，不按数量拆。
