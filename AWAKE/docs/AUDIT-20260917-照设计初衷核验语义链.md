## 〇 一句话结论

**第 1 层受它管（没破）｜第 2 层它方向相反｜第 3 层它不碰。**

⇒ 今天量到的 `19 → 23`（hit@3）只是「**取数段的健康度**」，**不能当成败标准**；

## 一 第 1 层「谁知道」：闸门仍然有效，而且它在语义臂的**下游**

### 1.1 代码：融合只决定先后，"过不过得去"由逐条筛

| 位置 | 做什么 |
|---|---|
| `src/WorldKnowledgeQueryService.cs:59-68` | 语义臂在锁外跑，拿回 id 列表；`FindCandidates` 把两臂**融合**成一个候选序 |
| 同文件 `:76-100` | 拿到候选序之后**逐条**过 `HasMatchingDeny` → `SelectExpression`：身份不够 → `PermissionLimited = true` → `continue`，**进不了答复文本** |
| 同文件 `:101-114` | 一条都过不去时，才落到 `blocked / referral` |

⇒ **融合只改"谁先谁后"，不改"谁能进来"。语义臂不是权限来源。**

### 1.2 实跑：候选表对七个身份**完全相同**，结果只因身份而分

模拟器门控矩阵（同一问句 × 七个身份）挂／不挂语义两次对跑，`diff` 只有 3 行状态差：

| 身份 | 能力上限 | 挂语义前 | 挂语义后 | `awake:entry:war.troops-mamluk` 里给它授权的表达 |
|---|---|---|---|---|
| `profile.soldier` | national / detail | `not_found` | **`partial`** | `identity_id: soldier`／`scope: national`／`min_detail: detail` |
| `profile.noble` | elite / detail | `not_found` | **`partial`** | `identity_id: noble`／`scope: elite`／`min_detail: detail` |
| `profile.merchant` | faction / detail | `not_found` | **`partial`** | `identity_id: merchant`／`scope: faction`／`min_detail: detail` |
| `profile.commoner` | local / rumor | `not_found` | `not_found` | ——（没有它的 grant） |
| `profile.headman` | national / detail | `not_found` | `not_found` | ——（身份 id 不在 grant 里） |
| `profile.notable` | regional / detail | `not_found` | `not_found` | ——（没有它的 grant） |
| `profile.anonymous` | （无能力） | `not_found` | `not_found` | —— |

⇒ 发生变化的**恰好就是条目自己 grant 里点名的那三个身份**；另外四个一行没动。
⇒ 语义臂送回的是**同一张候选表**（它不看身份），**结果却按身份分岔** —— 这就是"闸门在下游且有效"的直接证据。

### 1.3 ★ 缺口：这一维今天**不在验收里**

| 事实 | 出处 |
|---|---|
| 门禁验台**从目标条目自己的 grants 里挑一个身份**去问，注释原话「保证目标可被吐出来，否则测到的是权限而不是检索」 | `tools/worldbook-runtime-smoke/RetrievalProbeCases.cs` 的 `PickIdentity(snapshot, target)` |
| 24 条题集的唯一数据源里，`identity` 出现 **0 次**（**这是"补之前"的读数**；09-17 晚复核：`grep -c identity` = **16**，因为当晚补了 `allowedIdentity`／`deniedIdentity` 字段，见 §四.2） | `tools/_retrieval_cases_20260916.json`（当时 `grep -c identity` = 0） |
| 另一条对照查询固定用低权限身份 | 同文件 `RunQuery`：`IdentityId = "awake:identity:commoner"` |

⇒ **现有全部数字（字面 19／语义 22／合并 23，hit@3）在"谁知道"这一维上是盲的** ——
按设计，**身份不被允许成为失败原因**。
（这正是 `DECISION-20260917-设计初衷…` §二 第 1 条点名的那件事。**今天复核：还在。**）

## 二 第 2 层「何时知道」：仍是空的，而且语义臂的**方向与它相反**

### 2.1 入参里没有身份、没有日期、没有来历

`IWorldKnowledgeSemanticIndex.Search(string playerText, int limit)` —— 入参只有**玩家原话**与**条数**
（`src/WorldKnowledgeSemantic.cs:17-20`）。
⇒ 同一条问句，**第一天与第一百天、在场与不在场**，拿到的候选**完全一样**。

### 2.2 语料与模型里根本没有时间字段

| 有什么 | 没有什么 |
|---|---|
| `WorldKnowledgeEntry` 有 `SourceKind`／`SourceId`／`ReportId`／`SourceEventIds`／`SourceFactIds`（**来源**） | **没有** Day／到达日／知情者／公开程度 |
| 448 条 `runtime.json` 里 `source` 出现 1 次 | `day`／`time`／`arrived`／`heard`／`knownBy`／`公开程度` **零命中** |

⇒ 「**他还没听说**」这个初衷里明确要保住的**合法状态**，在这一层**表达不出来**。

### 2.3 ★ 方向相反：向量检索天生把"不知道"搬成"知道"

字面臂一无所获时会**诚实说没听说过**；而**向量检索永远会返回最近的那几条**，只靠 0.45 门槛挡无关话
（量法与依据见 `DECISION-20260917-两条通道怎么合.md` §三）。
⇒ 挂上语义后门控矩阵里 `not_found` **15 → 12**、`partial` **6 → 9** —— 变化的方向就是**拆掉"不知道"**。

### 2.4 ★ 今天唯一那处变化，照初衷看是**变坏**

唯一变化的是提问 `领主`：soldier／noble／merchant 从 `not_found` → `partial`，吐出来的是**马穆鲁克**（奴隶兵）。

⇒ 问"领主"，答"被拥有的人" —— **把一句诚实的"我不知道"换成了一句自信的答非所问**。
⇒ 初衷那条「**答不出常是正确**」，今天**没有任何一处判据在守它**。

## 三 第 3 层「信不信」：没建；而且语义臂的取值方式与它无关

| 事实 | 出处 |
|---|---|
| 融合**只看名次、不碰分数**（只累加 `1/(60+名次)`）⇒ 候选里**没有任何来源／证据参与排序** | `src/WorldKnowledgeSemantic.cs:114-142` |
| 结果里确实带了 `SourceIds`／`ReportIds`，并被抄进决策留痕 | `src/WorldKnowledgeQueryService.cs:96-97` → `src/WorldKnowledgeModels.cs:200-203` |
| 但**全仓没有一处拿它算可信度**；初衷 §十 要的证据枚举公式（`none/specific/corroborated/direct_proof` = `0/5/10/20`）**一处未落地** | 全仓 grep |

## 四 ✅ 那把尺子已经补上了（甲方 09-17「补啊」，当天落地）

### 4.1 新增第二条门禁：`identity-gate`（跑在 `tools/worldbook-runtime-sim`）

```
dotnet run -c Release -- identity-gate <manifest> <cases.json> <out.json>
  带语义臂：AWAKE_SIM_SEMANTIC=1      变异检验：AWAKE_GATE_MUTATE_ASSUME_ALLOWED=1
```

| 判据 | 内容 | 为什么它不是自证 |
|---|---|---|
| **① 阴性扫描（硬）** | 题集 **24 条 × 包内 12 个身份**：目标条目的 `grants` **点不到**某身份（按 `parents` **上溯**闭包）⇒ 该条目 id **不得**出现在 `HitIds` | 只读包里的 `grants` 与 `parents` **两份清单**，**不含** scope/detail 数学；运行时另外还要过 conditions/scope/detail（只会更严）⇒ 两边不是同一套代码 |
| **② 点名题（硬）** | `deniedCases` 5 条：够格身份必须拿到；被禁的那一档必须在够格身份那里**真能出现**过；受限一方必须拿到**低一档**（`requiredText`）且**漏不出细档**（`forbiddenText`） | "他没漏"若不配阳性对照就是恒真 ⇒ 空转 |
| **③ 空转护栏（硬）** | 被排除行、该知道行、"该知道真拿到"行都不许为 0；`deniedCases` 一条都读不到即判红 | 「恒 True＝没测」 |

⚠️ **受限那一方"到底该不该看见"由授权数据判（与①同一个 oracle），不由题面写死。**
第一版我把它写死成"必须看不见"，5 条里当场判红 4 条 —— 那 4 条其实**产品是对的**：
平民本来就该拿到「毛皮值钱吗？」的 rumor 档，只是不该拿到 detail 档。**判据写错会冤枉产品。**

### 4.2 题集补了第三类题：`deniedCases`（5 条，同一问法只换问的人）

| # | 问法 | 够格的一方 | 受限的一方 | 查的是 |
|---|---|---|---|---|
| D1 | `毛皮值钱吗？` | noble → detail（含「毛皮基准价 400」） | commoner → **只配 rumor**（「一张好皮子能顶半个月嚼谷」） | 详细度分层 |
| D2 | `盐是从哪儿来的？` | noble → detail（「盐基准价 40」） | commoner → 只配 rumor | 详细度分层（防单点） |
| D3 | `戴·科尔坦家靠什么发财？` | noble → secret | commoner → **整条拿不到** | 整条不可见 |
| D4 | 同上 | noble → secret（「操办科尔坦家的图谋」） | merchant → **只到 summary**（「海务财富尽归戴·科尔坦家族」） | 公开面 vs 秘密面 |
| D5 | `林·莫德里斯是什么湖？` | villager → rumor；`townsfolk` → summary | commoner → **整条拿不到** | **地域**：村民有、平民没有 |

D5 最尖：`villager`（村民）**拿得到**，`commoner`（无地缘的平民）**整条拿不到**，同一条条目同一问句
⇒ 证明「谁知道」是按**身份 id 与它的父链**判的，不是按"地位高低"排的。
