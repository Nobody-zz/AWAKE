## 二、算法骨架

```
每轮（玩家说了一句话 S，当前持有上一轮的"在场范围" P）：

1) 前置检查（决定这轮是"接着收"还是"重开"）
   若 P 为空                      → 重开：全库开搜
   若 本轮贴合度(S, P) < 阈值     → 换话题：全库开搜
   若 对话对象/聚落变了、或窗口关了 → 清空 P，重开
   否则                           → 接着收（第 2 步）

2) 在 P 内部收窄（不是在全库里收）
   语义臂：只对 P 里的条目算与 S 的相似度   ← 范围小 ⇒ 这一步比现在便宜
   字面臂：只对 P 里的条目做关键词/兜底命中
   合成 → 排序

3) 产出两个不同的东西
   新的在场范围 P' = 排序结果的前 W 条        （W 宽，给"下一轮"用）
   交付条数       = 排序结果的前 N 条        （N 窄，喂模型）

4) 单调保证：P' ⊆ P
   兜底：若 |P'| 小于最小存活数 M，不再收（保持 P），避免越收越空直到死锁
```

**一句话概括**：把"每轮重搜全库"换成"每轮只在上一轮留下的名单里收"，并给它两个放行的口子。

## 三、★ 两个数字必须分开（这是本设计最要紧的一条）

| 数字 | 含义 | 谁来用 | 大小 |
|---|---|---|---|
| **W：在场范围** | 留着给下一轮继续收的名单 | 只有算法自己用 | **宽**（几十条） |
| **N：交付条数** | 真正喂给模型的几条 | 下游 prompt | 窄（1~3 条） |

**为什么要分开**：W 太小 → 下一轮没得收（一刀就炸）；W 太大 → 收得太慢（等于没收）。
**N 才是"玩家看得见的准确度"，W 是"这条路能不能走下去"**。

**就是这里的 W 该看的指标**（在场范围有没有罩住正确答案），而 **`@hit3` 是 N 的指标**。

## 四、两个安全阀（必须有，否则会死锁）

1. **空手回退**：P 为空 ⇒ 必须重开全搜。
   *若不设*：第 1 轮没找到 ⇒ 后面每轮都在空集里收 ⇒ **永久锁死**，玩家怎么问都是"不知道"。
   （同仓已有先例：`AwakeFileStorageService.cs:143` 缺 key 返回 `Succeeded("")`，
   **凡"缺值用默认"都必须另有 `IsNullOrWhiteSpace` 兜底**，否则同样的死锁。）
2. **换话题重启**：本轮的话跟 P 的最高贴合度低于阈值 ⇒ 判定换话题 ⇒ 全库开搜。
   *若不设*：玩家从"北边的河"跳到"皇帝是谁"，会被死死困在河边那几条里。
   （人自己就这样：换了话题，前一个焦点会散。）

## 六、怎么验（做完了拿什么说话）

1. **单调性**：跑一段多轮对话，画出每轮的 |P| —— **必须单调不增**，且在换话题处允许跳回。
2. **空手不死锁**：构造第 1 轮空手的用例，确认第 2 轮能重开（这要**阳性对照**：不修就必然卡死）。
3. **候选序长度**：每题返回几条 —— ★ **实测：3–10 条（均值 6）**。若一直如此，说明"范围"这件事本来就不需要收；
   跨轮累积要等它变宽才划算（见 `docs/AUDIT-20260918-候选序实测.md`）。
4. **成本**：记录每轮比对的条目数 —— 应逐轮下降（对照现在每轮恒定 482）。
5. 三根门禁（`RETRIEVAL_GATE`／`MERGE_GATE`／`IDENTITY_GATE`）**同批复跑、数字变了要能解释**。
