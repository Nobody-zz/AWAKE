## 一 玩家说话 → NPC 回话，实际走的路（**活的**）

入口：`src/NpcDialogueService.cs:1010` `BuildPromptInputAsync`

| 步 | 干什么 | 代码 |
|---|---|---|
| 1 | 把玩家这句话，连同这个 NPC 的身份（文化／王国／聚落／角色／技能／性别／是否族长）打包成一个查询 | `NpcDialogueService.cs:1044-1062` |
| 2 | **内容分级门**：包的档位（`base` / `adult_optional`）与请求对不对得上；不对整条挡掉 | `WorldKnowledgeQueryService.cs:513` `ContentGateAllows` |
| 3 | **找候选（字面，两步）**<br>a) 主路：关键词表，**双向子串**——你这句里含词条的关键词，或反过来<br>b) 一条都没中，才走兜底：按「共享的字」捞，**最多 5 条**（`FallbackMinSharedTerms=1`／`FallbackMaxCandidates=5`） | `WorldKnowledgeQueryService.cs:353` **`FindLiteralCandidates`**<br>`:395` `FindFallbackCandidates` |
| 4 | **排序**（四级）：标题正好是你问的 → 别名/关键词正好是 → 标题互相包含 → 只沾到关键词；同级比匹配串长短，再按 id 稳定排 | `WorldKnowledgeQueryService.cs:426` `MatchQuality` |
| 5 | **权限／身份筛**：按 grants／denies／能力，判断这个 NPC「该不该知道、能不能说」。不通过 → 挡掉（`blocked`）或给「这方面的我不清楚，你可以去问某某」（`referral`） | `:443` `HasMatchingDeny`／`:453` `SelectExpression` |
| 6 | **拼成一块文本**，上限 `MaximumBytes`（默认 4096 字节），按第 4 步的顺序装，装满即断 | `:98`（循环里的 `ByteBudget` 判断；取值见 `:70`） |
| 7 | 交给 `WorldKnowledgeDecisionPolicy.Create` 出决策；**若 `AllowsAi == false`，直接 return，AI 请求根本不发** | `NpcDialogueService.cs:1110-1128` |
| 8 | 决策块经 `BuildPromptBlock` 变成 prompt 变量 **`retrieved_knowledge`** | `NpcDialogueService.cs:1129`／`:1172` |

**结果状态共五种**（`WorldKnowledgeModels.cs:155-159`）：`known`（答得出）／`partial`（只有摘要、细节不够）／`referral`（转介绍）／`blocked`（挡掉）／**`not_found`（一条都没中；默认档，也是最常见的那档）**。
（⚠️ 09-17 晚红测更正：原稿写"只有四种"，**漏掉了 `not_found`** —— 而下一节 §四 的真机日志里 `state=` 恰恰就是它。默认值定义见 `WorldKnowledgeModels.cs:104`。）
`MatchMode` 只有两个值：`keyword`／`identity`（候选为空时，`WorldKnowledgeQueryService.cs:75`）。

## 五 所以：这条链路现在长这样

```
玩家说一句话
   │
   ▼
[分级门]  ── 不过 ──► 挡掉
   │
   ▼
[字面找候选]  关键词双向子串 ── 全空 ──► 共享字兜底（≤5 条）
   │                                            │
   └──────────────┬─────────────────────────────┘
                  ▼
            [四级排序]
                  ▼
           [身份/权限筛] ──► blocked / referral
                  ▼
        [拼块 · 上限 4096 字节]
                  ▼
   AllowsAi? ── 否 ──► 不发请求
        │ 是
        ▼
   prompt 变量 retrieved_knowledge  →  云端模型

────────── 进程边界 ──────────
[服务进程] SqliteStorageAndRagBackend（FTS5）
           └ Hybrid / Semantic：返回「不支持」
           └ 调用方 KnowledgeService：**从未被构造**
```

## 六 这意味着什么

1. ~~**语义层不是"调优"，是"新增一个现在完全不存在的能力"。**~~
   **09-17 晚更正：这条已过期** —— 语义层当晚就落地了（见 §三），原话只对 09-17 白天成立。
   前一份调研给出的「换成 `bge-base-zh-v1.5`」仍然是给这条链路**补一层**，不是换一零件。
2. **有两条路可选，且都已有一半**：
   - **A 路（世界书内）**：在 `FindCandidates` 旁边**并列**加一条语义路（改动小、与现有四级排序并存）
     —— 但这一层跑在**游戏进程内**，模型会挤进游戏进程的内存。
   - **B 路（服务进程内）**：把 `SqliteStorageAndRagBackend` 的 `Hybrid`/`Semantic` 实现掉
     —— 好处是模型与推理都在**独立进程**（`DECISION-20260916` §一.5 的形态），游戏进程干净；
     代价是**要先把 `KnowledgeService` 这条（现在死的）调用链接上**。
3. **不管走哪条，都得先解决"玩家换个说法就找不到"** —— 这是真机唯一一条记录暴露出来的东西。
