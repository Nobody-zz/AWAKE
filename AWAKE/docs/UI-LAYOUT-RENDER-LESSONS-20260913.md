## 0. 先定性质：参考是"场景模拟"，我们是"文字界面"；但 **安静 ≠ 空洞**

⚠️ 本节 09-13 夜被用户**连纠两次**，两次都留在文里（不让后人重犯）：

1. **第一次纠偏**：参考 B 是**场景模拟**类模组 —— 图是主角、字是配角，主打用图撑沉浸。
   **AWAKE 现在做的是对话 + 写信**，是**文字承载**的界面，正文本身就是内容。
   ⇒ **不能整屏照搬**：拿它的手艺，不拿它的主张。
2. **第二次纠偏（更关键）**：「安静、不喧哗」**不是**「无趣、空洞」。
   我第二版为了守基线矫枉过正，把图压成"只做小锚点、字最亮、整屏大图不做" ——
   **那等于把"安静"做成了"什么都没有"。**

⇒ 真正的口径只有一句：

> **安静 ＝ 低对比、不抢戏、有秩序。**
> **安静 ≠ 无内容。** 要判的不是"图多大"，而是**两条判据**（见 §2.0）。

| 维度 | 场景模拟（参考） | AWAKE（对话 / 写信） | 拿不拿 |
| --- | --- | --- | --- |
| 图的作用 | 空间，撑沉浸（**调门偏高**） | **空间或锚点都行，但必须安静** | **拿手艺，调低调门** |
| 界面主体 | 图 | **字**（字必须始终可读） | — |
| 中栏 | 大图 | **对话正文**（要放图就放"安静的大图"） | 拿分区，**图降调门而非删除** |
| 3D / 人物卡横排 | 有 | 无 | **不拿**（不是"不好"，是本层做不了、且我们的场景不是模拟） |
| 选中态 · 元信息一行 · 底部状态行 | 有 | 缺 | **拿** |
| 文本分层（动作 / 台词 / 说话人） | 有 | 缺 | **拿**（对对话 UI 是核心增益） |

⇒ 本文以下一律分清：**[通用]** 的手艺可以搬；**[场景模拟专有]** 的**调门**要降、**素材**要换。

## 1. 四种"用图"的形态

| 形态 | 做法 | 图扮演 | 调门 | AWAKE |
| --- | --- | --- | --- | --- |
| **甲 · 图在面板里** | 面板内切一格放图（参考 A） | 内容 | 中 | 可用（如信笺那一格） |
| **乙 · 图当背景** | 整屏铺图，UI 浮在上面 | 空间 | **取决于图本身** | ⚠️ **可用，但必须是"安静的大图"** |
| **丙 · UI 浮在真 3D 上** | 真实场景 + 半透明 UI | 世界 | 高 | ❌ 本层做不了 |
| **丁 · 图当锚点** | 小图嵌进文字流：头像 / 立绘 / 物件 / 印鉴 | 锚点 | 低 | ✅ 可用 |

**关键：乙 的成败不在"大"，在"安静还是喧哗"。** 同样铺满整屏，两种东西完全不同：

- **喧哗的大图**：高对比场景画、有高光、有明确主体（一张"画"）⇒ 视线被拉走，正文读不动。
  **这是场景模拟要的，不是我们要的。**
- **安静的大图**：低对比的**连续质感** —— 石面的颗粒、纸的纤维、墙面的斑驳、极弱的氛围过渡。
  它不"画"什么，它**给地方**。⇒ **这才是 AWAKE 该用的"整屏图"。**

⇒ 一句话：**我们要的不是"把图删掉"，是"把图改成不会喊的那种"。**
（第一版照搬了场景模拟的**素材**，第二版把**素材和手段一起删了** —— 两次都错，错在把"调门"与"有没有"混为一谈。）

**参考 A 与 B 的内部分歧也正在此**：A 把图关在一格里（图是内容，近甲），B 让图铺满（图是背景，是乙）。
⇒ **A 更接近我们的排版，B 的手法是通用的**；两边的图**都得先降到"安静"那一档**再拿来用。

## 2. 布局经验（8 条，都从两份参考里拆出来的）

### 2.0 两条判据："安静"与"空洞"的分界（本节统领，也统领全篇）

| 判据 | 怎么问 | 通过 | 不通过 |
| --- | --- | --- | --- |
| **① 有物** | **把文字全遮掉**，还看得出这是什么吗？ | 看得出是"一封信 / 一块碑 / 一间屋子 / 一个人" | 只剩一片深色 + 几条线 ⇒ **空洞** |
| **② 不抢戏** | 正文读起来费不费劲？ | 图低对比、有暗角或衬底，**字始终最亮** | 图有高光、高对比、明确主体 ⇒ **喧哗** |

⇒ **两条都过 ＝ 安静。过①不过② ＝ 喧哗。过②不过① ＝ 空洞。**

**为什么把这条放在最前面**：本层最容易犯的两个错，正是这两个方向的偏离 ——
一边照搬场景模拟的调门（喧哗），一边为了"守基线"把界面做空（空洞）。
**有了判据，就不必靠感觉反复横跳。** 每次交付前，遮掉文字看一眼即可自检。

**推论（可操作）**：
- "低对比"**不等于**"纯色块"。纯色块 + 细线 + 文字 ＝ 判据①不过 ＝ **空洞**。
- 我们 M0 的 `panel_main_1280` **是过的**（暗石板有颗粒、有切角、有内衬线 ⇒ 遮掉文字仍是一块"石板"）。
  这就是"安静但不空洞"该有的样子，**是标尺，不是例外**。

### 2.1 四块分区口诀

```
左：谁在场 / 在哪       中：看得见什么         右：说了什么
------------------------------------------------------------------
底：我怎么说（输入）+ 状态说明一行小字
```

参考 A 与 B **都落在这一格局上**（A 左=联系人列、中=图、右=对话；B 左=环境描述+动作、中=场景、右=地点列表）。
⇒ 这是这类界面的**稳定解**，不必另创。

### 2.2 层级靠"尺寸差"，不靠颜色

两份参考里，**标题都小而弱**（地名/栏名），**内容都大而强**（对话正文、场景）。
颜色只承担一件事：**金＝可操作/当前**。其余全靠字号与留白拉层级。
⚠️ 这条对我们**格外要紧**：`NativeLanguages.xml` 把简体中文全映射到 `simkai`（楷体），
**我们没有"衬线 vs 无衬线"这一维可用**（详见画风基准 §1.5）⇒ 层级只能靠字号/颜色/装饰线/留白。

### 2.3 选中态是这类界面的"主心骨"

两份参考都把"当前选中"表达得很重：
- 参考 A：左栏选中项＝金框 + 底色块；
- 参考 B：右栏选中行＝金色圆点 + 整行高亮。

⇒ 别用"变亮一点点"表示选中。**选中＝加框 + 加底 + 换个明确的金**，三件一起上。

### 2.4 文本层面就分层：动作 / 台词 / 说话人

参考 A 的对话流里：**斜体灰＝动作描写**、**引号＝台词**、**金色＝说话人名**、**主色＝玩家**。
—— 这是**纯排版**就能做到的事，成本极低，观感提升极大。
⚠️ **我们这个还没做**（当前对话流是单一颜色一种字号），是性价比最高的一条。

### 2.5 元信息用"竖线分隔排一行"

参考 A 的头带副标题：`靠窗长桌｜夜晚｜城中刚刚解除围困`（三个维度压一行）。
比三个小标签省地方、也比标签串好看。**竖线用弱色，文字用次要色。**

### 2.6 每栏都有"自己的小标题"

参考 B：左栏「当前位置·公共长桌」、右栏「你眼中的酒馆」「场景状态」、中栏无标题。
⇒ 小标题**小而弱**（次要色、不抢戏），只是给这一栏"命名"，别做成大标题。

### 2.7 底部永远有一行"状态说明 / 计数"

- 参考 A：`本次记录独立保存；离开后可在历史中只读查看`
- 参考 B：`已选择 1 人 · 最多 3 人`

⇒ **零成本、高感知**：告诉玩家"这界面在干什么、我能选几个、数据存不存"。
我们已有类似的（空状态提示），但没有"计数/说明"这一层。

### 2.8 反例：**别把"设计说明"画进界面**

参考 A 最底部那排 `①谁在场 ②人和地点 ③正在聊什么 ④玩家怎么回应 ⑤需要时再展开`
**不是 UI，是设计标注** —— 那是给看图的人解释每块在干什么的。

**但它本身是好东西**，因为它是这类界面的**信息架构检查表**。对照我们的实现：

| 那 5 步 | 我们靠什么实现 | 现状 |
| --- | --- | --- |
| ① 谁在场 | 联系人列表 / 在场人物 | ✅ 有（信使在左栏；对话面板无） |
| ② 人和地点 | 头带 + 副标题（元信息一行） | ✅ 有（可再加"地点/时间"维度） |
| ③ 正在聊什么 | 气泡 / 对话流 | ✅ 有（**缺 2.4 的文本分层**） |
| ④ 玩家怎么回应 | 输入区 + 按钮 | ✅ 有 |
| ⑤ 需要时再展开 | 历史模式（只读） | ✅ 有 |

⇒ **结论：这 5 步我们已有 5/5，缺的不是结构，是"表达"**（分层、选中态、图、状态行）。
这条很重要：**不要为了学参考 A 去推翻结构**，去做那四件表达的事。

## 3. 渲染经验（10 条）

### 3.1 它在流水线里的位置（顺序错了必返工）

```
① 线框（定格子）  →  ② 定死尺寸（真实像素）  →  ③ 渲染（照尺寸出图）  →  ④ 回填复核  →  ⑤ 进游戏
```

⚠️ **渲染图的输入必须是"已定死的格子尺寸"。** 先出图再排版 = 图的比例/留白跟框对不上，必返工。
⇒ 出图前，界面那格必须已经是一个**带尺寸的空框**。

### 3.2 渲染图进游戏＝一张 sprite，**没有技术风险**

它走我们已有的 Brush 层（`GUI/Brushes/AwakeBrushes.xml` + `GUI/SpriteParts/`），
和现有的 `panel_main_1280` 是**同一类东西**。不需要相机、不需要 3D、不需要动模组主干。

### 3.3 真正的三个难点（都不是技术，是"控制"）

| 难点 | 症状 | 压法 |
| --- | --- | --- |
| **量** | 图要随什么变？一变就爆炸 | 见 3.4 |
| **一致性** | 同一角色跨图变脸 | 见 3.5 |
| **边缘** | 抠透明底抠不干净（发丝/半透明） | 见 3.6 |

### 3.4 量的口径：**图随场景变，不随人变**

- 随**场景/地点**变 ⇒ 每地点 1 张，是个有限集，可控。**先用这个。**
- 随**说话人**变 ⇒ 人物数 × 场景数，会爆（本项目角色卡有 76 张）。**不要一开始就走这条。**
- 人物需要"露面"时，走另一条**小图路线**：头像/半身立绘（尺寸小、可复用、可跨场景）。
⇒ **大图管环境，小图管人** —— 两条线分开，谁都别越界。

### 3.5 一致性靠"参考图锚"

同一角色跨图不变脸 ⇒ **固定一张立绘当参考**，后续只做局部重绘/换姿势，不要每次从零生成。
同理，**整套图要有"一张母图"当风格锚**（色调/笔触/光源方向），否则十张图十个调子。

### 3.6 边缘：插画**不抠底**

- 首选**整格带背景**出图，靠"暗角 + 暗边"把边缘压进面板 —— 这**正好符合我们的暗石板 UI**。
- 真要透明底，只用在**头像**这种小尺寸上，且四周留 2–4px 暗边。
⇒ **别指望在整幅场景图上抠人物。**

### 3.7 明暗：调门定生死 —— **图要看得见，字要更亮**

我们的 UI 是暗的（`bg.panel #181010`）。因此：

- **图要看得见**：图**自身**必须有明确明暗结构（暖光 / 侧光 / 颗粒），否则落在暗底上会"沉掉"，白花一张图；
- **字要更亮**：**正文永远是最亮的一层**（`text.primary #F2EDE4`）；
- ⚠️ **"安静的大图"不等于"暗的大图"**：安静＝**对比低**，不是**亮度低**。
  一张亮度中等、对比平缓的纸面 / 石面 / 墙面 —— 既看得见又不抢戏，**这才是目标档位**。

⇒ 一句话：**图的亮度可以接近字，但对比不能压过字。**

### 3.8 要避开的四类"AI 味"

1. **过度光泽/塑料质感**（皮肤反光、金属镜面）
2. **过饱和的金**（金要暗、要旧、要细）
3. **对称完美的构图**（骑砍是歪的、糙的）
4. **无意义的景深虚化**（为虚而虚）

⇒ 要的是**钝、糙、暗、不对称、有灰尘**。

### 3.9 分辨率口径

按**最终显示尺寸 ×2** 出图（给九宫格与未来放大留余量）；**别 ×4 生成再缩**（丢细节 + 白花额度）。

### 3.10 授权与登记

AI 生图进模组要问清**模型授权**（能否商用/再分发）。
每张图登记**来源与提示词**，方便日后要换/要重出时能复现。
⚠️ 图片**不进 git**（体积），进 `docs` 登记路径 + 放 `out/`。

## 4. 渲染做不到的四件事（边界，别越界）

| 渲染**不能**做 | 为什么 | 该谁做 |
| --- | --- | --- |
| 替你决定**信息架构** | 图再美，分区错了还是难用 | 本层（框架文档） |
| 生成**文字** | 硬规矩：sprite 里绝不能烤文字（中文 fallback + 多语言） | 文字一律由控件渲染 |
| 做**可切状态的按钮皮** | 那是精确的九宫格工艺，四态边距要逐字节一致 | 手工/矢量（美术线） |
| 当**最终界面** | 一张图是"画"，不是"界面"，Bannerlord 不吃图当 UI | 必须回填成 sprite + Brush |

⇒ **渲染的唯一正位＝整格的氛围/场景/人物图**（分类表里的 C6 类 + 对话中栏大图）。
别拿它当万能工具。

## 5. 对 AWAKE 的落地含义（按价值排序）

> ⚠️ 本节 09-13 夜改过**两次**：初稿主张"整屏场景图、弹窗变场景"（照搬场景模拟）；
> 二稿又把图压成"只做小锚点、大图不做"（矫枉过正成空洞）。
> **下面是第三稿 ＝ 按 §2.0 两条判据收敛的结果。**

**核心：不是"要不要图"，是"图要安静，且必须过判据①（不许空洞）"。**

1. **§2.4 文本分层**（斜体灰＝动作、引号＝台词、金＝说话人、主色＝玩家）。
   **零外部依赖、纯排版、对"对话界面"是核心增益。** 当前对话流是单一颜色一种字号 ⇒ **最该先补的第一件事。**
2. **§2.0 判据自检**：每次改完界面，**遮掉文字看一眼** —— 若只剩深色块 + 几条线，回去加质感/加"物"。
3. **§2.3 选中态**（加框 + 加底 + 明确金，别只变亮）—— M1 的 `contact_item` 到货即可做。
4. **§2.7 状态说明行**（计数 / 数据存不存）+ **§2.5 元信息一行** —— 都是零成本。
5. **用图：形态乙与丁都可用，按判据调门**：
   - **写信界面（信使）** → **信笺质感**：纸面纤维 / 折痕 / 封蜡 / 印鉴。
     这是**大面积**的图，但属**安静的大图** ⇒ 正是"不空洞"该有的样子。**性价比最高的一处用图。**
   - **对话界面** → **头像 / 半身立绘**（回答"谁在说"）；面板底沿用现有石板质感（已达标尺）。
   - **整屏背景** → ✅ **可做**，前提是**安静的大图**（连续质感：石面 / 墙面 / 纸面 / 极弱氛围），
     **不是**高对比场景画。⚠️ 且必须**真机验过正文可读性**（现未验）。
6. **§2.8 的结论**：5 步架构我们 **5/5 都有** ⇒ **不要为学参考去推翻骨架**，只做"表达"。

⚠️ **全屏遮罩 `BlankWhiteSquare_9` 的处置（随本条第三次改）**：**不急着换，但不封死。**
它本身是纯黑洗色、判据①不过 ⇒ 属于"空洞"那一侧，**所以它确实是"该被质感替换的那一块"**；
但替换的前提是第 5 条那个"安静的大图"—— **先出图、先真机验可读，再换。** 现在不动。
