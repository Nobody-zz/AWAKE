## 一、硬伤：12 个职业永远匹配不上，掉进「匿名」

### 1.1 机制：驼峰 vs 下划线

游戏把职业交给运行时是一个**枚举**（`TaleWorlds.CampaignSystem.Occupation`，33 个成员）。
代码把它变成字符串用，然后拿**字符串**去比对一张表：

| 环 | 位置 | 做了什么 |
|---|---|---|
| 取 | `BannerlordWorldbookIdentityAdapter.cs:82` | `hero.Occupation.ToString()` ⇒ `"RansomBroker"`（**驼峰**） |
| 归 | `WorldbookIdentityCapabilityRules.cs:128-136` | `NormalizeRole`：只 `ToLowerInvariant()` ＋ `-`/空格换下划线，**不拆驼峰** ⇒ `"ransombroker"` |
| 比 | 同文件 `:25-73` 的 `switch` | 表里写的是 `case "ransom_broker":` ⇒ **对不上** |
| 兜 | 同文件 `:71-72` | `default: return Unknown();` ⇒ `profile.anonymous` |

★ `WorldbookIdentityEvaluator.cs:115-123` 里**还有一份** `NormalizeRole`，行为与上面一模一样，同一个毛病。

### 1.2 落空清单（探针输出，机械化比对，无手抄）

**真落空 15 / 31 个职业**（已扣掉 `Lord` 这个误报 —— 它在调用点第一步 `IsNoble` 就被接住了，见 `:20-23`）。
其中 **12 个属于纯归一化错配**：表里明明写了下划线版本，只是永远匹配不上。

```
GoodsTrader→goodstrader      (表里: goods_trader)
RansomBroker→ransombroker    (表里: ransom_broker)
HorseTrader→horsetrader      (表里: horse_trader)
TavernWench→tavernwench      (表里: tavern_wench)
TavernGameHost→taverngamehost(表里: tavern_game_host)
GangLeader→gangleader        (表里: gang_leader)
RuralNotable→ruralnotable    (表里: rural_notable)
PrisonGuard→prisonguard      (表里: prison_guard)
ShopWorker→shopworker        (表里: shop_worker)
BannerBearer→bannerbearer    (表里: banner_bearer)
CaravanGuard→caravanguard    (表里: caravan_guard)
ShipWright→shipwright        (表里: ship_wright)
```

**另外 3 个表里根本没有**（属内容／映射缺口，不是归一化问题）：`ArenaMaster`、`Bandit`、`Special`。

★ **规律**：单词语的枚举名（`Merchant`、`Guard`、`Gangster`、`Musician`）全部正常；**凡是多词驼峰，全部落空。**

### 1.3 后果：匿名 ⇒ 一条知识都拿不到

- `Unknown()` 给出 `profile.anonymous`，`IdentityId` 随之变成 `awake:identity:anonymous`；
  而 `snapshot.Identities` 里**确实有**这个身份（`WorldbookLoader.cs:99` 按原 id 建键）
  ⇒ `WorldbookIdentityEvaluator.cs:34-36` 走 `hasKnownExplicitIdentity = true` 那一支，
  `IdentityIds = {awake:identity:anonymous}`，**角色身份表不再补任何东西**。
- **实测（机械统计上线包）**：`awake:identity:anonymous` **只出现在 `denies` 里，从不出现在 `grants` 里**。
  十种被授予的身份里没有它。
  ⇒ **匿名角色在 461 条、1050 条说法里，拿不到任何一条。**
- 且**没有任何日志**。`npc_dialogue_knowledge_decision` 会记 `identity=profile.anonymous`，
  但那只是一行普通日志，没有人会去看，玩家只会觉得「他什么都不知道」。

### 1.4 ⚠️ 一处我先猜错、后来纠正的：匿名不是"被硬拒"

`SelectExpression`（`WorldKnowledgeQueryService.cs:476-516`）在身份不匹配时是
`:487 continue` **直接跳过、不设 `PermissionLimited`**。
⇒ 匿名角色**不会**被判成"权限受限"，也就**不会**走到「这不是我该知道、也不是我该说的」那句写死台词。
⇒ 它的实际表现是 **永久 `not_found`**（关键词命中与否都一样），
   09-18 拆开之后 `not_found` 会放行 AI ⇒ 玩家看到的是"一个什么都不知道、但很会聊的 NPC"。
**这一条我第一遍推成了"被硬拒吐台词"，是错的。写在这里免得下一个人照错的去查。**

### 1.5 已核到游戏数据：这些职业是真的

- `Occupation="GoodsTrader"` 挂在 `SandBoxCore/ModuleData/spnpccharacters.xml` 里 **`is_hero="true"`** 的 Trader 身上
  （另有 SandBox `spspecialcharacters.xml` 的 "Nervous Caravanmaster"）。
- `Occupation="RansomBroker"` 真实存在（`is_hero="false"` 的 Ransom Broker）。
⇒ **受影响的是真人：商人英雄、马贩、赎金经纪人、酒馆女侍、狱卒、旗手、商队护卫……**

### 1.6 ★ 同一件事、两把尺子：一处做对了

`AwakeUnnamedProfileService.cs:39-83` 的 `RoleLabel(Occupation)` **直接 switch 枚举**，
覆盖 23 个职业，而且 `:53-56` 明确把 `Merchant`／**`GoodsTrader`**／**`HorseTrader`** 一起译成「商贩」。

⇒ **同一个 NPC，提示词里写着「帝国的商贩」，而检索侧当他是匿名、一条知识都不给。**
这不是"缺功能"，是**两条链对同一个枚举用了两把尺子**——一把按枚举、一把按字符串。
（另一把尺子还有个小的：`RoleLabel` 自己也有 9 个职业落到 `default: "路人"`：
`Lord/Bandit/Wanderer/PrisonGuard/Gangster/BannerBearer/CaravanGuard/Special/ShipWright`。
其中旗手／商队护卫／狱卒若被 `IsSoldier` 先接住（`:31-32`）就没事，**这一点没逐个核**。）

### 1.7 讽刺的地方

## 二、身份分层实际只有两档（**内容侧，属世界书线**）

机械统计上线包 1050 条说法：

- 一共 **34 种身份组合**，但 **83% 压在两种**上：
  - **437 条**＝十个身份一起给（谁都能听）
  - **431 条**＝只给 `headman` / `merchant` / `noble` / `soldier` 四个（上层能听）
- 真正的职业分辨力很小：`noble` vs `soldier` 只有 **30 / 24** 条能区分（约 5%）；
  `villager` vs `townsfolk` 只有 **52 / 40**（约 9%）。
- 「不该知道」的硬拒绝（`denies`）：**3 / 1050（0.3%）**，其中 2 条 deny `anonymous`、1 条 deny `tavernkeeper`。
- 指路：上线包 **4 条**，四条的 `reason` 还是同一句「可公开询问的知识面广人物」；试点包 **0 条**。

⇒ 设计上有"身份·阶层·专业"三个维度，**内容上实际只做了「上层能听／人人能听」**。
所以大多数时候身份根本不产生"他不知道"——因为给的就是谁都能听的说法。
**（这一节是世界书线的盘子，本文件只报数，不动内容。）**

## 三、表述侧与检索侧的不对称

### 3.1 无名 NPC 有的，英雄没有

| | 身份串（进提示词的 `npc_identity`） | 那条身份约束 |
|---|---|---|
| **无名 NPC** | `名字，<文化><职业>，性别，约<岁>岁。`（`AwakeUnnamedProfileService.cs:8-17`） | **有**：`你是无名角色，不是有名英雄；你只了解自己的身份、所处地点与日常见闻，不掌握领主账目、王国机密或超出身份的信息。`（`:19-24`） |
| **有名英雄** | `名字，性别，文化`（`NpcDialogueOutput.cs:164-172`） | **没有**：`BuildStateConstraint` 对英雄直接 `return string.Empty`（`:22`） |

⇒ **越是有名有姓的英雄（领主、名门、商人头目），给他的身份材料反而越薄**，连"不掌握超出身份的信息"这句都没有。
而那句约束**正是**「按身份表述自己不知道」这句话在代码里的唯一一处落地（`NpcDialogueService.cs:1167-1173` 拼进 `npc_state`）。

### 3.2 更正我 09-18 说宽的一句

我在 09-18 的回复里说「阶层、职业、年龄、技能一个都没进提示词」。**这话说宽了。**
`WorldKnowledgeDecisionPolicy.BuildPromptBlock`（`WorldKnowledgeModels.cs:269-275`）在有知识的那一轮
**是把身份写进知识块的**：

```
知识状态：known ／ 身份：profile.noble ／ 知识范围：elite ／ 允许详细度：detail ／ 命中档案：… ／ 知识正文：…
```

真正的问题是：**`not_found` 时整块返回空串 ⇒ 这份"我知道多大范围"的自知跟着一起没了。**
同一个 NPC：有知识时知道自己是谁、能说多细；没知识时不知道。
⇒ 要它"按身份说自己不知道"，缺的恰恰是**没知识那一轮**的这份自知。

### 3.3 机器词表直接喂给模型

上面那三个字段是**英文机器名**（`profile.noble` / `elite` / `detail`），
人格模板进提示词用的也是英文 token（`[PERSONA_CONSTRAINTS] TOKEN=CONSTRAINT_NO_UNSUPPORTED_FACTS …`，
其中一条正是"不许编无依据的事实"）。**模型能不能读懂这些 token，我没核**（§五）。
