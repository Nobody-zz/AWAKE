### 2.3 ⭐ 核心架构决定：政治制度 / 文化 **分开**，且政体**不绑死**

> **本节架构分析仍然全部成立**（甲方第一轮指示）。执行优先级按 §2.4 收缩（架空暂缓）。

> 甲方原话（第一轮）：「政治制度和文化最好分开，虽然游戏内暂时没有锚点，但不代表后面本模组不会做机制。
> 例如，玩家扮演巴旦尼亚王国（部落制政体），但学习了帝国先进制度后改组为封建制王国。
> 这说明政体最好不要绑死。玩家如果想要架空政体或者在游戏里体验神权、商人共和国等等特殊政体
> 也有充足扮演空间。」

**注意：甲方说的「游戏内暂时没有锚点」，实测已取得机械证据** ——
`entity.kingdom.*` / `entity.culture.*` **被 `CanonicalEntityRef` 拒绝**（`WB-DOC-003`）。
⇒ **这不是「暂时」，是编译器的硬限制**，因而「政体不绑死」不只是设计偏好，
**是唯一可行的做法**。

#### (a) 为什么必须分开

初版把「政治/文化」当成一块。**错。** 两者是**不同性质的层**：

| | 政治制度 | 文化 |
|---|---|---|
| 是什么 | **可被施加、替换、改组的规则集** | 一个族群**长期形成**的底色 |

| 是否可变 | **可变**（部落制→封建制） | 极慢（改不掉，只能叠加） |
| 玩家能动性 | **强**（改组、架空、自创） | 弱（生在什么文化就是什么） |
| 举例 | 封建制／部落制／神权制／商人共和国 | 巴旦尼亚的德鲁伊传统、帝国的东西分治心态 |

⇒ 若混在一域，**「可变的」会被「不可变的」淹没**，玩家分不清哪些能改。

#### (b) 为什么政体不能绑死 —— 「巴旦尼亚改组」反推

甲方场景：**巴旦尼亚王国（部落制）→ 学帝国制度 → 改组为封建制王国**。

若写成「`巴旦尼亚 = 部落制`」这一条**断言式条目**，则改组时：
- 旧条目变成**错的**（但已编译进包，无法作废）
- 新条目与旧条目**并存**，运行时不知道以谁为准
- ⇒ **每次改组都要改包**，而改组是**玩家局的运行时行为** ⇒ **架构上就错了**

**正确形态**：把「政体」与「谁在用政体」**分成两层**：

```
┌─ 制度件（不绑任何王国／锚点） ──────────────────┐
│  politics/polity-tribal          部落制         │
│  politics/polity-feudal          封建制         │
│  politics/polity-theocratic      神权制  ← 架空 │
│  politics/polity-merchant-republic 商人共和国 ← 架空│
└──────────────────────────────────────────────┘
                    ▲
                    │ 被引用（运行时决定，非编译期写死）
                    │
┌─ 状态条目/机制 ──────────────────────────────┐
│  「巴旦尼亚当前政体 = polity-tribal」        │ ← 改组 = 换引用
│  「本局玩家政体 = polity-feudal」            │
└────────────────────────────────────────────┘
```

**关键**：**制度件写"这制度是什么、怎么运作、谁了解它"；
"谁现在用它"是运行时状态，不写进世界书。**
⇒ 改组**不碰包**，只换引用。**架空的政体也能写**（因为它不需要游戏里存在）。
