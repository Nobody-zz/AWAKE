# 「何时知道」这道闸（2026-09-19 新建）

## 0. 一句话

设计初衷的三根轴里，「何时知道」此前**一道闸都没有**（管道是有的：`day`／tick、周报时间窗、事实流水账）。
今晚补上一道，只覆盖**动态事实的时点**这一层。
**变异检验判红**（泄漏 0 → 3，EXIT=1）—— 所以它是真在测，不是全绿空转。

---

## 1. 这道闸是什么

- **位置**：`tools/worldbook-runtime-sim` 新增 `time-gate` 子命令（与 `identity-gate` 同形）。
- **零替身**：事实由真件 `WorldFactCapture.TryCreateWar` 现造；查询走真件 `WorldFactQuery`；
  本闸只做"摆好当下、读回结果、对判据"。
- **判据五条**：

| # | 判据 | 内容 |
|---|---|---|
| ① | 未来不泄漏（硬） | 事实发生在第 d 天 ⇒ 把「当下」设成 **d-1**，它不得出现在结果里，**且决策理由必须是 `excluded_outside_window`**（不只是"没出现"——靠别的通道偶然被挡不算挡住） |
| ② | 到了就会出现（硬，阳性对照） | 「当下」设成 **d**，同一条必须出现。**没有这条，①讲不准是恒真**（"查询恒返空"也能满足①） |
| ③ | 老料不回流（硬） | 「当下」设成 **d+7**（窗 `[d+1, d+7]`），它必须已被排除 |
| ④ | 周窗形状（硬） | `WeeklyDynamics` 在当下 D 的窗口必须恰为 `[D-6, D]` |
| ⑤ | 空转护栏（硬） | 阴性行／阳性行／阳性命中都不许为 0 ——「恒 True＝没测」 |

- **变异检验**：`AWAKE_GATE_MUTATE_FORGE_DAY=1` 把「当下」**冒充**成事实发生的那一天
  （＝从输入侧模拟"窗界失效"），而地面真值仍是"这一刻它还不该被知道" ⇒ **① 必须判红**。
  这与身份闸的变异同构（那边是"把被排除的身份冒充成够得着的身份"）。

## 3. 三条侦察发现（全部 grep／实读，带出处）

### 3.1 ★ 作者层的时间与状态字段，**进不了包**

作者层 schema 顶层有这些字段：`status`（枚举含 **`future`**／`rumor`／`needs_review`／`rejected`）、
**`era`**、**`lifecycle`**、`universe`、`content_tier`、`related_domains`、`aliases`、`entity_ids`、`redirects`…
（出处：`docs/worldbook-studio-plan/awake.worldbook.authoring.v1.schema.json`）

编译产物三份（`ModuleData/Worldbook/packages/calradia/{runtime,index,manifest}.json`）实测：

| 键 | 命中次数 |
|---|---|
| `"era"` / `"status"` / `"lifecycle"` / `"universe"` / `"related_domains"` / `"content_tier"` | **各 0** |
| `"entityRefs"` | 402 |
| `"sourceDocumentId"`（词条层） | 482 |

编译后一个词条只剩：`{id, domain, title, summary, keywords, expressions}` ＋
`extensions{subdomain 482, entityRefs 402, sourceDocumentId 482}`。

⇒ **「何时知道」在内容侧不是"没写"，是"写了也进不了包"。**
`era`／`lifecycle`／`status=future` 在作者手上是活的，到运行时一枚不剩。

### 3.2 唯一一处"条件语言"只有契约声明，没有消费者

`awake.worldbook.state-predicate.v1`（出处：`tools/worldbook-studio/contracts/authoring-action-route-registry.v1.json:109-125`）
声明得**很完整**：`allowed_operators` `["=",">","<","&&","||"]`、24 个 `bare_boolean_fields`
（`approval_ready`／`lease_valid`／`freshness_stale`…）、`numeric_fields`、`enum_fields`、优先级、未知字段即校验错。

但 `condition_language`／`bare_boolean_fields`／`allowed_operators` 三个串
在 `src/`＋`tools/`＋`framework/` 的 `.cs` 里 **0 命中** ⇒ **只有声明，没有消费者**。

⚠️ **别把它和事件规则的 `condition` 混为一谈**：`AwakeEventDataLoader`（解析）＋`AwakeEventEngine.ConditionMet`（求值）
那套是**事件规则**用的枚举（`Always`／`InSettlement`…），**是活的**。两者同名不同物。

### 3.3 顺带纠我自己档里一个说法

`docs/REVIEW-MY-OBJECTS-20260919.md` §1.2 写「`subdomain`／`entityRefs` 埋在 `extensions` 里、不在顶层」——
**这话只对编译产物成立**。**作者层 schema 里它们本来就是顶层**（`subdomain`／`entity_ids`／`aliases`…），
是**编译器**把它们投影进 `extensions`（`entity_ids`→`entityRefs`、`aliases`→并入 `keywords`）。
⇒ 读"字段在哪"必须**先说是哪一层**（作者层 / 编译产物 / 编辑器），否则同一字段有两个答案。

## 4. 现场：生产闸有一条**偶发红**（不是我这两笔碰出来的）

**复现（同一二进制、同一输入，结论掷硬币）**：

```
连跑 4 次：RC=1 / RC=0 / RC=1 / RC=0        （红绿各半）
恒定同一项：FAIL store-switch-blocks-old-load
           :: InvalidOperationException:campaign reset must invalidate the old store
RESULT 在 passed=30 failed=1 与 passed=31 failed=0 之间跳
```

- **判据位置**：`tools/worldbook-runtime-production-smoke/ProductionSmokeTestsMore.cs:128`
  —— `Check(oldStore.LifecycleState == WorldStateStoreLifecycle.Ending, ...)`。
- **测试做了什么**：起一个旧 store 并装上 → 后台发起 `WorldEventLedger.LoadFromStoreAsync`（用 barrier 把它卡在存储读取上）
  → 此时调 `AwakeRuntime.ResetSessionStateForCampaign()` → 断言旧 store 被标成 `Ending`。
- **可核线索（这是推断，标"待验证"）**：reset 只有在 `_worldStateStore != null` 时才 retire
  （`src/AwakeRuntime.cs:973-976`：`if (_worldStateStore != null) RetireWorldStateStoreLocked(_worldStateStore);`）
  ⇒ 只要 reset 那一刻 `_worldStateStore` 已被置空／换掉，这条断言**必然红**。
  所以这条红指向的不是 retire 逻辑本身，而是「**谁在 reset 之前把 `_worldStateStore` 置空/换掉了**」
  —— 测试侧竞态、还是安装/绑定竞态，**我没有做根因判定**。
- ⇒ **结论：这条闸现在的绿不值钱。** 同一输入两个答案，既不能当"过了"、也不能当"坏了"用。

## 6. 建造中踩到的坑（已修，值得记）

- **控制台编码会静默吃掉判阅证据**：新闸若不显式 `Console.OutputEncoding = System.Text.Encoding.UTF8;`，
  中文与 `✓`／`✗`／`①` 落到**管道**会被按 GBK 编码 ⇒ 读数档（按 utf-8 解）里变成 `?` 与乱码。
  症状是"闸判 PASS/FAIL 的字样还在、但逐行证据全成问号"——**判阅证据静默失真**。
  已在该闸首行钉死；其余验台是否也有这个病，**未逐个体检**（待办）。
