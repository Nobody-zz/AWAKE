# 世界书工作室作者模式设计

> 锁定日期：2026-08-22
> 适用范围：`tools/worldbook-studio` 离线编辑器

## 目标

把当前以原始 YAML 文本框为默认入口的世界书工作室，改造成面向普通内容编辑者的中文模块化编辑器。作者不需要理解 YAML、内部 ID、注册表哈希或数组缩进，也能新建、填写、检查并保存一份 `awake.worldbook.authoring.v1` 档案。原始 YAML/JSON 能力保留为明确标注的高级维护模式。

## 用户流程

默认编辑器采用五步引导：

1. **基本信息**：标题、知识分类、知识适用时期、确定程度、简介、内容状态。
2. **客观事实**：一条事实一个卡片，可添加、删除和折叠多条事实。
3. **NPC 表达**：每条事实下维护摘要、详细、秘密等表达层级，并填写 NPC 实际说法。
4. **知识权限**：用中文身份、知道范围、最低详细度和禁止身份配置 `grants`/`denies`。
5. **检查与保存**：显示中文错误、所在模块、原因、示例和“立即前往”按钮。

页面顶部显示步骤和完成状态；步骤之间可以返回修改。保存、校验、预览、编译和导出继续使用现有业务服务，不改变游戏目录或冻结 AWAKE 运行候选。

## 编辑模型与内部格式

浏览器使用独立的 `EditorDocumentModel`，不直接把 YAML 字符串作为默认编辑状态。Core 负责在内部文档与编辑模型之间转换：

```text
authoring v1 YAML/JSON
        ↓ 读取投影
中文编辑模型
        ↓ 合并用户修改
authoring v1 YAML/JSON
```

程序自动维护或只读展示：`schema_version`、`revision`、`id`、`universe`、`registry_bindings`、各种 hash、`author_created`、`authority`、`conflict_policy`、断言/表达内部 ID。编辑模型必须带上当前文档 hash、revision、registry 版本/hash 和每个断言/表达的稳定 ID；保存时按 ID 合并，不能依赖中文正文生成 ID。只保留 v1 schema 明确允许但作者模式未覆盖的字段；如果文件已经含有 v1 禁止的未知字段，作者模式拒绝保存并引导进入高级模式修复，不会静默丢弃。

## 中文字段映射

| 作者看到的名称 | authoring v1 字段 | 交互方式 |
|---|---|---|
| 档案标题 | `title.zh-CN` | 文本输入 |
| 知识分类 | `domain` | 中文下拉：政治、经济、文化、战争 |
| 知识适用时期 | `era.key/start_year/end_year` | 中文选项；自定义时期才显示年份 |
| 确定程度 | `era.certainty` | 确定、范围确定、大致确定、时间未确定 |
| 档案简介 | `summary.zh-CN` | 多行文本 |
| 内容状态 | `status` | 中文下拉；正典状态按现有审核规则处理 |
| 客观事实 | `assertions[].text.zh-CN` | 事实卡片，多条 |
| 事实类型 | `assertions[].kind` | 事实、解释、传闻、关系、状态 |
| NPC 可以说的话 | `expressions[].text.zh-CN` | 表达卡片，多条 |
| 表达详细程度 | `expressions[].layer` | 传闻、摘要、详细、秘密 |
| 知道该知识的身份 | `grants[].profile_id` | 中文身份多选 |
| 知道范围 | `grants[].scope` | 本地、区域、全国、阵营、贵族圈、私人 |
| 最低表达详细度 | `grants[].min_detail` | 传闻、摘要、详细、秘密 |
| 禁止知道 | `denies[].profile_id` | 中文身份多选 |

`era.key` 在界面上不显示为“所属时代”，统一改名为“知识适用时期”，并用说明解释为“这条知识发生或有效的时间范围”。普通选项为：当前世界、历史时期、某事件之前、某事件之后、长期存在、时间未确定；自定义时期时才填写起止年份或事件名。

## 身份显示

身份选项从现有 profile registry 读取，内部 ID 不暴露。至少支持当前注册表中的普通村民、城镇居民、普通平民、头人、商人、酒馆老板、赎金经纪人、士兵、贵族、高管理贵族；显示名来自 `display.zh-CN`，缺少中文显示名时使用安全的本地化回退并在校验区提示。

推荐对象从 referral registry 单独显示为“可以去询问谁”，不与“谁知道这条知识”混为一项；公证商人、赎金经纪人、酒馆老板和村庄或城镇头人可作为公开询问对象。

## 来源、原创与审核边界

v1 在文档、断言、表达三个层级都要求 `sources` 与 `author_created` 二选一：

- 已有 `sources` 且内容没有改动时，作者模式只读展示来源绑定并保留来源。
- 新增断言/表达使用 `author_created.review_status=draft`，不自动写入 `sources`。
- 已有来源型对象在本批作者模式中只读；界面明确显示“此内容由来源证据支持，普通作者模式不直接修改”，高级模式仍可维护。来源型内容转为作者草稿、来源脱钩和审计事件另列后续批次，不在本批自动发生。
- 作者模式保存原创内容一律保持 `needs_review` 或原有非正典状态；不能通过普通下拉把未批准内容变成 `canon`。`canon` 需要现有审核事件产生 `review_event_id`，否则保存被拒绝。
- 改动已有 `author_created` 对象会递增该对象的 revision、清除旧的 `review_event_id` 并回到 `draft`；文档 revision 也递增。

## 未覆盖字段与权限条件

`universe`、`authority`、`content_tier`、`entity_ids`、`aliases`、`redirects`、`lifecycle`、来源绑定和注册表绑定在作者模式中显示为只读摘要；作者模式保存必须逐字段保留它们。`authority` 的 owner/conflict policy 不由普通编辑者修改。

权限卡片可直接编辑身份、范围、最低详细度和公开推荐对象；年龄、管理技能、性别、族长等数值/布尔条件放在“高级条件”折叠区。文化、王国、城镇、职务 ID 若没有对应中文实体目录，只显示已有条件数量和“由高级模式维护”，保存时按稳定规则 ID 原样保留，禁止静默清空。

## 并发与模式切换

作者保存请求必须携带打开时的 `source_hash`、文档 revision 以及 profile/referral registry 版本和 hash。新增卡片在浏览器第一次添加时立即生成不可变 `clientKey`；保存失败重试复用同一 key，服务端首次接受时生成内部稳定 ID 并在返回快照中绑定，禁止重复生成。服务端重新读取当前文件并做 CAS 检查；任一不匹配返回 409，前端保留用户缓冲区并要求重新读取合并。成功保存后重新读取服务端文件，同时刷新作者模型和高级文本框，旧 AI suggestion buffer 失效。

保存前统一执行两步：先对当前和候选文档做完整 v1 schema 校验，再按对象层级作者字段白名单检查；未知字段或不满足 schema 的对象直接阻止保存。语义比较使用规范化 JSON 树，不比较 YAML 排版、缩进或换行；只有作者字段、受控元数据或真实对象集合发生变化才递增 revision。

诊断映射由 Core 统一完成：业务校验直接携带对象 ID；JSON Schema 路径先按数组位置从同一份候选文档解析到对象 ID；无法可靠解析时 `assertionId/expressionId/ruleId` 为空并保留通用高级诊断，禁止伪造卡片目标。权限条件在模型中标记为 `editable`、`readonly-summary` 或 `advanced-only`；合并器只应用显式 dirty 的字段，空控件不会覆盖未触碰的已有条件。有效 ID 缺少中文名是 warning，未知或已删除 ID 才是阻止保存的 error。

作者模式和高级模式共享“最后一次服务端快照”，但各自拥有临时缓冲区；切换前若当前模式 dirty，必须保存、放弃或取消，不能直接互相覆盖。高级模式保存成功同样发布新的服务端快照版本，作者模型、registry 绑定和 AI buffer 按新的 source hash/revision 失效，必须重新读取。

## 高级模式

默认不展示原始 YAML。高级模式入口名称固定为：

> 高级模式：直接编辑世界书文件

进入前说明该模式面向开发者或熟悉 YAML/JSON 的维护者。高级模式沿用当前文本编辑器、保存和校验逻辑；切换模式前检查未保存状态，避免两个编辑模型互相覆盖。

## 错误与引导

校验诊断必须将内部代码翻译成中文动作提示。例如：

> “客观事实”不能为空。请返回第 2 步，填写一条可以验证的世界知识。示例：瓦兰迪亚的主要粮食产区位于西部平原。

每个诊断携带模块、稳定对象 ID（如果可解析）、卡片索引和可聚焦目标；前端提供“立即前往”。英文错误码和内部路径只放在可展开的技术细节中。

## 不在本批范围

- 不迁移现有 `awake.worldbook.authoring.v1` 文件格式。
- 不改动 AWAKE 游戏运行时、`PlayerExports`、`Modules\\AWAKE`、dist 或冻结候选。
- 不实现多人协作、云端同步、拖拽排序或自动批准正典。
- 不把 AI 建议直接写入正典；现有人工确认、隔离建议和 CAS 规则保持不变。
- 不删除高级 YAML 编辑器。

## 完成标准

使用一个不懂 YAML 的内容编辑者视角，完成“新建档案 → 填写基本信息 → 添加两条事实 → 给事实添加两种 NPC 表达 → 选择普通平民和贵族权限 → 保存 → 校验 → 预览”的流程，不需要手写内部 ID、缩进或哈希；故意留空事实时，能从错误提示直接跳回事实卡片。有效但无中文名的身份只出现可继续的 warning；未知身份、CAS 冲突、来源转换失败和 schema 失败均能恢复而不丢缓冲区。现有 CLI/Core 测试、API smoke、浏览器 loopback smoke、Release 构建和发行包检查不回归。
