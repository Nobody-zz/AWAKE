# AWAKE 改进方向

> 日期：2026-08-16
> 依据：`AF-History-Evolution-20260816.md` 的教训、`PLAN-SceneVisualSelection-20260816.md` 的双模式方案、`AWAKE-Task-Queue-20260816.md` 的现状。
> 原则：运行时内容无关、模块可替换、schema 有版本、命令有权限与幂等、UI 可读且本地化、性能有预算、发布有白名单。

## 一、方向总览

AWAKE 不追求“把 AF 再写一遍”，而是把 AF 证明有效的分层保留下来，再补上它缺失的工程约束：

1. 对话层：AI 只负责角色化表达。
2. 规则/后处理层：负责“什么已经成立”。
3. 命令/效果层：负责结算与权限。
4. 世界层：事件、记忆、关系、外交、政策、世界书。
5. 内容层：内容包注册，不写死在运行时。
6. 发布层：版本、哈希、白名单、本地化、双版本。

## 二、P0：对话与架构基线

### 1. 双模式对话（已锁 PLAN，待签收）

第一版同时具备：

- 场景 AI 对话：AWAKE 覆盖层，不沿原版对话，不回退原生对话。
- 原版对话窗口 AI 模式：原版对话界面上的 AWAKE 切换层，关闭后恢复原版选项。

关键约束：

- 场景预览：地面扇形 + 候选高亮，候选 48、标记 180、每 tick 新建 16。
- 目标稳定 debounce，避免 `OneToOneConversationCharacter` 瞬态 null 反复重建。
- 上下文门谓词隐藏 AI 按钮：任务、强制剧情、竞技场、战斗结算等。
- 覆盖层捕获鼠标/键盘/手柄输入，关闭后恢复原版焦点。

第一动作：签收 `PLAN-SceneVisualSelection-20260816.md` 后实现。

### 2. 会话服务统一

场景、遭遇面谈、通讯录、原生对话 AI 模式共享同一套：

- `NpcDialogueService`：AI 会话、流式、取消、命令桥。
- `NpcMemoryService`：跨会话记忆。
- 世界书/关系/玩家情报上下文。

UI 可以不同，但会话状态不能各自为政。

第一动作：把 `NpcDialogueOverlay`、`AwakeMessengerOverlay`、未来的 `NativeConversationAIMode` 统一到同一个会话调度器。

### 3. 规则/提示词 schema 与注册表

AF 的教训：规则 JSON 从 100 KB 涨到 140 KB，没有 schema 版本和注册表，规则 ID 会被删除/合并，内容包难以兼容。

AWAKE 方向：

- 规则文件带 `schemaVersion`、`manifest`、`fingerprint`。
- 所有规则通过注册表登记，加载时校验，未知字段 fail-closed。
- 提供一次性迁移工具，禁止无版本地改 ID。
- 规则正文不无限堆在单一 JSON，按主题拆分并索引。

第一动作：先把现有世界书 manifest 规范扩展到规则/提示词注册。

### 4. 命令层扩展

当前只有关系命令。方向：

- 结构化命令，不学 AF 的 `[ACTION:...]` 字符串标签。
- 所有命令走 `CommandRiskPolicy + PermissionGate + 幂等 + 回执`。
- 先接世界事件、周报、关系，再接外交/政策/政令。

第一动作：把 `WorldCommandBridge` 的命令目录做成可注册、可枚举、可审计。

### 5. 发布与版本纪律

AF 的教训：正式包带 `EarlyException_*.html`，版本号频繁跳但无 changelog。

AWAKE 方向：

- 发布白名单：只允许已声明的 DLL、XML、Prefab、ModuleData、语言包。
- 每次发布校验：SubModule 版本、程序集版本、哈希、本地化 key、事件 ContentHash。
- 功能与修复不混入一次提版；普通修复不提版。
- 双版本构建产物必须分开目录，禁止混用。

第一动作：把现有构建/校验流程固化成 `tools/release_check.ps1`。

## 三、P1：世界模拟与内容

### 6. 事件引擎数据驱动化

当前事件引擎是骨架，无内容规则。方向：

- 事件定义带 ID、触发条件、冷却、每日上限、选项、对话动作。
- 内容包通过注册接口注入，不在运行时硬编码。
- 事件元数据走存储持久化，游戏日滚动重置。

第一动作：把 `SlaaneshEventEngineCore` 的硬编码事件改造成注册表驱动，并补 SdkSmoke。

### 7. 记忆系统

方向：

- 结构化记忆：时间、地点、人物、事件类型、承诺、结果。
- 日常记忆按游戏日衰减/合并，重大事件永久保留。
- 承诺账本与秘闻传播单独建模，不塞进正文。
- 记忆以稳定 ID 和事实为权威，外部数据库只做镜像。

第一动作：在现有 `NpcMemoryService` 上增加事件类型、weight 和合并规则。

### 8. 主动聊天

方向：

- 动机化候选：事件、关系、队伍状态、家族压力、政治。
- 冷却、疲劳、打开失败恢复。
- 场景弹窗、地图通知、来信三种入口。
- 无名 NPC 主动只使用身份内知识。

第一动作：把 `NpcProactiveService` 的动机表扩展为可注册内容，而不是硬编码枚举。

### 9. 世界书/RAG

方向：

- 保持索引先行，不引入 ONNX/全量扫描。
- 世界书查询要记录命中率、耗时、注入预算。
- 支持同一 keyword 多条 rules、多 Variants、TextMappings。
- 内容包世界书通过 manifest 注册，不要求作者手动改运行时。

第一动作：给世界书查询加结构化日志和缓存命中统计。

### 10. 内容包解耦

方向：

- 运行时零世界观内容。
- 女神、情色、战争、政令等内容独立包。
- 内容包公开 API：注册事件、规则、世界书、信件模板、NPC 主动动机。

第一动作：把 `SlaneshsEmbraceContent` 的内容通过注册接口接入，运行时不做任何内容判断。

## 四、P2：体验与 UI

### 11. Messenger 统一会话

方向：

- 通讯录、写信、来信、未读、通知统一到一个界面语义。
- 场景/面谈用沉浸覆盖层，远程用 Messenger，不重复实现会话。
- 群聊、头像、媒体、TTS 后续以插件形式接入。

第一动作：先合并通讯录和 NPC 覆盖层的入口调度。

### 12. 开发者检查面板

当前是文本报告。方向：

- 结构化诊断 UI：宿主、路由、Provider、存储、世界书、记忆、事件。
- 一键自检、错误代码、日志位置。
- 只读诊断，不在面板里执行写操作。

第一动作：把 `AwakeDeveloperReport` 输出改成可绑定 VM。

### 13. 首启向导与配置

方向：

- 无模型时引导配置 Provider/Key/Route。
- MCM 只保留常用开关，详细配置进 AI 设置台。
- 自动检测路由能力，避免“能连但没授权”。

第一动作：把 Marcus 一键配置流程做成可重入的首启向导。

### 14. 热键与 MCM

方向：

- 场景内 T/Y，场景外命令台 U，避免与 AF 撞键。
- 热键可配置，冲突时给出明确提示。
- MCM 分组顺序稳定，开发者项后置。

第一动作：建立热键冲突检测。

## 五、P3：性能、稳定与可观测

### 15. 检索与知识性能

- 禁止全量扫描、禁止本地 ONNX。
- 倒排索引 + 指纹 + 分层召回。
- 所有查询有预算上限和超时。

### 16. 主线程与 tick

- mission/campaign tick 不做阻塞 AI、文件、数据库。
- 后台结果通过统一 dispatcher 回主线程。
- 长列表 UI 使用 append/diff，不高频 Clear 全量重建。

### 17. 日志与错误码

- 结构化日志、错误码、关联 ID。
- 游戏内不弹错误详情，只提示日志位置。
- 日志滚动、关键路径 perf 探针。

### 18. 存储与存档契约

- 存档只存权威状态，外部数据库是历史镜像。
- 存储 key 冻结并带 schema 版本，读档缺 key 做安全回退。
- 迁移必须可重入，不能因一次失败永久跳过。

## 六、第一批落地建议

1. 签收并实现双模式对话 PLAN。
2. 统一会话调度器，消灭重复入口逻辑。
3. 建立规则/提示词 schema 与注册表。
4. 事件引擎注册表驱动。
5. 发布校验脚本与白名单。
6. 记忆结构化与衰减。

## 七、不做的事

- 不复制 AF 巨型单体。
- 不反射写原版对话 VM。
- 不 Harmony 拦截 `StartConversation`。
- 不引入 ONNX/近 1GB 扫描。
- 不把成人内容写进运行时核心。
- 不把外部数据库当作存档权威。
