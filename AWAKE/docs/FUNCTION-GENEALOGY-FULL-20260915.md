# 第 0 章 · 系统关系（本次新增，骨架在这一章）

## 0.1 三个中枢

谱系原来按"功能"平铺，看不出底下其实只有三个中枢，其余全是它们的分支。

| 中枢 | 是什么 | 现在什么状态 | 缺了会怎样 |
|---|---|---|---|
| **内容中枢**（世界书） | 448 档知识与设定。**它是唯一能同时喂"数值"和"台词"的东西** | 内容有、**通路窄**——检索是关键词命中，中文无分词（`docs/CEILING-MARCUS-FUNCTIONAL-20260915.md` §三.1） | 从"有内容的模组"退化成"有模型的模组" |
| **记忆中枢** | 时间线 ＋ 事件落盘 ＋ 会话记忆 | **断**：事件调用点写了 Durable、背后是内存；状态落在 `AwakeState/unbound/`（绑在认出存档之前） | **三阶段全部空转**：关掉再读档，谁也不记得你 |
| **命令中枢** | 意图 → 受控动作 → 游戏结果（R0–R3、preflight、幂等 receipt、`Uncertain` 不回滚重试） | **有件无调用**：真件都在框架里，玩法侧 0 调用 | **第二阶段整块做不了**：NPC 只会说话，改不了任何事 |

⇒ **两个中枢是"断的"或"有件没人用"。** 这解释了一件事：第一阶段那四个面为什么全卡在同一批地基上——它们不是四个独立的问题，是**同一个中枢的四个出口**。

## 0.2 ★「一条内容 → N 个出口」（本次展开最重要的一条）

**一条世界书条目，可以同时是五样东西。** 原来平铺的清单看不出这一点，而它决定了每个功能值不值得做：

| 出口 | 形态 | 玩家在哪看到 |
|---|---|---|
| ① **数值修正的理由** | `ExplainedNumber.AddFactor(值, 理由文本)` | 游戏自己的数值明细（tooltip 逐条来源） |
| ② **NPC 的说法** | 同条目摘要进上下文 | 对话／喊话／回信 |
| ③ **世界事件的起因** | 事件生成的素材 | 事件收件箱、周报 |
| ④ **周报／编年史的一段** | 叙述素材 | 周报、传记 |
| ⑤ **检索的命中面** | `Title ＋ Keywords` | "上次你说过…"能不能提对 |

**把这条反过来读，就能给功能称重：它消费了几个出口？**

- 只做 ② ⇒ 那是一段**背景设定**：好看，不出活。
- 只做 ① ⇒ 那是一张**数值表**：出活，不好看。
- **② 与 ① 共用一条 ⇒ 玩家听到的和算出来的是一回事。** ← 这才值得做。
- 出口 ⑤ 是**前四个的地基**：检索不准，①②③④ 全都只能是"随机"而不是"提起"。

⇒ **推论**：凡是"只做一个出口"的功能，优先级一律往后放；凡是能同时喂两个以上出口的，优先做。
⇒ 这条已经落地验证过一次：文化数值修正（`docs/DESIGN-CULTURE-MODIFIER-KNOWLEDGE-COUPLING-20260915.md`）就是 ①＋② 共用一条。

## 0.3 四组咬合（谁不改，谁就白做）

| 咬合 | 说明 |
|---|---|
| **记忆 ↔ 一切** | 记忆不做，对话／写信／事件／周报全部**活不过一次读档** |
| **检索 ↔ 长线** | 检索不准，"提起旧事""传记""编年史"全变成流水账 |
| **命令 ↔ 外交／喊话／领兵** | 这三条是**同一个"意图→动作"链的三个皮肤**：不是三个功能，是一个功能三种穿法 |
| **美术 ↔ 呈现** | 面板／肖像／文书面貌不做，内容再好，玩家看到的还是制式框 |

# 第一阶段 · AI 模组的基本可玩性

**判据**：装上以后，玩家觉得"这个 NPC 是活的、这个世界在动"。
**归口**：**主干**（对话/信件/事件链路）＋ **角色卡**（语气与立场）＋ **世界书**（内容）＋ **UI**（面板）。**四条线全动**才能出效果——这是本阶段最大的跨线风险。

# 第二阶段 · 骑砍世界的沉浸式扮演

**判据**：**AI 的输出能改游戏状态**，而不是只说话。

# 判断（不是功能，是"怎么选"）

1. **世界书只在"一条内容多出口"时才值钱。** 只喂一个出口的功能，是在把 448 档内容浪费成一段设定。（§0.2）
2. **周报最划算的一招是"给它一个作者"。** 同一件事由自家书记官、宫廷史官、仇家分别写，立场不同——**能力成本几乎为零，但玩家会记很久**。这是"从数据变文学"的那一步。
3. **指令识别里最保命的不是"能听懂"，是"听不懂就说听不懂"。** 猜错的指令会改坏存档。
4. **第二阶段的性质是断崖，不是延续。** 第一阶段答错只是话说得不好，第二阶段答错会改坏存档。**先做一条最窄的**（例如"劝降一个守军"），把"意图→动作→结果"证死，再铺开。
5. **对话是入口，不是留存。** 玩家因为对话装模组，但让他玩一百小时的，是**周报／编年史／传记**给的那个"时间感"——§1.4 和 §3.4 被低估了。
6. **同一个模组，三个出口共用一条内容，胜过三个模组各做一件事。** 这是本项目相对"又一个 AI 对话模组"的唯一结构性优势。
