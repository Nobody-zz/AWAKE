## 一、内容差哪些

### 1. 题材单一（最要紧）

**现在的 12 档全是地点。** `entity_ids` 的 kind 分布实测：

| kind | 条数 | 说明 |
|---|---|---|
| `lore` | 11 | 湖 / 湾 / 半岛 / 山脉 / 部族（语义实体） |
| `settlement` | 2 | 德里亚特（刚修正为游戏锚定） |
| **`hero` / `clan` / `kingdom` / `culture`** | **0** | **一个都没有** |

而游戏里现成有：**397 英雄 · 95 家族 · 8 王国 · 23 文化 · 494 聚落**。

**世界书里没有人、没有家族、没有势力、没有事件。** 只有地。
对玩家来说，聊得最多的话题是"某某领主是什么人""这个家族跟那个家族什么关系"——现在一条都答不上。

### 2. domain 覆盖不全

| domain | 档数 |
|---|---|
| geography | 5 |
| culture | 4 |
| politics | 2 |
| economy | 1 |
| **war** | **0** |

`war` 一档没有。骑马与砍杀的核心就是打仗，这一块完全空白。

### 3. 身份用了 6/12，且缺了最关键的

| 身份 | 用量 |
|---|---|
| commoner 平民 | 24 次（占绝对多数） |
| townsfolk 市民 | 5 |
| villager 村民 | 4 |
| notable 乡绅 | 4 |
| merchant 商人 | 2 |
| noble_high_steward 贵族总管 | 1 |
| **headman 头人 / tavernkeeper 酒馆老板 / ransom_broker 赎金经纪人 / soldier 士兵 / noble 贵族 / anonymous 未知** | **全 0** |

两个刺眼的点：
- **贵族（noble）一次没用，但它的子身份"总管"用了 1 次**——子用了父没用，说明不是有意取舍，是漏了。
- **士兵（soldier）0 次**。战争题材的世界书没有士兵视角。

### 4. 分层说法只做了 40%

40 条表达里 **24 条（60%）与断言正文逐字相同**（兜底载体）。真正差异化的 16 条几乎全在 `*-tales`（传说类，11 条 100% 差异化）。
客观事实类的 10 条全是复制——**"同一件事不同人说法不同"这件最有价值的事，基本没做。**

### 5. 层级只有三档，缺两头

| layer | 条数 |
|---|---|
| summary | 25 |
| detail | 11 |
| rumor | 4 |
| **secret 秘闻** | **0** |
| **unknown 无人知晓** | **0** |

### 6. 否决全空

**40 条表达，有 `denies` 的：0 条。** 而它是必填字段。
现在只有"谁能知道"，没有"谁不能知道"——知识壁垒这个概念完全没落地。

### 7. 条件维度一个没用

`culture_ids` / `kingdom_ids` / `settlement_ids` / `role_ids` / `is_female` / `is_clan_leader` / 年龄 / 管理等级 / 技能 —— **实测全部为 0**。
游戏数据现成给弹药（23 文化 / 8 王国 / 494 聚落），一条都没用。

### 8. 来源只有一种

已登记来源 5 个，全是编年史。**游戏官方文本（27 万条本地化）一条都没登记为 source**——它本来是最硬的书证（带 ID、带出处、可复核）。

## 二、格式差哪些

### 1. 可选字段几乎全空（12 档）

| 字段 | 使用率 |
|---|---|
| `subdomain` | 12/12 ✅ |
| `entity_ids` | 12/12 ✅ |
| `related_domains` | **0/12** |
| `aliases` | **0/12** |
| `redirects` | **0/12** |
| `lifecycle` | **0/12** |
| `author_created` | **0/12** |

### 2. `aliases` 全空是硬伤（这条最实际）

5 个语义锚点（拉科尼斯湖 / 沙拉斯湾 / 卡恰尔半岛 / 黎明山脉 / 合儿必特部）**不进 `entityRefs`**，检索只能靠 `title` + `aliases`。

**没有 aliases = NPC 换个叫法问就找不到。** 而这几处恰恰别名很多——编年史里就写着"大镜子""北方的海""蓝路水道"这些俗称，**但一条都没填进 aliases**。

### 3. `lifecycle` 不用，血缘只记在账上

12 档是投影批从一个地点拆出来的（有 `split_from` 血缘），但血缘**只记在 `PROJECTION-MANIFEST` 里，字段里没有**。schema 明明有 `lifecycle`。

### 4. `entity_ids` 的 lore 类型编译器不支持（C16）

格式上合法（schema 允许），但编译器只认 `hero/clan/settlement` → 11 条 lore 锚点会让编译直接抛错。**格式与工具对不上。**

### 5. `denies` 必填却全空

契约层面不合理：逼着每条写 `denies: []`。要么给真内容，要么改契约让它不必填。

### 6. 状态停在 `needs_review`，没有进 canon 的路径

12 档全是 `needs_review`。schema 有 `canon`，但"什么条件算审完"没有口径。

### 7. 其他结构性缺口

- `registry_bindings` 填了，但 **referral 没接线**（C13）
- `indexes` 是死字段（编译器写、运行时不读）
- `sources` XOR `author_created`：我们全用 `sources`，意味着**不能声明任何原创内容**

## 三、做得好的（别一棍子打死）

1. **来源引文做得很扎实** —— 每条断言都带 `quote` + `quote_hash` + `locator`，可逐字回溯。这是最费功夫也最值钱的部分。
2. **时代维度用起来了** —— `era.key`：current 7 / historical 5；`certainty`：bounded 6 / approximate 3 / unknown 3。有区分，不是一律"当前"。
3. **传说类真的做了身份化** —— 4 个 `*-tales` 档 11 条表达 100% 差异化，是"分层说法"的正确示范。

## 四、最小补齐动作（按性价比）

| 动作 | 补什么 | 成本 | 收益 |
|---|---|---|---|
| **填 aliases** | 5 个语义锚点的俗称/别称（编年史里现成有） | 极低 | 直接决定"问不找得到" |
| **补 war / economy 档** | 让 5 个 domain 都有货 | 中 | 验得出结构问题 |
| **写 1–2 个人物/家族档** | 打破"只有地" | 中 | 玩家最常问的话题 |
| **给 noble / soldier 补视角** | 把 6 个空身份用起来 | 低 | 分层立刻立体 |
| **把游戏官方文本登记为 source** | 增加来源种类 | 低 | 书证更硬 |
| **denies 要么填真内容要么改契约** | 结束"必填空数组" | 低 | 契约自洽 |

**如果只做一件**：**填 aliases**。它成本最低，但直接决定了现有内容能不能被问到——现在 5 个语义锚点没有别名，等于有一半内容藏在地毯底下。
