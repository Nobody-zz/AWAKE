## 1. 评分模型

| 维度 | 权重 | 含义 |
| --- | --- | --- |
| 可玩性 P | 35% | 玩家能直接看到、感受到、反复游玩的程度 |
| 可行性 F | 30% | 在当前代码、马库斯能力、游戏约束下的实现难度；5=最容易，1=最难 |
| 架构适配 A | 20% | 是否能复用马库斯服务与本模组现有模式，避免自造底层 |
| 成本风险 C | 15% | 5=便宜安全，1=高成本高风险；含开发、token、UI、存档、权限与内容量 |

总分 = P × 0.35 + F × 0.30 + A × 0.20 + C × 0.15

层级：S ≥ 4.2；A ≥ 3.6；B ≥ 3.0；C ≥ 2.4；D < 2.4；X11 为否决。

硬门禁：18+ 内容必须先满足年龄硬校验（年龄不明确即不满足）与性别/身份视角分支，逐项分析中已行级标记；Save 是权威；效果必须走命令与事件；不反射或不硬编码 AF/爱与恨签名；所有异步调用不阻塞游戏主循环。评分只是预判，不代表最终承诺。

## 3. 分层结论

- **S（立即/第一批）**：祈愿/献祭扩展、祭坛/圣地入口、关系标签、NPC写信、历史归档、身体开发面板、发情周期系统、发情提示与状态条、事件弹窗UI、场景/位置识别、档位预设、独立可玩（联动增强待 CapabilityBroker 启用后评估）、权限细分、命令风险分级。这些要么已有骨架，要么纯架构配置，要么是小闭环核心。
- **A（紧接着做）**：37 项。记忆、世界事件、UI 基础、开发者工具，适合在 0.1-0.2 阶段成批进入。
- **B（机制稳定后做）**：33 项。关系、俘虏、世界模拟的进阶内容，依赖事件和存储先稳定。
- **C（有条件做）**：16 项。资产、大内容、跨模组或框架能力未启用，需要前提条件。
- **D（暂缓/否决）**：4 项。高风险高成本、依赖外部资产、或违背 Save 权威。

## 4. 通用制作思路与马库斯调取要求

1. 注册：在 `OnSubModuleLoad` 只调 `FrameworkHostLocator.Register`；`IFrameworkExtension.Register` 里注册 capability、context provider、command、tool；战役工作在 `CampaignSessionReady` 开始。
2. AI 任务：`Prompts.RegisterAsync` 注册版本化 Prompt 与输出 Schema，再通过 `_host.Ai.SubmitAsync` 走逻辑 Route；每个调用携带 `RequestContext`、correlation ID、deadline、CancellationToken。
3. 世界读取：实现 `IContextProvider.ContributeAsync`，返回 `ContextContribution`；只读 `PlayerKnown` DTO，不长期持有 TaleWorlds 实时对象；敏感信息走 Context/RAG/云外发三重门。
4. 持久化：`Storage.OpenCampaignNamespaceAsync` 打开 namespace，再读写 `IKeyValueStore`；业务状态必须落在存档和框架存储，sidecar 只是历史镜像。
5. 世界修改：注册 `CommandDescriptor + ICommandAdapter`；`Preflight` 和 `Execute` 保持同步快速，先 `Commands.PreflightAsync` 再 `Commands.SubmitAsync`，带幂等键和快照复核。
6. 世界反应：修改成功后在命令内发布 durable 事件；周报、NPC 反应、后续追踪只订阅事件，不直接轮询状态。
7. 知识：`Rag.IngestAsync` 与 `Rag.SearchAsync`；多语料、分块、Embedding/Rerank、命中解释属于本项目配置和内容职责。
8. 资产：图片/语音只消费 AssetHandle，不暴露路径；生成走 Media，播放走 Assets，审批门和成本控制由本模组负责；Assets/Media 当前未启用，需框架接入或自建降级。
9. 跨模组：只通过版本化 `capability://.../vN` 和 `CapabilityBroker` 调用其他 Mod，不使用反射或内部签名；CapabilityBroker 当前未启用，联动落地需先由框架接入。
10. 诊断：`Diagnostics` 记录 route、命令、事件、RAG 的命中率/失败率/耗时/token；开发者面板导出脱敏诊断。

## 5. 逐项分析

### A. 女神与神术层

- **A1 女神形象系统（3.65 / A）**：原理：女神人格可视化的最短回路；做法：Mood状态到头像/表情切换，再接Assets；马库斯：现有dialogue route的mood输出 + Assets/Media（当前未启用，需接入或自建降级）。
- **A2 女神长期记忆（4.05 / A）**：原理：跨会话人格连续需要三级压缩；做法：每日/重大/总览摘要加归档隔离；马库斯：memory.daily route + Storage namespace。
- **A3 神谕预言候选（3.25 / B）**：原理：AI只说预言不直接改世界；做法：预言确认后进入事件时间线，到期核验；马库斯：事件契约 + Context/RAG只读。
- **A4 祈愿/献祭扩展（4.85 / S）**：原理：愿力环已实现，缺入口和交换物；做法：菜单收集金币/物品/俘虏/仪式到offering.accept；马库斯：Commands + Storage + Events；18+门（年龄不明确即不满足；性别/身份分支）。
- **A5 神术战场祝福/诅咒（2.35 / D）**：原理：战前祷词和低限幅加成形成神术感；做法：先做R1展示型通知，再圣物和短时增益；马库斯：命令 + 战场上下文门。
- **A6 神殿网络（3.00 / B）**：原理：各城神殿状态让女神感知世界；做法：香火/祭司/信徒只读快照进Context；马库斯：GameData/Context + Storage。
- **A7 放纵月世界事件（3.55 / B）**：原理：世界观底层节日可直接做成世界事件；做法：春秋两季事件池加冷却去重和秩序变化；马库斯：事件总线 + 命令；18+门（年龄不明确即不满足；性别/身份分支）。
- **A8 女神任务/委托（3.35 / B）**：原理：把神谕变成有目标的任务链；做法：任务状态持久，完成后结算愿力；马库斯：Storage + Events + Commands。
- **A9 神学与异端（2.55 / C）**：原理：教团冲突产生世界事件；做法：先做轻量异端事件链，不做大系统；马库斯：事件 + dialogue route。
- **A10 信徒/信仰值（3.65 / A）**：原理：信仰是女神理解NPC的语义信号；做法：NPC faith字段加祈祷频率，只影响提示词；马库斯：Storage + Context。
- **A11 祭坛/圣地入口（4.30 / S）**：原理：女神菜单需要稳定入口；做法：城镇/城堡菜单注册祈祷/献祭/神谕；马库斯：自建Gauntlet，UiRegistry未启用。
- **A12 神谕经济（2.55 / C）**：原理：愿力与市场联动制造世界反馈；做法：默认关闭的限幅经济事件；马库斯：命令 + 事件。
- **A13 女神偏好曲线（3.85 / A）**：原理：女神态度应随玩家行为演变；做法：行为计数到偏好状态，再注入女神提示词；马库斯：Context + dialogue prompt。

### B. NPC 与关系层

- **B2 关系标签（4.35 / S）**：原理：明确关系类型比模糊数值更有实感；做法：标签状态机加切换/解除/百科显示；马库斯：Storage + Commands + Context；18+门（年龄不明确即不满足；性别/身份分支）。
- **B3 关系网络（3.00 / B）**：原理：可视化关系增强探索；做法：从关系存储生成图；马库斯：Storage只读 + UI。
