## 一、牵头概念：轻档三层

**轻档不是薄档——骨架自动、观感人工、门禁机验。**

百科化的目标：每一处地点、每一样物产、每一件物品、每一个可成为知识的概念，都有一条知识条目。规模化不靠写得多，靠把每条目拆成三层，各层用各层最便宜的生产方式：

| 层 | 生产方式 | 内容 | 人工占比 |
|---|---|---|---|
| **L1 底座层** | 自动（DB 驱动生成器） | 官方译名、aliases、A 级引文五元组、locator、source hash、slug 命名 | 0 |
| **L2 观感层** | 人工（唯一必须人写的部分） | 同一对象 × 六身份观感差异：村民听到什么、商人知道什么、贵族看到什么 | 全部 |
| **L3 门禁层** | 机验 | 硬门 5 项、红测套件、权限矩阵、自检 | 0 |

**不可让渡的内核**：百科条目仍不是维基条目。一个对象一条目一真相是百科；一个对象 × 六种身份观感才是这个世界书。中立内核 + 分层观感（旧章法 §一）原样适用。

## 二、范围与域映射：扩容不扩域

编译器 taxonomy 硬编码五域封闭（政治/经济/文化/战争/地理，`WB-DOC-002` 白名单）。**百科化不开第六域，扩的是各域下的 subdomain 目录**：

| 对象品类 | 归域 | subdomain 示例（需登记白名单） |
|---|---|---|
| 地点（聚落/堡/村/地标） | 地理 | 沿用现有 |
| 物产、物品 | 经济 | `goods`（物产）、`items`（器物） |
| 兵种、军械、军制概念 | 战争 | 沿用现有 |
| 官职、制度、部落法 | 政治 | 沿用现有 |
| 信仰、传说、技艺、习俗 | 文化 | `craft`（技艺）等按需登记 |

红测探针 E9 守这条：任何"第六域"提案直接 BREAK。

## 三、轻量条目规格（L 规格）

**Schema 唯一权威原则**：L 规格的字段集以编译器 JSON Schema 为唯一权威（schema 封闭，additionalProperties:false；`slug` 是文件名概念、**不是文档字段**，文档体内禁写）。任何 L 规格修订必须以"骨架样例过 validate"为生效条件（红测 E9 守此条）。

L 档是百科条目的默认形态，结构下限（可与旧章法重档并存，重档用于真正多层知识）：

1. **断言 1 条**，文本 ≤80 字，单主题；**表达 1–2 条**（`rumor` 与 `detail` 至少各一或按对象性质声明）。
2. **六身份显式落点**：villager/townsfolk/soldier/merchant/headman/noble 六身份在档内必须**显式直配**（grant 或 deny 之一）。靠 Parents 链继承兜底的，须在档内 `notes` 写明"X 经 Y 继承"，禁止裸缺（war1/军制批教训：继承缺口=簿记黑洞）。
3. **不变式**：`grant.min_detail == 所在表达 layer`；deny 仅限秘密/敏感内容且定向具体身份，禁祖链根。
4. **素材**：A 源口径按品类分层——**地点类**：官方描述文必达（DB 两处查证：localization + descriptionText）；**物品/物产类**（红测 E12 实测）：官方**译名与属性数据**必达（覆盖≈100%），**叙述性描述文覆盖≈0%**——叙述正文三条路：①由结构化属性自动成文（数值转观察句）②B 级编年史 ③D 级原创登记（登记才合法，无例外）。
5. **引文机制**：quote 必须能在来源快照中定位（WB-SOURCE-001）；同一官方源被多档引用时，主档留整段、副档用**差异化子串**（hash 不同 = 合法多域引用；整段双投 = 警）。
6. **译名纪律**：官方译名由生成器从 DB 直取，人工不得手写译名（硬规矩第 0 条的自动化落实）。

## 四、生成器流水线（L1 底座层的实现）

```
DB 提取(BannerlordSage) → 骨架 JSON → 渲染 yaml → 人工 L2 观感 → 六步编译 → 矩阵/自检
```

- 生成器红线：YAML 序列化必须 JSON 往返 + `ignore_aliases`（WB-YAML-006 禁锚点）；slug 命名空间 `item-<官方英文名 kebab>` 等，重名即拒。
- 批量纪律：每批 ≤40 档；register 每档独立 operation id（幂等缓存 CAS-409 教训）；`--out` 全相对路径（WB-PATH-003 教训）；六步脚本必须断言 `ok`（MUTATION-UNKNOWN 教训）。
- **逐档 validate 纪律**：validate 诊断不携带文档归属（Document=None，红测 E9 实测），批量流水线必须**逐档或分批 validate**，禁止全库一锅验后无法定位坏档；全库基线错误数应为 0，任何增量错误即本批 FAIL。
- 编译产物不入库（workspace 已 gitignore），入库的是 authoring yaml + 结果 JSON。

## 五、门禁（L3）

硬门 5 项（机验，判生死）：
- **H1** L 规格结构达标（§三 1–3）
- **H2** A 源必达或 D 登记留痕
- **H3** 引文定位 + hash 三处一致
- **H4** 六身份显式落点（继承须 notes 声明）
- **H5** slug/aliases 唯一且双语

观测层（不判死）：规模统计、交叉覆盖、观感密度抽样。
红测收敛判据 **R**：红测套件连续两轮 0 BREAK 方可从 v0.x 转正。
