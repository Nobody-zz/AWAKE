## 一、⚠️ 为什么上一版索引失效了（先读这节，避免重蹈）

旧索引 `AWAKE-PLAN-INDEX-20260816.md` 想做的事是「**把所有 PLAN 登记成一张表，状态变化必须同步**」。
**这个目标在 08-17 之后就已经不可达了** —— 到 09-30，`docs/` 下已有 **652 个文件**：

| 前缀 | 数量 | 性质 |
|---|---|---|
| `PLAN-*` | **228** | 计划，绝大多数已完成或已过期 |
| `AUDIT-*` | 59 | 审计（一次性取证，不是计划） |
| `AWAKE-*` | 35 | 项目级文档 |
| `persona-*` / `PERSONA-*` | 58 | 角色卡线 |
| `REVIEW-*` | 31 | 复查（含大量 `ROUND1/2/3` 同名变体） |
| `UI-*` | 18 | UI 线 |
| `DECISION-*` | 12 | **裁定（这类才真正长期有效）** |
| 其余 | ~160 | HANDOFF / DONE / FEED / SPEC / GRILLME / 中文名 等 |

**结论**：
1. **任何"全量清单"必然在两周内失效** —— 维护成本随文件数线性增长，而收益为零（没人会读 228 行 PLAN 表）。
2. **旧索引还陈述了 F 但没做**：其第七节写「已归档 **205 个文件**，位置 `docs/archive/`」——
   而 **`docs/archive/` 目录根本不存在**（09-30 实测）。这是最坏的一类错误：读者会去找一个不存在的地方。
3. ⇒ **正确做法：只维护「当前权威在哪」＋「按类型去哪找」两张指针**，不做穷举。

## 四、文档类型约定（命名即类型）

`TYPE-主题-日期.md` —— 按前缀判性质：

| 前缀 | 含义 | 时效性 |
|---|---|---|
| `DECISION-` | **裁定**（甲方或主控拍板） | **长期有效**，优先读，是"为什么这么定"的唯一出处 |
| `SPEC-` / `CONTRACT-` / `REF-` | 规范 / 契约 / 参考 | 在被取代前有效 |
| `PLAN-` | 计划 | **做完即过期**；不要照旧 PLAN 执行 |
| `AUDIT-` | 审计（一次性取证） | 取证时点有效；结论可能已变 |
| `REVIEW-` | 复查 | 同上，常见 `ROUND1/2/3` 变体，取最新一轮 |
| `DONE-` / `FEED-` | 完成记录 / 回执 | 历史 |
| `HANDOFF-` | 线间移交 | 历史，但含当时的裁决排序 |
| `DIAG-` | 诊断 | 一次性 |

> **日期后缀（如 `-20260930`）是判断时效的第一依据。** 早于当月的 `PLAN-` 基本可直接忽略。

## 六、为什么没有 `docs/archive/`

旧索引说要归档 205 个文件到 `docs/archive/`，**但从未执行**。09-30 决定**不补做**：

- `docs/` 下的历史文档**本身就是证据链**（审计、复查、裁定都要能被溯源），搬走反而断链；
- 本项目已有**统一的退役惯例**：不删除、不搬走，而是**在原文件头部加状态标记**
  （`superseded` / `retired` ＋ 指向现行权威）。实例见 `AWAKE-Version-Roadmap-0.2.0-to-1.0.0-20260817.md`。
- ⇒ **判断一份文档是否还有效，看它头部的状态声明，而不是看它在哪个目录。**

⭐ **两条必须记住的判据教训**：
1. **「设计没照做」≠「工作没完成」**。实证：`Dialogue-BatchC` 要的 `awake.conversations` 零命中，但 `AwakeMessenger*` 已落地 ⇒ 功能做了、换了形态。

⭐ **按簇核验**（第二轮方法）：大簇对应同一子系统，**核一次子系统覆盖一批**。
已核：`WorldbookStudio-A*`（Studio 存在）✅、`MARCUS-AWAKE-P3*`（framework 存在）✅、
`PLAN-Awake-*-20260816`（混杂）⬜、`PersonaWorkbench-*`（`tools/persona-workbench/` 只有 .md）⬜。

## 七、怎样加新文档

1. **命名按 §四**（`TYPE-主题-日期.md`，中文主题可用）。
2. **不必登记到本文件** —— 本文件刻意不做清单（见 §一）。
3. **若它取代了某份旧文档**：去**旧文档头部加 `superseded` 标记 ＋ 指向它**。
   ⚠️ **这是最容易被漏掉、后果最严重的一步** —— `AWAKE-Version-Roadmap-0.2.0-to-1.0.0` 就是因为漏了这步，
   导致 **6 周内两份文件同时自称"当前权威"**。
